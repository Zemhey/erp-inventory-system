# ADR-0007: 库存流水为事实源，余额为派生结果

- 状态：已采纳
- 日期：—

## 背景

库存系统有两种根本不同的建模方式：

- **A. 余额为主**：直接维护 `inventory_balances.on_hand_qty`，需要时加减。
- **B. 流水为主**：每次变动写一条不可变流水，余额是从流水推导出的缓存/快照。

这个选择决定了系统**可追溯性**、**可对账性**与**可测试性**。

## 决策

采用 **B，并同时保留两者**：

1. `inventory_ledger` 是**不可变事实源**（无 `updated_at`、无删除，结构上宣告不可变）；
2. `inventory_balances` 是**派生快照**，用于高性能查询；
3. 一旦两者不一致，**以流水为准重算余额**；
4. 库存余额增加 `available_qty` 生成列（`on_hand - reserved`）与 `CHECK (on_hand_qty >= 0)`、`CHECK (reserved_qty <= on_hand_qty)` 约束。

## 理由

1. **可追溯**：每笔库存变动都能反查来源单据（`biz_ref_no`），这是"商业系统"的硬要求（FR-INV-02）。
2. **可对账**：不变量 INV-2（`on_hand_qty == Σ 流水变动量`）变成一个**随时可运行的校验任务**，而不是月底的人工动作。
3. **可测试**：这是决定性理由 —— 有了一条清晰的不变量，测试就有**确定的断言对象**，而不是"看界面数字对不对"。E2E 与属性测试都可以直接断言 INV-1/INV-2/INV-3。
4. **可回滚**：作废单据只需生成反向流水，"净效果为 0"可直接验证（INV-8）。

## 替代方案与放弃原因

- **只用余额（A）**：查询快，但无法追溯变动来源，无法对账，作废单据要靠"反向算"极易出错。放弃。
- **只用流水、余额每次实时聚合**：一致性最好，但报表与列表查询性能不可接受。放弃。
- **流水为主 + 余额为派生** ← **采纳**：兼得两者，代价是要接受"两者可能短暂不一致"，用不变量校验解决。

## 后果

- ✅ 不变量 INV-1~INV-4 成为可自动验证的命题
- ✅ 对账（FR-SET-03）有明确实现依据
- ✅ 报表口径与流水口径一致，避免"报表和流水对不上"
- ⚠️ 需要小心保证"写流水"与"更新余额"在**同一事务**内完成
- ⚠️ 余额更新需乐观锁/行锁 → 并发冲突要有明确重试或报错策略（对应 BR-INV-02）
- ⚠️ 需要一个定期校验任务（对账）来发现漂移
