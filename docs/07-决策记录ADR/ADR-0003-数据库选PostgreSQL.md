# ADR-0003: 数据库选 PostgreSQL 16

- 状态：已采纳
- 日期：—

## 背景

课程允许 mysql / PostgreSQL / GaussDB 等。数据库选型对**测试体系**的影响远超一般认知。

## 决策

**PostgreSQL 16**（本地与测试环境同版本，集成测试用 Testcontainers 起真库）。

## 理由

1. **Testcontainers 官方镜像支持最好** → 集成测试能跑真库；
   **绝不用 H2/SQLite**：DB 行为不一致（约束、锁、隔离级别、类型语义）= 假绿测试，比没有测试更危险。
2. **约束能力强**：`CHECK`、生成列、部分唯一索引、`EXCLUDE` 约束、`SERIALIZABLE` 隔离级别 —— 能把不变量**写在数据库层**，并发与脏数据由 DB 挡住。
3. 窗口函数 / CTE / JSONB 让报表与"对账"查询更简洁。
4. 招聘市场价值高于 MySQL。

## 替代方案与放弃原因

- **MySQL 8**：可用，但约束能力、生成列、Testcontainers 支持均略弱；招聘溢价低。
- **GaussDB**：**明确放弃**（除非课程强制）。理由：本地生态差、Docker/Testcontainers 镜像缺失、社区资料少 —— 会直接拖垮自动化测试体系，而测试体系是本项目的简历核心。**不为了"看起来高级"牺牲可测性。**

## 后果

- ✅ 集成测试跑真库，断言可信
- ✅ 可用数据库约束直接表达不变量 INV-1/INV-3
- ✅ 测试环境与生产同版本，无"本地过 CI 不过"
- ⚠️ 团队/同事熟悉度低于 MySQL → 单人项目无此问题
- ⚠️ 需注意 PG 与 MySQL 在大小写、类型转换、自增语义上的差异（已选 PG，无迁移负担）
