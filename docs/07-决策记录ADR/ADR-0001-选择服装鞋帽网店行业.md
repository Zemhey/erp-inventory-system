# ADR-0001: 选择服装/鞋帽网店行业

- 状态：已采纳
- 日期：—

## 背景

课程要求"自行选择某个行业的进销存"（便利店、书店、粮油经销商、服装网店等）。
行业选择直接决定：功能清单的复杂度、数据模型的维度、以及**后续自动化测试用例的丰富度**。

## 决策

选择**服装/鞋帽网店**，并在商品上附加 `季节/批次` 字段。

## 理由

四个维度对比（★越多越复杂）：

| 维度 | 服装/鞋帽 | 粮油/生鲜 | 便利店 | 书店 |
|---|---|---|---|---|
| SKU 组合（颜色×尺码） | ★★★ | ★★ | ★ | ★★ |
| 时间维度（效期/批次） | ★★ | ★★★ | ★★ | ★ |
| 逆向流程（退换货） | ★★★ | ★★ | ★ | ★★ |
| 金额组合（折扣叠加） | ★★★ | ★★ | ★★ | ★★ |
| 多仓/多店 | ★★★ | ★★★ | ★★ | ★★ |

服装行业在 **SKU 组合爆炸 + 逆向流程 + 金额组合** 三项上同时最强，这三项恰好是自动化测试用例密度最高的区域：

- SKU 组合 → 大量等价类与边界值，适合自动生成用例
- 退换货 → 状态机回退与库存回补测试
- 促销叠加 → 金额组合测试，可用财产式测试（property-based testing）

**附加决策**：给商品加 `季节/批次` 字段，把"时间维度"并入 —— 等于同时拿到服装 + 粮油两个行业的测试面。

## 替代方案与放弃原因

- **粮油/生鲜**：时间维度（FEFO/账期）最强，但 UI 复杂度低，金额组合简单。放弃。
- **便利店**：业务直观好演示，但复杂度最低，测试价值最低。放弃。
- **书店**：版次/出版社维度中等，整体居中。放弃。

## 后果

- ✅ 测试用例密度最高，自动化测试有真实用武之地
- ✅ 退换货与促销叠加都是"商业级"特征，不像课程作业
- ⚠️ UI 复杂度上升（颜色×尺码矩阵、促销配置界面）→ 需控制 Web 端范围
