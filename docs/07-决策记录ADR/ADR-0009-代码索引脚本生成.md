# ADR-0009: 代码索引由脚本生成，不手写

- 状态：已采纳
- 日期：—

## 背景

项目初期曾计划"先写代码索引文档"。但此时**代码尚不存在** —— 手写的索引 100% 是想象，且一旦代码开始变动就会过期。

更严重的问题：**过期的索引会主动误导你**（索引说 A 模块依赖 B，实际早就改了），比没有索引更糟。

## 决策

**`index/` 目录下所有产物一律由脚本生成，不手写**：

| 产物 | 来源 | 生成方式 |
|---|---|---|
| `index/modules.md` | 源码目录 + 模块注解 | 目录扫描脚本 |
| `index/api-map.md` | `openapi.yaml` | springdoc 导出 + 转换 |
| `index/deps.json` | 构建依赖树 | `gradle dependencies` 解析 |
| `index/coverage-map.md` | JaCoCo 报告 | CI 产物解析 |
| `index/test-map.md` | 追踪矩阵 + 测试报告 | 矩阵解析 + Allure 汇总 |

**目标命令**：

```bash
./scripts/gen-index.sh           # 重生成全部索引
./scripts/gen-index.sh --check   # CI 模式：与提交产物不一致则失败
```

**现在（M0 之前）这一项要做的是**：定义生成方式、目录约定、产物模板 —— **而不是内容**。骨架落地后，一条命令即可刷新。

## 理由

1. **零维护成本 + 永远与代码一致**：这是"生成式"相对"手写式"的根本优势。
2. **可以放进 CI 做校验**（`--check`）：保证文档与代码零漂移 —— 这是简历上的亮点。
3. **与 ADR-0008 协同**：`api-map.md` 从契约生成，契约又从代码校验，闭环。
4. 手写版本在 3 周内必然过期，之后开始骗人。

## 替代方案与放弃原因

- **手写代码索引**：必然腐化，且现在无内容可写。放弃。
- **完全不建索引**：项目变大后找不到东西；追踪矩阵与代码对不上。放弃。

## 后果

- ✅ 索引永远准确，且维护成本为零
- ✅ CI 可强制检查漂移
- ✅ 简历可写："代码索引与接口清单由脚本自动生成并纳入 CI 校验，避免文档腐化"
- ⚠️ 需先写生成脚本（M0 骨架跑通后即可做，成本约 1 天）
- ⚠️ 生成脚本本身要维护（但它比 N 份文档稳定得多）
