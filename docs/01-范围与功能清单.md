# 01 · 范围与功能清单

> 本文回答"**做什么、不做什么**"，并产出全项目唯一的需求编号（FR-xxx）。
> 所有后续产物（接口、数据表、测试用例、追踪矩阵）都必须挂到 FR 编号上。

- 行业：**服装/鞋帽网店**进销存
- 形态：B/S 多端（服务端 + Web + 小程序 + Android），云托管
- 本文状态：v0.1 初稿（限时 1 天产出，后续随开发增补）

---

## 1. 范围定义

### 1.1 做什么（In Scope）

| 类别 | 内容 |
|---|---|
| 主数据 | 商品/SKU（颜色×尺码）、供应商、客户/会员、仓库/库位 |
| 核心业务 | 采购进货、销售出货、客户退货、库存调拨与盘点 |
| 库存 | 实时库存查询、库存流水追溯、预占/释放、批次效期 FEFO |
| 账务 | 日清月结、期间锁账、总账与明细对账 |
| 报表 | 进货统计、出货统计、进销存汇总表、（可选）毛利分析 |
| 系统 | 认证授权、数据权限、幂等、审计日志 |
| 多端 | 服务端 API、Web 管理端、小程序（移动开单/查询）、Android |
| 交付 | 云托管部署、CI/CD、HTTPS、监控、单机版一键包 |
| 加分 | 自然语言操作入口、MCP Server、可测试性后门 |

### 1.2 不做什么（Out of Scope）★ 明确划掉，防止范围膨胀

- ❌ 财务总账/会计凭证（只做到"进销存对账"，不做复式记账）
- ❌ 生产制造/ BOM / 委外加工
- ❌ 真实支付通道对接（用模拟支付/挂账）
- ❌ 物流面单对接（用模拟运单号）
- ❌ 电商平台订单同步（淘宝/抖音 API）
- ❌ 多语言/多币种
- ❌ 微服务拆分（**单体模块化**，理由见 ADR-0006）

> 划掉这些不是偷懒。**范围越清楚，"大型系统"的重心才能压在库存/金额一致性上**，而那里才是测试与简历的价值所在。

## 3. 主业务流闭环（★ 测试火力全押在这一条）

```
采购进货(批次/效期) → 入库质检 → 多仓库存(预占/调拨)
      → 销售出货(拣货/出库) → 客户退货入库 → 日清月结/对账 → 统计报表
```

**三个必须做真实的硬场景**（对应简历上的三条）：

1. **并发防超卖**：N 并发下单同一 SKU，库存绝不超卖、金额不错账
2. **日清月结幂等与对账**：重复执行结果一致；总账与明细差额为 0；跨月/跨年/闰月边界
3. **三端一致性**：Web/小程序/Android 走同一业务用例，结果与库存流水一致

## 4. 功能清单（FR 编号）

> 优先级：**M**=MVP必做（课程必选得分项）· **P1**=重要（支撑商业级质感）· **P2**=可选加分

### 4.1 IAM · 认证与权限

| FR | 功能 | 优先级 | 验收要点 |
|---|---|---|---|
| FR-IAM-01 | 用户登录/登出（JWT） | M | 密码错误锁定；token 过期 |
| FR-IAM-02 | 角色与菜单/接口权限（RBAC） | M | 无权限接口返回 403 |
| FR-IAM-03 | 数据权限：按仓库/门店隔离 | P1 | A 仓仓管看不到 B 仓数据 |

### 4.2 MDM · 主数据

| FR | 功能 | 优先级 | 验收要点 |
|---|---|---|---|
| FR-MDM-01 | 商品与 SKU（颜色×尺码矩阵生成） | M | 同商品下 SKU 不可重复；停用不删 |
| FR-MDM-02 | 供应商管理 | M | 编码唯一 |
| FR-MDM-03 | 客户/会员管理（含折扣等级） | M | 会员折扣等级可影响售价 |
| FR-MDM-04 | 仓库与库位管理 | M | 至少一个默认仓 |

### 4.3 INV · 库存

| FR | 功能 | 优先级 | 验收要点 |
|---|---|---|---|
| FR-INV-01 | 实时库存查询（多仓/多SKU/合计） | M | 可用量 = 实存 − 预占 |
| FR-INV-02 | 库存流水（每笔出入可追溯来源单据） | M | 流水可反查单据号 |
| FR-INV-03 | 库存预占与释放 | P1 | 预占失败即拒绝下单；超时自动释放 |
| FR-INV-04 | 仓间调拨 | P1 | 调出/调入两笔流水，总量守恒 |
| FR-INV-05 | 批次/效期与 FEFO 扣减 | P1 | 优先扣最早效期批次；一单可拆多批次 |
| FR-INV-06 | 盘点与差异调整 | P2 | 差异必须走审批并生成调整流水 |

### 4.4 PUR · 采购进货

| FR | 功能 | 优先级 | 验收要点 |
|---|---|---|---|
| FR-PUR-01 | 进货单创建/编辑/提交/审核 | M | 状态机约束；审核后不可改 |
| FR-PUR-02 | 入库确认 → 生成入库流水、增加库存 | M | 支持分批入库；部分入库状态 |
| FR-PUR-03 | 进货单作废/红冲 | P1 | 已入库的作废须先冲减库存 |

### 4.5 SAL · 销售出货

| FR | 功能 | 优先级 | 验收要点 |
|---|---|---|---|
| FR-SAL-01 | 出货单创建（预占库存） | M | 库存不足即拒绝 |
| FR-SAL-02 | 出货确认（预占 → 出库扣减） | M | 扣减后可用量与实存同步 |
| FR-SAL-03 | 折扣/促销叠加与金额计算 | P1 | 优先级明确；分单位舍入一致 |
| FR-SAL-04 | 出货单作废/红冲（回补库存） | P1 | 回补生成正向流水 |

### 4.6 RMA · 退货（逆向流程）

| FR | 功能 | 优先级 | 验收要点 |
|---|---|---|---|
| FR-RMA-01 | 客户退货入库（回补可售库存） | M | 关联原出货单；金额冲销 |
| FR-RMA-02 | 换货（退 + 新出，差价为 0 或补退） | P2 | 差价计算与库存联动 |

### 4.7 SET · 结算与对账

| FR | 功能 | 优先级 | 验收要点 |
|---|---|---|---|
| FR-SET-01 | 日清：每日汇总当日出入库与金额 | M | 幂等：同日重复执行结果一致 |
| FR-SET-02 | 月结：期间结账并锁账 | M | 锁账后该期间单据不可改 |
| FR-SET-03 | 总账与明细对账（差额=0 断言） | M | 差额非 0 必须报警 |

### 4.8 RPT · 报表统计

| FR | 功能 | 优先级 | 验收要点 |
|---|---|---|---|
| FR-RPT-01 | 进货统计（供应商/商品/期间） | M | 与流水口径一致 |
| FR-RPT-02 | 出货统计（客户/商品/期间） | M | 与流水口径一致 |
| FR-RPT-03 | 进销存汇总表（期初+入−出=期末） | M | 恒等式必须成立 |
| FR-RPT-04 | 毛利/成本分析 | P2 | 成本口径（移动加权）明确 |

### 4.9 SYS · 系统能力

| FR | 功能 | 优先级 | 验收要点 |
|---|---|---|---|
| FR-SYS-01 | 请求幂等（requestId） | P1 | 同 requestId 重复提交只生效一次 |
| FR-SYS-02 | 操作审计日志 | P1 | 记录 who/when/what/前后值 |
| FR-SYS-03 | 可测试性钩子（test profile）：reset / time-travel / seed | P1 | 生产 profile 不注册 |
| FR-SYS-04 | 自然语言操作入口（LLM function calling） | P2 | 指令 → 工具调用 → 返回结果 |
| FR-SYS-05 | MCP Server 暴露核心能力 | P2 | 外部 Agent 可查库存/建单据 |

## 5. MVP 边界（课程必选得分线）

**MVP = 全部标 M 的功能**，即：

- 认证 + RBAC（FR-IAM-01/02）
- 商品SKU / 供应商 / 客户 / 仓库（FR-MDM-01~04）
- 库存查询 + 流水（FR-INV-01/02）
- 进货：建单 + 审核 + 入库（FR-PUR-01/02）
- 出货：建单 + 出货确认（FR-SAL-01/02）
- 退货入库（FR-RMA-01）
- 日清月结 + 对账（FR-SET-01~03）
- 三类报表（FR-RPT-01~03）
- 四端可演示（服务端/Web/小程序/Android）

**MVP 之外的 P1 是"商业级质感"的来源**（预占、FEFO、数据权限、幂等、审计），**P2 是简历亮点**（盘点、毛利、NL、MCP）。

> 策略：**先把 MVP 全部打通到"能跑"**（拿满基础分），**再把主业务线（进货→库存→出货→退货→结算→报表）做到真**（拉开差距），最后按余力摘 P2。
