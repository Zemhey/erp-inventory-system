## 1. 契约工作流（强制）

```
① 改 openapi.yaml（唯一入口）
        ↓ 生成
② 服务端接口骨架（springdoc 双向校验，防止实现与契约漂移）
        ↓ 生成
③ 三端 SDK（TypeScript client，Web/小程序/Android 共用）
        ↓ 驱动
④ 契约测试（OpenAPI schema 校验 + Pact）
        ↓ 白捡
⑤ Schemathesis 属性测试（自动生成边界参数）
        ↓ 产出
⑥ index/api-map.md（代码索引）
```

**CI 门禁**：实现导出的 OpenAPI **与**契约源做 diff，**不一致则构建失败**。
这一条挡住的正是"代码写了但文档没更新"的经典腐化。

## 2. REST 约定

| 项 | 约定 |
|---|---|
| 基础路径 | `/api/v1` |
| 资源命名 | 复数、小写连字符：`/purchase-orders` |
| 动作 | 状态变更用子路径：`POST /purchase-orders/{id}/receive` |
| 分页 | `?page=1&size=20`；响应含 `total`, `page`, `size` |
| 参数避让 | 资源自身也有 `size` 字段时（SKU 尺码），筛选参数必须换名（本项目为 `skuSize`），**禁止与分页 `size` 同名** —— 同名会让 Spring 静默忽略其中一个 |
| 过滤 | `?status=APPROVED&warehouseId=1` |
| 排序 | `?sort=createdAt,desc` |
| 时间格式 | ISO-8601（`2025-06-01T10:00:00+08:00`） |
| 金额 | **JSON 中为整数（分）**，字段名以 `...Amount` 结尾 |
| 字段命名 | 小驼峰：`onHandQty`, `requestId` |
| 版本 | URL 版本；破坏性变更必须升版本 |

## 3. 统一响应结构

```json
// 成功
{ "code": "OK", "message": "success", "data": { ... } }

// 分页
{ "code": "OK", "data": { "items": [...], "total": 137, "page": 1, "size": 20 } }

// 失败
{ "code": "INV_INSUFFICIENT_STOCK", "message": "库存不足：SKU 1001 在 上海仓 可用量 3，需求 5",
  "details": { "skuId": 1001, "available": 3, "required": 5 },
  "traceId": "a1b2c3d4", "timestamp": "2025-06-01T10:00:00+08:00" }
```

**约定**：
- HTTP 状态码表达**类别**（400/401/403/404/409/422/500），**业务码表达具体原因**；
- 业务错误一律用 4xx，**不用 200 包错误**（否则契约测试和监控都失效）；
- `traceId` 贯穿日志 → 测试失败可直接用它捞日志（自动化测试的价值就在这里）；
- 错误消息**必须包含定位信息**（哪个 SKU、哪个仓、差多少）—— 这是"商业系统"与玩具的差别，也让测试断言更容易写。

## 4. 错误码表

| 前缀 | 模块 | 示例 |
|---|---|---|
| `AUTH_` | 认证 | `AUTH_INVALID_CREDENTIALS`, `AUTH_TOKEN_EXPIRED`, `AUTH_ACCOUNT_LOCKED` |
| `PERM_` | 权限 | `PERM_DENIED`, `PERM_DATA_SCOPE_DENIED` |
| `MDM_` | 主数据 | `MDM_SKU_NOT_FOUND`, `MDM_SKU_DUPLICATED`, `MDM_CODE_DUPLICATED` |
| `INV_` | 库存 | `INV_INSUFFICIENT_STOCK`, `INV_RESERVE_FAILED`, `INV_BALANCE_MISMATCH`, `INV_NEGATIVE_NOT_ALLOWED` |
| `PUR_` | 进货 | `PUR_ORDER_NOT_FOUND`, `PUR_STATUS_ILLEGAL`, `PUR_OVER_RECEIVE` |
| `SAL_` | 出货 | `SAL_ORDER_NOT_FOUND`, `SAL_STATUS_ILLEGAL`, `SAL_AMOUNT_MISMATCH` |
| `RMA_` | 退货 | `RMA_ORIGIN_ORDER_REQUIRED`, `RMA_QTY_EXCEED_ORIGIN` |
| `SET_` | 结算 | `SET_PERIOD_CLOSED`, `SET_RECONCILE_MISMATCH`, `SET_ALREADY_SETTLED` |
| `SYS_` | 系统 | `SYS_DUPLICATE_REQUEST`（幂等命中）, `SYS_VALIDATION_ERROR` |

> **错误码是"可测的枚举"**：每个码都应有至少一条测试用例触发它。
> 追踪矩阵里"测试用例ID 为空"的行，配合错误码表就能算出测试缺口。

## 5. 六核心资源（M0 交付范围）

M0 只需要这六个资源的契约成型：

| 资源 | 路径 | 关键操作 |
|---|---|---|
| 商品/SKU | `/products`, `/skus` | CRUD、SKU 矩阵生成 |
| 仓库 | `/warehouses` | CRUD |
| 库存 | `/inventory`, `/inventory/ledger` | 查询、流水、预占 |
| 进货单 | `/purchase-orders` | 建单、审核、`/receive` 入库 |
| 出货单 | `/sales-orders` | 建单、`/ship` 出库 |
| 结算 | `/settlements` | `/daily` 日清、`/monthly` 月结、`/reconcile` 对账 |

### 5.1 契约样例片段（出货：库存不足场景）

```yaml
paths:
  /sales-orders/{id}/ship:
    post:
      summary: 出货确认（预占转出库）
      parameters:
        - name: id
          in: path
          required: true
          schema: { type: integer, format: int64 }
        - name: X-Request-Id          # ★ 幂等键
          in: header
          required: true
          schema: { type: string, minLength: 8, maxLength: 64 }
      responses:
        '200':
          description: 出货成功
          content:
            application/json:
              schema: { $ref: '#/components/schemas/ApiResponse' }
        '409':
          description: 库存不足
          content:
            application/json:
              schema: { $ref: '#/components/schemas/ApiError' }
              examples:
                insufficientStock:
                  value:
                    code: INV_INSUFFICIENT_STOCK
                    message: "库存不足：SKU 1001 在 上海仓 可用量 3，需求 5"
                    details: { skuId: 1001, warehouseId: 1, available: 3, required: 5 }
```

> 注意 `X-Request-Id` **是一个必填 header** —— 幂等不是可选项，它是契约的一部分。
> 这样 Schemathesis 会自动测缺失/超长/非法 requestId，白捡一批用例。

## 6. 属性测试与契约（自增值）

`openapi.yaml` 写好后，直接跑：

```bash
schemathesis run packages/api-contract/openapi.yaml --base-url http://localhost:8080
```

它会**基于 schema 自动生成**参数边界、类型错误、缺失字段等请求，找出实现与契约不一致的地方。
简历价值："基于 OpenAPI 契约自动生成属性测试，发现 N 个接口契约缺陷。"
