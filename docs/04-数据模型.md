## 2. 关键表设计要点

### 2.1 `inventory_balances`（库存余额）

```sql
CREATE TABLE inventory_balances (
  id              BIGSERIAL PRIMARY KEY,
  sku_id          BIGINT      NOT NULL REFERENCES skus(id),
  warehouse_id    BIGINT      NOT NULL REFERENCES warehouses(id),
  batch_no        VARCHAR(64) NOT NULL DEFAULT '',
  production_date DATE,
  expiry_date     DATE,                                   -- FEFO 依據
  on_hand_qty     INTEGER     NOT NULL DEFAULT 0 CHECK (on_hand_qty  >= 0),  -- ★ 数据库层防负
  reserved_qty    INTEGER     NOT NULL DEFAULT 0 CHECK (reserved_qty >= 0),  -- ★
  available_qty   INTEGER     GENERATED ALWAYS AS (on_hand_qty - reserved_qty) STORED,
  version         INTEGER     NOT NULL DEFAULT 0,         -- ★ 乐观锁
  warehouse_code  VARCHAR(32) NOT NULL DEFAULT '',         -- ★ 数据权限冗余
  created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
  CONSTRAINT uq_balance UNIQUE (sku_id, warehouse_id, batch_no),
  CONSTRAINT ck_available CHECK (reserved_qty <= on_hand_qty)  -- ★ 预占不得超过实存
);
```

**三条关键设计**：
1. **`CHECK (on_hand_qty >= 0)`** —— 超卖的最后一道防线。即使代码有 bug，数据库会拒绝。这让并发测试的断言非常干脆。
2. **`available_qty` 用生成列** —— "可用量 = 实存 − 预占"由数据库保证，不可能算错，也无需应用维护。
3. **`version` 乐观锁** —— 并发更新冲突时重试或报错，而不是静默覆盖。

> **测试价值**：这三个设计本身就是可测命题（对应不变量 INV-1/INV-3）。集成测试直接并发压这一张表。

### 2.2 `inventory_ledger`（★ 流水：不可变事实源）

```sql
CREATE TABLE inventory_ledger (
  id            BIGSERIAL PRIMARY KEY,
  sku_id        BIGINT      NOT NULL,
  warehouse_id  BIGINT      NOT NULL,
  batch_no      VARCHAR(64) NOT NULL DEFAULT '',
  change_qty    INTEGER     NOT NULL,          -- 正=入，负=出，★ 不允许为 0
  biz_type      VARCHAR(32) NOT NULL,          -- PURCHASE_IN/SALES_OUT/RETURN_IN/TRANSFER_OUT/ADJUST...
  biz_ref_no    VARCHAR(64) NOT NULL,          -- ★ 来源单据号，可反查
  biz_ref_id    BIGINT,
  unit_cost     BIGINT,                        -- 成本（分），移动加权用
  request_id    VARCHAR(64),                   -- ★ 幂等键
  occurred_at   TIMESTAMPTZ NOT NULL,          -- ★ 业务时间（可注入，非 now()）
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  CONSTRAINT ck_change_nonzero CHECK (change_qty <> 0)
);
CREATE INDEX idx_ledger_sku_wh ON inventory_ledger (sku_id, warehouse_id, occurred_at);
CREATE INDEX idx_ledger_bizref ON inventory_ledger (biz_ref_no);
```

**关键点**：
- **无 `updated_at`、无 `deleted`** —— 结构上就宣告"不可变"；
- `occurred_at` 是**业务时间**，由 `ClockProvider` 注入 → 跨月/跨年结算可测；
- `biz_ref_no` 让"每笔库存变动可追溯来源单据"（FR-INV-02）在 SQL 层直接可查；
- `request_id` 支撑幂等断言（不变量 INV-9）。

> **"流水是事实源，余额是派生结果"** —— 一旦余额与流水不一致，**以流水为准重算**。
> 这条设计让"对账"变成一个可以随时运行的校验任务，而不只是一个月底的动作。

### 2.3 金额字段统一约定

| 约定 | 说明 |
|---|---|
| 类型 | `BIGINT`，单位**分** |
| 禁止 | `FLOAT` / `DOUBLE` / `REAL`（任何浮点金额一律不通过 review） |
| 折扣 | `INTEGER` 万分比（9000 = 9折） |
| 舍入 | 应用层显式 `RoundingMode.HALF_UP`，**集中在一处** |
| 汇总 | 先算行金额，再 Σ 汇总；禁止用合计反算行 |

## 3. 迁移策略

- **Flyway**，文件命名 `V{版本}__{描述}.sql`，如 `V1__init_schema.sql`；
- **迁移脚本进 CI**：每个 PR 都在空库上跑全量迁移（`flyway migrate`），保证迁移可重复执行；
- **禁止修改已合并的迁移**，只能新增；
- 种子数据用 `R__seed_*.sql`（repeatable）区分环境。
