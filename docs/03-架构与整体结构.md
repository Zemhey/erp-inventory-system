## 1. 架构总览

```
┌──────────────────── 客户端层 ─────────────────────┐
│  Web (Vue3+TS)   │  小程序 (uni-app)  │  Android  │
└────────┬─────────────────┬────────────────┬──────┘
         │                 │                │
         └──────── HTTPS / REST + JWT ──────┘
                         │
┌────────────────────────┴──────────────────────────┐
│              应用层（Spring Boot 3 单体模块化）    │
│  ┌──────────────────────────────────────────────┐ │
│  │ 接口层  Controller / DTO / 参数校验 / 异常映射 │ │
│  ├──────────────────────────────────────────────┤ │
│  │ 应用层  ApplicationService（编排、事务边界）   │ │
│  ├──────────────────────────────────────────────┤ │
│  │ 领域层  DomainService / 实体 / 业务规则 / 状态机│ │
│  ├──────────────────────────────────────────────┤ │
│  │ 基础设施 Repository / MQ / 缓存 / 外部适配     │ │
│  └──────────────────────────────────────────────┘ │
└───┬──────────┬──────────┬──────────┬──────────────┘
    │          │          │          │
┌───┴───┐ ┌────┴────┐ ┌───┴────┐ ┌───┴─────┐
│ PG 16 │ │ Redis   │ │RabbitMQ│ │ 对象存储 │
│ 主数据 │ │ 缓存/锁 │ │ 异步   │ │ 图片    │
└───────┘ └─────────┘ └────────┘ └─────────┘
```

**关键决策：单体模块化，不做微服务**（理由见 [ADR-0006](07-决策记录ADR/ADR-0006-单体模块化而非微服务.md)）。
单人项目拆微服务 = 把 80% 时间花在分布式问题上，而这些时间对简历没有加分。

## 2. 分层职责（强制，禁止越界）

| 层 | 职责 | 禁止 |
|---|---|---|
| **Controller** | 参数绑定与校验、鉴权注解、DTO ↔ 领域对象转换、异常→HTTP 映射 | ❌ 业务逻辑 ❌ 直接调 Repository |
| **ApplicationService** | 用例编排、**事务边界**、幂等校验、领域事件发布 | ❌ 写复杂业务规则（应下沉领域层） |
| **DomainService** | 业务规则、状态机校验、不变量维护 | ❌ 依赖 Web/MQ 等基础设施 |
| **Repository** | 持久化、查询 | ❌ 业务规则 |
| **基础设施** | MQ、缓存、时钟、外部 API | ❌ 被领域层直接引用（走接口/端口） |

**依赖方向**：`Controller → Application → Domain ← Repository`（领域层不依赖基础设施，靠接口反转）

> **规则**：领域层通过接口（如 `ClockProvider`、`EventPublisher`、`InventoryPort`）依赖基础设施，而非直接 import 具体实现。这条规则直接决定**可测试性**（见 [06-测试策略](06-测试策略.md)）。

## 3. 模块划分（按限界上下文）

对应 [02-领域模型](02-领域模型与术语表.md#2-聚合与限界上下文) 的 7 个上下文 + 2 个横切：

| 模块 | 包路径 | 职责 | 里程碑 |
|---|---|---|---|
| `iam` | `com.erp.iam` | 认证、RBAC、数据权限 | M1 |
| `mdm` | `com.erp.mdm` | 商品/SKU/供应商/客户/仓库 | M1 |
| `inv` | `com.erp.inv` | 库存余额、流水、预占、调拨、FEFO | M1 |
| `pur` | `com.erp.pur` | 采购进货单与入库 | M1 |
| `sal` | `com.erp.sal` | 销售出货单与出库 | M1 |
| `rma` | `com.erp.rma` | 退货入库 | M2 |
| `set` | `com.erp.set` | 日清月结、对账 | M2 |
| `rpt` | `com.erp.rpt` | 统计报表（只读） | M2 |
| `sys` | `com.erp.sys` | 幂等、审计、测试钩子、NL/MCP | M1/M7 |
| `shared` | `com.erp.shared` | 通用：时间、金额、错误码、分页、事件总线 | M0 |

**模块间通信规则**：
- 同进程内直接调用**应用服务接口**（Java 接口 + Spring 注入）；
- **禁止跨模块直接访问对方的表**（RPT 例外，走只读视图）；
- 库存变动**唯一入口**：`inv.InventoryApplicationService`。

## 4. 目录结构（单仓多包）

```
公司系统/
├── docs/                       ← 文档（00~07）
│   └── 07-决策记录ADR/
├── index/                      ← ★ 代码索引（生成物，不手写）
│   ├── modules.md
│   ├── api-map.md
│   ├── deps.json
│   ├── coverage-map.md
│   └── test-map.md
├── scripts/
│   ├── gen-index.sh            ← ★ 一条命令重生成全部索引
│   ├── gen-openapi.sh
│   └── dev-up.sh               ← 一键起本地环境
├── apps/
│   ├── server/                 ← Spring Boot 3
│   │   ├── src/main/java/com/erp/{iam,mdm,inv,pur,sal,rma,set,rpt,sys,shared}/
│   │   ├── src/main/resources/db/migration/   ← Flyway
│   │   └── src/test/java/      ← L1/L2 测试（与被测代码同包）
│   ├── web/                    ← Vue3 + TS + Vite + Element Plus
│   ├── miniapp/                ← uni-app
│   ├── android/                ← uni-app 出包 →（可选）原生 Kotlin
│   └── desktop/                ← Tauri 壳（单机版 10%）
├── packages/
│   ├── api-contract/           ← ★ OpenAPI 单一事实源
│   │   └── openapi.yaml
│   └── test-kit/               ← ★ 测试公共库（数据工厂、客户端、页面对象）
├── tests/
│   ├── e2e-web/                ← Playwright
│   ├── e2e-miniapp/            ← miniprogram-automator
│   ├── e2e-android/            ← Appium
│   ├── cases/                  ← ★ YAML 语义用例（三端共用）
│   ├── perf/                   ← k6
│   └── security/               ← ZAP / Trivy
├── infra/
│   ├── compose/                ← docker-compose（本地 + 测试）
│   ├── nginx/
│   └── k8s/ 或 terraform/
└── .github/workflows/          ← CI/CD
```

**为何 `packages/api-contract` 是枢纽**：
一份 `openapi.yaml` 同时驱动 ① 服务端接口骨架 ② 三端 SDK ③ 契约测试 ④ Schemathesis 属性测试 ⑤ `index/api-map.md`。
**改接口 = 改这个文件**，两侧与测试同时对齐 —— 这就是"接口契约即单一事实源"。

## 5. 部署视图

```
┌─────────────── 云服务器（学生机 + 域名 + 备案 + HTTPS）───────────────┐
│  Nginx (443, TLS by Let's Encrypt)                                   │
│    ├── /            → Web 静态资源                                     │
│    ├── /api/        → Spring Boot :8080                              │
│    └── /miniapp/    → H5 版小程序（同源，便于自动化测试）              │
│                                                                       │
│  Docker Compose:  app │ postgres │ redis │ rabbitmq │ prometheus │ grafana│
│  GitHub Actions:  构建 → 单测/集成/契约 → 镜像 → Trivy 扫描 → 滚动部署  │
│  自托管 runner（Windows，本机）: ★ 执行小程序自动化                     │
└───────────────────────────────────────────────────────────────────────┘
```

**三个环境**（配置外置，禁止硬编码）：

| 环境 | 用途 | 数据 |
|---|---|---|
| `local` | 本地开发 | compose 起依赖，种子数据 |
| `test` | CI 自动化测试 | Testcontainers 临时 PG；**test hooks 生效** |
| `prod` | 线上 | 真实数据；**test hooks 不注册** |

## 6. 代码索引生成机制（★ 回应"代码索引现在做不了"）

**原则：代码索引不手写，全部由脚本从源码与 OpenAPI 生成。**

手写索引的必然结局：三周后过期 → 开始骗你 → 比没有索引更糟。
生成式索引的额外好处：**零维护成本，且永远与代码一致**。

| 生成物 | 数据来源 | 生成方式 | 里程碑 |
|---|---|---|---|
| `index/modules.md` | 源码目录 + 模块注解 | 脚本扫目录，提取模块名/职责/文件数/行数 | M0 骨架后 |
| `index/api-map.md` | `openapi.yaml` | springdoc 导出 → 脚本转 Markdown 表格 | M0 |
| `index/deps.json` | 构建工具 | `gradle dependencies` 解析为图 | M0 骨架后 |
| `index/coverage-map.md` | JaCoCo 报告 | CI 产物解析，按模块统计覆盖率 | 测试地基后 |
| `index/test-map.md` | 追踪矩阵 + 测试报告 | 解析 `00-索引`矩阵 + Allure 结果 | 测试地基后 |

**目标命令**：

```bash
./scripts/gen-index.sh          # 重生成 index/ 下全部产物
./scripts/gen-index.sh --check  # CI 中用：若生成结果与提交的不一致则失败
```

`--check` 模式是简历亮点："索引产物纳入 CI 校验，保证文档与代码零漂移。"

## 7. 技术选型清单（锁定，不再反复比较）

| 类别 | 选型 | 版本 | 理由（一句话） |
|---|---|---|---|
| 语言 | Java | 17 LTS | 自动化测试岗 JD 出现率最高 |
| 框架 | Spring Boot | 3.x | 企业系统事实标准 |
| 数据库 | PostgreSQL | 16 | Testcontainers 支持最好；约束/窗口函数强 |
| 迁移 | Flyway | — | 迁移即代码，可版本化、可测 |
| 缓存/锁 | Redis | 7 | 预占与分布式锁 |
| 消息 | RabbitMQ | 3.13 | 异步结算、幂等消费、死信 |
| 鉴权 | Spring Security + JWT | — | — |
| API 文档 | springdoc-openapi | — | 从代码导出 OpenAPI（与契约源双向校验） |
| 构建 | Gradle（Kotlin DSL） | 8.x | 增量构建快；依赖树易导出 |
| 测试 | JUnit5 + Mockito + Testcontainers + REST Assured | — | 见 06 |
| Web | Vue 3 + TypeScript + Vite + Element Plus | — | 国内企业系统主流 |
| 移动 | uni-app（Vue 语法） | — | 一套代码出小程序 + H5 + APK |
| E2E | Playwright / miniprogram-automator / Appium | — | 三端各一 |
| 性能 | k6 | — | 脚本即代码，CI 友好 |
| CI/CD | GitHub Actions（含 Windows self-hosted runner） | — | 免费 + 能跑小程序自动化 |
| 部署 | Docker Compose →（可选 K8s） | — | 单人项目 compose 足够 |
| 监控 | Prometheus + Grafana | — | 演示"商业系统"运维面 |

## 8. 非功能要求

| 要求 | 目标值 | 怎么验证 |
|---|---|---|
| 并发防超卖 | 100 并发下单同一 SKU 不超卖 | k6 + DB 断言 |
| 接口响应 | 查询类 P95 < 300ms | k6 报告 |
| 库存流水一致性 | 任意时刻不变量 INV-2 成立 | 定时校验任务 + 测试 |
| 可用性 | 本地/线上均可一键起 | `dev-up.sh` |
| 日志 | 结构化 JSON + traceId 贯穿 | 日志断言 |
| 审计 | 所有写操作留痕 | 审计日志测试 |
