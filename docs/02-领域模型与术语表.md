# 02 · 领域模型与术语表

> 本文是**全项目的统一语言**。代码里的类名、数据库的表名、接口的字段名、文档的用词、测试用例的描述，**必须与本文一致**。
> 命名不一致是"大型系统"崩坏的第一步：你说"库存"，代码叫 `stock`，接口叫 `qty`，测试叫 `amount` —— 三周后没人搞得清。

本文状态：v0.1 初稿。

## 1. 术语表（Ubiquitous Language）

### 1.1 主数据

| 术语 | 英文/代码名 | 定义 | 易混点 |
|---|---|---|---|
| 商品 | `Product` | 款式级概念（如"圆领T恤"） | ≠ SKU。商品不参与库存 |
| SKU | `Sku` | 最小库存单元 = 商品 + 颜色 + 尺码 | 库存、单据都挂在 SKU 上 |
| 颜色 | `color` | SKU 维度之一 | — |
| 尺码 | `size` | SKU 维度之一 | — |
| 季节/批次 | `season` / `batchNo` | 时间维度 | 批次用于 FEFO |
| 供应商 | `Supplier` | 进货来源 | — |
| 客户/会员 | `Customer` | 出货对象，可带折扣等级 | — |
| 仓库 | `Warehouse` | 库存存放地点 | 数据权限按此隔离 |
| 库位 | `Location` | 仓库内细分位置 | P2 用 |

### 1.2 库存（★ 最易混淆，必须严格区分）

| 术语 | 英文/代码名 | 定义 | 关系 |
|---|---|---|---|
| 实存量 | `onHandQty` | 仓库里真实物理存在的数量 | 基础量 |
| 预占量 | `reservedQty` | 已被单据锁定、但尚未出库的数量 | ≤ onHand |
| **可用量** | `availableQty` | **= onHandQty − reservedQty** | ★ 下单时校验的是这个 |
| 在途量 | `inTransitQty` | 调拨中、尚未到达的数量 | 调拨场景 |
| 库存流水 | `InventoryLedger` | 每一次库存变动的**不可变**记录 | 追溯的唯一依据 |
| 库存余额 | `InventoryBalance` | 当前各 (SKU, 仓库, 批次) 的数量快照 | 由流水推导，非事实源 |
| 库存预占 | `reserve` | 锁定可用量（下单时） | 需超时自动释放 |
| 库存释放 | `release` | 解除预占（取消订单/超时） | — |

> **关键规则**：**可用量才可下单**。`onHandQty` 永远不可作为下单依据 —— 这是超卖的根源。
> **关键规则**：**流水是事实源，余额是派生结果**。余额算错时，以流水重算为准。

### 1.3 单据与状态机

| 术语 | 英文/代码名 | 定义 |
|---|---|---|
| 进货单 | `PurchaseOrder` | 采购入库单据（表头 + 明细） |
| 出货单 | `SalesOrder` | 销售出库单据 |
| 退货单 | `ReturnOrder` | 客户退货入库单据 |
| 调拨单 | `TransferOrder` | 仓间移库单据 |
| 盘点单 | `StocktakeOrder` | 盘点与差异调整 |
| 表头 | `header` | 单据级字段（单号、往来单位、日期、金额合计） |
| 明细 | `line` / `item` | 行级字段（SKU、数量、单价、金额） |
| 单号 | `orderNo` | 业务单号（人类可读，如 `PO20250601-0001`） |

**单据状态机（统一五态，各单据共用）**：

```
DRAFT(草稿) → SUBMITTED(待审) → APPROVED(已审) → PARTIAL(部分执行) → COMPLETED(已完结)
                     ↓                ↓                  ↓
                 REJECTED(驳回)   VOIDED(已作废) ←──── 红冲
```

| 状态 | 含义 | 允许操作 |
|---|---|---|
| DRAFT | 录入中 | 编辑、删除、提交 |
| SUBMITTED | 已提交待审 | 审核通过/驳回 |
| APPROVED | 已审核可执行 | 入库/出库、作废 |
| PARTIAL | 部分入库/出库 | 继续执行、作废（需先冲减） |
| COMPLETED | 全部执行完毕 | 只读 |
| VOIDED | 已作废 | 只读（留档） |
| REJECTED | 被驳回 | 退回编辑 |

> **测试价值**：7 个状态 × 若干操作 = 一张状态转移矩阵，**非法转移必须全部被拒绝**。这是状态机测试的标准靶子。

### 1.4 账务与金额

| 术语 | 英文/代码名 | 定义 |
|---|---|---|
| 日清 | `dailySettlement` | 每日汇总当日出入库与金额 |
| 月结 | `monthlySettlement` | 期间结账，锁账 |
| 账期 | `period` | 结算期间（如 `2025-06`） |
| 锁账 | `closing` | 期间关闭后单据不可改 |
| 总账 | `generalLedger` | 期间汇总数 |
| 明细账 | `detailLedger` | 单据/流水级明细 |
| 对账 | `reconcile` | 校验总账 = 明细合计 |
| 金额单位 | `amount` | **一律以「分」为整数存储** |
| 单价 | `unitPrice` | 以「分/件」存储 |
| 折扣 | `discountRate` | 用整数万分比（如 9000 = 9折），**禁用 float** |
| 成本口径 | `costMethod` | 移动加权平均（MOVING_AVERAGE） |

> **关键规则**：**金额全程用整数「分」，禁用 float/double**。所有舍入必须显式（`RoundingMode.HALF_UP`）且集中在一处。
> **关键规则**：折扣用整数表示，禁止浮点相乘 —— 这是金额测试最容易出 bug 的地方。

### 1.5 系统能力

| 术语 | 英文/代码名 | 定义 |
|---|---|---|
| 幂等键 | `requestId` | 客户端生成的唯一请求标识，防重复提交 |
| 审计日志 | `AuditLog` | who/when/what/前后值 |
| 可测试性钩子 | `test hooks` | 仅 test profile 生效的后门 |
| 时钟 | `ClockProvider` | 可注入时间源（★ 让跨月结算可测） |

## 2. 聚合与限界上下文

```
┌─────────────┐   ┌──────────────┐   ┌──────────────┐
│   MDM       │   │    INV       │   │    PUR       │
│ 主数据      │←──│  库存        │←──│  采购进货    │
│ Product/Sku │   │ Balance/     │   │ PurchaseOrder│
│ Supplier    │   │ Ledger/      │   └──────────────┘
│ Customer    │   │ Reserve      │   ┌──────────────┐
│ Warehouse   │   └──────┬───────┘←──│    SAL       │
└─────────────┘          │           │  销售出货    │
                         │           └──────────────┘
                  ┌──────┴───────┐   ┌──────────────┐
                  │    SET       │←──│    RMA       │
                  │  结算对账    │   │  退货逆向    │
                  └──────┬───────┘   └──────────────┘
                         │
                  ┌──────┴───────┐
                  │    RPT       │  报表统计（只读，跨域查询）
                  └──────────────┘
```

**依赖方向规则（单向，禁止环）**：

- `PUR / SAL / RMA / INV` 都可依赖 `MDM`（读主数据）
- `PUR / SAL / RMA` **必须通过 `INV` 的领域服务改变库存**，不得直接写库存表
- `SET` 依赖 `INV` 的流水（读）
- `RPT` 只读，可查任意域的只读视图
- `MDM` 不依赖任何人（最底层）
- `IAM / SYS` 是横切关注点（cross-cutting），被所有模块依赖

> **违反此规则的写法（常见错误）**：出货 Service 里直接 `UPDATE inventory SET qty = qty - 1`。
> 正确写法：`inventoryService.ship(skuId, warehouseId, qty, bizRef)` —— **库存变动的唯一入口**。

## 3. 核心业务规则（★ 测试断言的直接来源）

### 3.1 库存规则

| 规则 | 编号 | 说明 |
|---|---|---|
| 可用量校验 | BR-INV-01 | 下单/出库只校验 `availableQty`，不校验 `onHandQty` |
| 超卖防护 | BR-INV-02 | 预占/扣减必须在**事务 + 行锁/乐观锁**下原子完成，并发结果不允许为负 |
| 流水不可变 | BR-INV-03 | `InventoryLedger` 一旦写入不得修改或删除 |
| 余额一致性 | BR-INV-04 | 任意时刻 `onHandQty` == 该 SKU+仓+批次 的流水净和 |
| 预占超时 | BR-INV-05 | 预占超过 N 分钟未出库，自动释放（时钟可注入） |
| FEFO | BR-INV-06 | 出货优先扣最早效期批次；单笔可拆多批次 |
| 调拨守恒 | BR-INV-07 | 调拨前后两仓总量不变 |

### 3.2 单据规则

| 规则 | 编号 | 说明 |
|---|---|---|
| 状态机约束 | BR-DOC-01 | 仅允许合法状态转移，非法转移必须报错 |
| 审核后只读 | BR-DOC-02 | APPROVED 后表头/明细不可编辑 |
| 作废前置 | BR-DOC-03 | 已产生库存变动的单据作废，必须先冲减（生成反向流水） |
| 部分执行 | BR-DOC-04 | 分批入库/出库，累计数量不得超过单据数量 |
| 幂等提交 | BR-DOC-05 | 同 `requestId` 重复提交只生效一次 |

### 3.3 金额规则（★ 组合爆炸区）

| 规则 | 编号 | 说明 |
|---|---|---|
| 整数分 | BR-AMT-01 | 所有金额以「分」整数存储与计算 |
| 显式舍入 | BR-AMT-02 | 每处除法/折扣必须显式舍入策略（HALF_UP），禁止隐式 |
| 促销优先级 | BR-AMT-03 | 会员价 → 促销 → 优惠券 → 满减，顺序与叠加规则明确 |
| 行金额公式 | BR-AMT-04 | `行金额 = round(单价 × 数量 × 折扣率)` |
| 单头合计 | BR-AMT-05 | `合计 = Σ行金额`（先算行再汇总，**禁止反算**） |
| 对账恒等 | BR-AMT-06 | 总账合计 == 明细合计（差额必须为 0） |

### 3.4 账务规则

| 规则 | 编号 | 说明 |
|---|---|---|
| 日清幂等 | BR-SET-01 | 同一账期重复执行日清，结果完全一致 |
| 锁账不可逆 | BR-SET-02 | 月结锁账后，该期间单据不可新增/修改 |
| 期间边界 | BR-SET-03 | 跨月、跨年、闰月、时区边界必须正确归属期间 |
| 断点续跑 | BR-SET-04 | 批处理中断后可续跑，不重复计入 |

## 4. 关键不变量（Invariants —— 测试的最终断言对象）

> 这些是**永远为真**的命题。E2E 和属性测试应围绕它们写断言，而不是断言具体数值。

| 编号 | 不变量 |
|---|---|
| INV-1 | 任意 (SKU, 仓库, 批次) 的 `availableQty >= 0`，`onHandQty >= 0` |
| INV-2 | `onHandQty == Σ(InventoryLedger 变动量)` |
| INV-3 | `可用量 == 实存量 − 预占量` |
| INV-4 | 所有单据数量守恒：单据明细合计 == 对应库存流水合计 |
| INV-5 | 总账金额合计 == 明细金额合计（差额 0） |
| INV-6 | 进销存汇总表恒等式：`期初 + 本期入 − 本期出 == 期末` |
| INV-7 | 调拨前后，全仓总量守恒 |
| INV-8 | 作废单据不产生正向库存影响（净效果为 0） |
| INV-9 | 同 `requestId` 的重复请求，系统状态变化只发生一次 |
| INV-10 | 同账期重复结算，结果幂等 |

> **这 10 条不变量，就是你这个项目的测试核心资产。** 写进简历："围绕 10 条库存与金额不变量设计财产式与一致性断言，而非硬编码期望值。"

## 5. 命名规范（强制）

| 对象 | 规范 | 示例 |
|---|---|---|
| Java 类 | 大驼峰 | `PurchaseOrderService` |
| Java 方法 | 小驼峰，动词开头 | `createPurchaseOrder()` |
| 数据库表 | 小写下划线，复数 | `purchase_orders`, `purchase_order_lines` |
| 数据库字段 | 小写下划线 | `on_hand_qty`, `unit_price` |
| REST 路径 | 小写连字符，复数资源 | `/purchase-orders/{id}/receive` |
| JSON 字段 | 小驼峰 | `onHandQty`, `requestId` |
| 枚举值 | 大写蛇形 | `PARTIALLY_RECEIVED` |
| 测试用例ID | `TC-<模块>-<三位序号>` | `TC-INV-007` |
| 需求编号 | `FR-<模块>-<两位序号>` | `FR-INV-05` |
| 业务规则 | `BR-<模块>-<两位序号>` | `BR-INV-02` |

> `TC-INV-007` 这种编号是**追踪矩阵的连接键**（见 [00-索引与追踪矩阵](00-索引与追踪矩阵.md#3-追踪矩阵--本文件的核心)）。测试用例的命名必须带编号，否则矩阵对不上。
