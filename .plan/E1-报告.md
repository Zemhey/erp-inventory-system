## 3. 页面与权限

### 3.1 审计查询 `/audits`

- 筛选：操作人（精确）、业务单据号（精确）、**资源类型 / 资源 ID**、操作类型（17 个动作枚举）、结果、时间区间（半开 `[from,to)`）
- 列表：发生时间倒序；动作列下方直接给出变更概览（`修改 1` / `无变更前快照`）；单据号与 traceId 均可点
- 详情抽屉：`GET /audits/{id}` 二次取值；**变更前 / 变更后并排表**（字段路径 × 两侧值，新增/删除/修改/未变分别上色），默认"只看差异"，可切全部字段；原文 JSON 折叠
- 轨迹弹窗：`/audits/timeline`（正序）；traceId 弹窗：`/audits/by-trace`（按写入顺序）
- 页面明示两条边界：① 只读（表 append-only，触发器拒绝 UPDATE/DELETE）；② `sys:read` 可看全公司、**尚未按数据权限收窄**

补充"资源类型 / 资源 ID"两个筛选维度的原因：后端刻意不把主数据编码当 `bizRefNo`（`AuditAspect.BIZ_REF_KEYS` 不含 `code`），没有这两个维度就只能按人翻主数据历史。

### 3.2 数据字典 `/dicts`

- 左类型右项，`sortNo` 升序原样展示；「包含已停用的类型与字典项」真实切换 `onlyEnabled`
- **只读而不是假表单**：后端只有两个 GET，页面上写明"维护接口缺失、已登记契约申请"；同时写明"这些字典值尚未成为 SKU 录入的下拉约束"

### 3.3 权限（两道）

| 层 | 行为 | 用例 |
| --- | --- | --- |
| 前端路由守卫 | `meta.permission='sys:read'`；无权限身份直接输 `/audits`、`/dicts` → 弹回 `/dashboard` | TC-SYS-095 |
| 菜单 | `session.hasPermission('sys:read')` 过滤（支持 `sys:*` 通配） | TC-SYS-095 |
| 后端 `@RequirePermission("sys:read")` | 无权限调 `/audits`、`/dicts` → 403 `IAM_FORBIDDEN` | TC-SYS-095 |

负向身份用既有 `PURCHASER` 角色（`pur:*` 但不能看审计），证明"能开单 ≠ 能看审计"；临时账号由用例 `finally` 删除。

**关于 `e2e-reserve-001` = 0 条**：本轮用自建库（`erp-e1-pg`），该预占夹具是**共享开发库**里手工留下的数据，不在任何迁移/脚本里，全新库里就是 0 条。E2E 清理 SQL 里就写着这一点（`e2e/helpers/sql.ts` 第 365–369 行），可移植的不变量是"本轮没动过它"——由 `baseline_reservation` 与 `baseline_reservation_state` 两个基线键逐字对比保证。在共享开发库上跑，这里会输出"仍为 1 条"。

### 5.4 数据隔离口径（为什么不能按"单号=唯一"）

清理会回收当日的取号序列（当天已无单据时删除 `document_sequences` 行），于是同一个 `PO20261024-000N` 会在后续轮次复用；而审计行不可删。第一版用例因此拿到过 `期望 4 实得 16`（4 轮 × 4 条）与 `期望 1 实得 4`。改成三种不变量：

1. **resourceId**（BIGSERIAL 不复用）——界面用例 091/093/096；
2. **造数前时间戳 `from`**——接口用例 118；
3. **traceId**（全局唯一）——119 与 093 的 by-trace。

轨迹接口没有时间参数（契约如此），断言钉"**正序末尾四条**"，历史轮同号记录允许排在前面（截图 `TC-SYS-093-audit-timeline` 可见同一单号的多轮历史）。

## 7. 过程中修掉的问题（都是真跑出来的）

| 现象 | 根因 | 处理 |
| --- | --- | --- |
| 首轮 5 条 UI 用例全在 `/audits` 找不到元素，页面停在登录页 | 用例在 `loginViaUi` 后**立刻 goto**，打断了还在飞的登录请求 → token 未落盘 → 守卫弹回登录 | 统一 `loginAndWaitDashboard`：等 URL 真正到 `/dashboard` |
| EP 的 el-checkbox 点不动（`element is not visible`） | Element Plus 把原生 `input` 隐藏，可见的是外层 label | 点标签文案（`只看差异字段` / `包含已停用的类型与字典项`），断言仍用 `toBeChecked()` |
| `getByPlaceholder('全部操作类型')` 超时 | EP 2.9 的 el-select 占位符是 `<span>`，不是 input 的 placeholder 属性 | 点占位符文案展开下拉 |
| 日期区间 `getByPlaceholder('开始时间')` 命中 2 个 | 日期面板 popper 里也有同 placeholder 的输入框 | 限定 `.filters .el-range-editor` 内 |
| 弹窗表格 `count()` 得 -1 | 弹窗刚开、行还没渲染，`count()` 不自动等待 | 先 `expect(first()).toBeVisible()` 再计数 |
| 既有用例 `E2E-19` 偶发 `page.goto: net::ERR_ABORTED`（第 2 遍复现 1 次） | **既有竞态**：`loginAsAnother` 清 token 后，上一页迟到的 401 让 axios 拦截器整页跳 `/login`，与紧接着的 `goto` 抢导航 | `e2e/helpers/ui.ts` 加 `gotoIgnoringRedirectRace`：只对 `ERR_ABORTED` 重试一次、其它错误照抛（不用 sleep 掩盖）。修复后连跑两遍全绿 |
| 1280px 下"变更/traceId"两列被挤出视野 | 9 列总宽超内容区 | 把变更摘要并入"动作"列第二行，收紧列宽（8 列，全部可见） |

## 9. 发现的缺口

完整内容见 `.plan/E1-契约申请.md`，摘要：

1. **字典无写端点** → 维护界面无法交付（页面已按只读交付并写明原因）。
2. **`GET /dicts/ACTIONS` 被后端 400 文案引用，但种子里没有该类型** → 用户被引到 404；前端动作下拉只能镜像 `AuditAction.java`（漂移风险）。建议补种 `ACTIONS` 字典。
3. **单据工作流的 `before_json` 恒为 null**：`AuditAspect` 只按"路径末段是纯数字"取快照，`/submit`、`/approve`、`/receive` 取不到 → 审计页对单据只能展示"变更后"，看不到状态迁移对照。（这是本次做界面才暴露的后端语义缺口。）
4. 轨迹接口无时间过滤（低优先，长历史下同号会被多轮数据稀释）。
5. 观察项：审计不做数据权限过滤；字典值尚未成为 SKU 录入约束 —— 两点都已在页面上明示，不粉饰。
