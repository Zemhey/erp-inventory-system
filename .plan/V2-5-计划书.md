## 1. 目标与范围

### 1.1 一句话目标

把"系统发生过什么"变成**可查、可还原、不可篡改、可串联**的事实：
每个写接口自动留痕，任何人拿 traceId 或单据号都能还原一条完整的操作轨迹，
并且这条轨迹在数据库层**改不掉**。

## 2. 设计与关键决策

### 2.1 分层（照抄 mdm：`api → application → repository → domain`）

```
com.erp.sys/
├── api/          AuditController（GET×4）、DictController（GET×2）
├── application/  AuditAspect、AuditSafetyNetFilter、AuditRecorder、
│                 AuditQueryService、AuditJson、MetricsRecorder、AuditMetricsBinder
├── repository/   AuditLogRepository（只写）、AuditLogQueryRepository（只读）、DictRepository
└── domain/       AuditLog、AuditAction、AuditResult、AuditQueryFilter、DictType、DictItem
```

依赖方向单向；`domain` 是纯 POJO（无 Spring/JDBC）。

### 2.2 ★ 为什么切 Controller 层，而不是 ApplicationService

三条理由，第一条是本批并行环境决定的：

1. **冲突**：本批 6 条泳道中 V2-1/V2-2/V2-3 **同时**改
   `InventoryApplicationService` 与 `DocumentNumberGenerator`。切 Service 会让审计切入点
   成为第四个冲突点；切 Controller 层让本泳道**完全不碰**那两个文件。
2. **信息完整性**：审计要记录"哪个 HTTP 写操作、被谁、结果如何、响应体是什么"。
   Service 方法没有 HTTP 上下文（路径、IP、响应体），`after_json` 凑不出来。
3. **覆盖面稳定性**：切 Service 要逐个模块认方法名，新模块会被漏掉；
   切 Controller 层只依赖一条结构约定"所有 `@RestController` 都在 `com.erp..api..`"。

### 2.3 ★ 契约与共享文件：纯追加纪律

本批多泳道并行，合并顺序不可控。因此本泳道对**共享文件**的每一次改动都是
**纯追加、不重排、不动既有行**：

| 文件 | 改动 | 冲突风险 |
|---|---|---|
| `ErrorCode.java` | 末尾追加 3 个 `SYS_AUDIT_*` / `SYS_DICT_*` 码 | 低（纯追加） |
| `application.yml` | `include` 行末尾追加 `prometheus` + 新增 `metrics.tags` | 低 |
| `build.gradle.kts` | 追加 1 行 `micrometer-registry-prometheus` | 低 |
| `SecurityConfig.java` | 追加 1 行 `requestMatchers(...).permitAll()` | 低 |
| `openapi.yaml` | 在 `paths` 末尾追加 6 个路径、`schemas` 末尾追加 3 个 schema、`tags` 末尾追加 `sys` | 低（V2-6 约定不改契约） |
| `GlobalExceptionHandler.java` | 追加 1 个 handler（405 归因） | 低 |
| `ArchitectureTest.java` | 追加 2 条规则 + 4 条自检用例 | **中**（本批只本泳道改；后续泳道若也加规则需按本节纪律） |

### 2.4 ★ 两条"审计必须活着"的硬设计

**(1) 审计写库在业务事务之外 —— `REQUIRES_NEW`**

业务失败时 Spring 回滚业务事务。若审计写在同一事务里，它会跟着消失 ——
结果是"失败的写操作永远查不到"，而失败恰恰最需要审计。
本项目 M1 踩过同族坑：登录失败计数写在业务事务内，一次回滚就清零，
导致"连续失败锁定"从未生效。

**(2) 审计失败绝不影响业务**

`AuditRecorder.record()` 的契约是**不抛任何异常**：写失败只记日志 +
`erp_audit_write_failed_total` 计数，业务照常返回。
`AuditAspect` 的取值辅助（`biz_ref_no`、`actor`、IP、快照）全部容错，
取不到就写 `null`。

### 2.5 ★ 为什么在切面之外还要一个兜底过滤器

**这是本期最重要的一个发现**，实测数据支撑：

`AuditAspect` 只在 Controller **方法被调用**时生效。但写请求可能在方法调用**之前**
就被拒掉：`@Valid` 校验失败、缺 `X-Request-Id`、参数类型不匹配 —— 全是 400。
这些是"有人尝试写了东西但被系统拒绝"，是审计最该记录的部分，而切面**看不到**
（方法没被调用）。

**实测**：只靠切面时，42 个写接口只有 **26** 条审计。
差的 16 个正是"空请求体/非法参数"这类接口。

因此新增 `AuditSafetyNetFilter`（Servlet 过滤器，`HIGHEST_PRECEDENCE + 5`，
在 `TraceIdFilter` 之后）：请求结束后若切面没写（靠请求属性 `erp.audit.recorded` 协调），
且该请求**确实匹配到了处理器**（`HandlerMapping.BEST_MATCHING_PATTERN_ATTRIBUTE` 非空），
就补一条"请求级"审计。**不重复记录**。

只对"匹配到处理器"的请求补审计：对只读端点发 PUT/DELETE 会在路由阶段抛 405、
匹配不到处理器 —— 那种请求不该产生审计（它并没有改动任何东西）。

### 4.1 INV-15 的实际语法（这是本期的核心资产）

```java
// 从运行时注册表枚举写接口 —— 不解析源码（会漏组合路径/条件映射）
for (Map.Entry<RequestMappingInfo, HandlerMethod> entry
        : handlerMapping.getHandlerMethods().entrySet()) {
    if (!handler.getBeanType().getPackageName().startsWith("com.erp.")) continue;
    Set<RequestMethod> methods = entry.getKey().getMethodsCondition().getMethods();
    for (String pattern : entry.getKey().getPatternValues()) {
        if (normalizePath(pattern).startsWith("/__test__")) continue;   // 排除后门
        for (RequestMethod m : methods) {
            if (WRITE_METHODS.contains(m)) endpoints.add(...);          // POST/PUT/PATCH/DELETE
        }
    }
}

// 逐个发真实请求，断言"每个接口让 audit_logs 至少多一行"
for (WriteEndpoint endpoint : endpoints) {
    long before = auditCount();
    perform(endpoint);          // 允许失败（404/400/403 都行）：失败的写操作同样必须留痕
    if (auditCount() <= before) missing.add(endpoint.toString());
}
assertThat(missing).as("★ INV-15 ...").isEmpty();
```

**判据为什么是"行数增量"而不是"出现新的 `(resourceType, action)` 键"**：
两个不同接口完全可能落到同一个键上（`POST /skus` 与 `POST /skus/matrix` 都是
CREATE + SKU），用键集合会把后者误判成"没审计" —— 本泳道实测踩到过这个假红。

## 5. 数据库（V13）

### 5.1 三张表

- **`audit_logs`（追加型）**：`id / tenant_id / actor_id / actor_name / action /
  resource_type / resource_id / biz_ref_no / before_json / after_json / trace_id /
  ip / occurred_at / result / error_code`
  - **无 `updated_at`** —— 加了它就意味着"这一行会被改"
  - 索引：`(occurred_at DESC)`、`(actor_id, occurred_at)`、`(biz_ref_no)`
  - `before_json` / `after_json` 用 **JSONB** 而不是 TEXT：审计查询要按字段值过滤与还原
  - `result` 有 `CHECK (result IN ('SUCCESS','FAIL'))`
- **`dict_types` / `dict_items`**：种子 4 类 14 项（COLOR/SIZE/SEASON/UNIT）
- **权限种子**：`ADMIN: sys:*`、`VIEWER: sys:read`、`FINANCE: sys:read`（只追加，不建账号）

### 5.2 ★ 不可篡改是数据库层的保证

```sql
CREATE OR REPLACE FUNCTION audit_logs_append_only() RETURNS trigger AS $$
BEGIN
    RAISE EXCEPTION 'audit_logs 是追加型表，禁止 % （审计不可篡改，见 FR-SYS-06）', TG_OP
        USING ERRCODE = 'restrict_violation';
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_audit_logs_append_only
    BEFORE UPDATE OR DELETE ON audit_logs
    FOR EACH ROW EXECUTE FUNCTION audit_logs_append_only();
```

实测（psql 直连）：

```
ERROR:  audit_logs 是追加型表，禁止 UPDATE （审计不可篡改，见 FR-SYS-06）
ERROR:  audit_logs 是追加型表，禁止 DELETE （审计不可篡改，见 FR-SYS-06）
```

**为什么两层都要**：代码层（ArchUnit）拦"自己人顺手加了个方法"；
数据库层拦"绕过代码的手工 SQL / 运维脚本"。只做一层都不够：
纯代码约束挡不住 psql，纯触发器挡不住"先查出来改完再插回去"。

## 6. 坑（本期实测踩到，全部有对应代码注释）

| # | 坑 | 现象 | 规避 |
|---|---|---|---|
| 1 | **`@SpringBootTest` 默认关闭指标导出** | `/actuator/prometheus` 在测试里 404/500（`NoResourceFoundException: No static resource actuator/prometheus`），生产却正常。`MeterRegistry` 被换成 `SimpleMeterRegistry`，只注册 3 个端点 | 测 Actuator 的类加 `@AutoConfigureObservability`。排查两轮才定位 |
| 2 | **Actuator 端点不在 `RequestMappingHandlerMapping` 里** | `MockMvc` 打不到 `/actuator/*` | 用 `RANDOM_PORT` + 真实 HTTP；凡是测容器层行为都必须用真实端口 |
| 3 | **Micrometer 吃掉指标名里的 `created`** | 注册 `erp.order.created` → 导出成 `erp_order_total`（与"订单总数"撞名），断言永远失败 | 改用 `erp.order.placed` → `erp_order_placed_total` |
| 4 | **Gauge 重复注册会 500** | 第二次 `reconcileDiff()` 后 `/actuator/prometheus` 直接 500 —— 比没有指标更糟 | 注册前 `registry.find(name).gauge() != null` 判存在，只更新原子值 |
| 5 | **`Map.ofEntries` 重复键是启动期异常** | 加了复数映射后 `INVENTORY` 出现两次 → `ExceptionInInitializerError: duplicate key: INVENTORY`，整个 Spring 上下文起不来，71 个用例连带全红 | 静态 Map 构造必须人工核对键唯一；`Map.of` 系列不做去重 |
| 6 | **`TestRestTemplate` 对 401 自动重试** | `HttpRetryException: cannot retry due to server authentication, in streaming mode` —— 拿到的是客户端异常而不是服务端 401 | 用 `java.net.http.HttpClient`（不自动重试） |
| 7 | **幂等键校验失败时切面看不到** | 42 个写接口只产生 26 条审计 | `AuditSafetyNetFilter` 兜底（见 §2.5） |
| 8 | **兜底与切面资源类型推导不一致** | 切面给 `PRODUCT`、兜底给 `PRODUCTS`（路径首段），同一业务域被拆成两个指标维度 | 兜底也读 `HandlerMapping.BEST_MATCHING_HANDLER_ATTRIBUTE` 取 Controller 类名；并在 `ORDER_TYPES` 里同时收录单复数（双保险） |
| 9 | **`code` 不能当单据号** | 主数据编码（`AUD-P13`）被写进 `biz_ref_no`，"按单据追溯"全错 | `BIZ_REF_KEYS` 只认 `orderNo/bizRefNo/docNo/settlementNo/period` |
| 10 | **测试连接池撞 `max_connections`** | 全量 `check` 里 `FATAL: sorry, too many clients already`，报错停在 Tomcat 启动阶段 | `PostgresTestBase` 里把测试池设为 4（生产仍 20） |
| 11 | **405 被兜底成 500** | 对只读的 `/audits`、`/dicts` 发 POST 得到 500 | `GlobalExceptionHandler` 加 `HttpRequestMethodNotSupportedException` handler → 405 |
| 12 | **`api` 不许依赖 `repository`**（既有 ArchUnit 规则抓到本泳道） | `AuditController` 直接用了 `AuditLogQueryRepository.Filter` → 规则红 | 把 `Filter` 提到 `domain` 改名 `AuditQueryFilter`，依赖方向恢复 `api → domain ← repository` |
| 13 | **超大快照不能截断** | 截断产生非法 JSON，"可还原"失效 | 超过 16000 字符返回 `null`（保留 `resource_id`/`biz_ref_no` 定位） |

## 7. 风险与回滚

| # | 风险 | 影响 | 止损 |
|---|---|---|---|
| **R1** | 审计表膨胀（每写请求一行，含快照） | 磁盘与查询变慢 | 已做：快照超 16KB 不记；索引只建 3 条（按真实查法）；后续按 `occurred_at` 分区/归档（不在本期） |
| **R2** | 审计写失败被静默吞掉 | 审计链路"看起来正常" | `erp_audit_write_failed_total`（应恒为 0）+ `erp_audit_logs_total_all` 长期不涨即告警 |
| **R3** | `/actuator/prometheus` 匿名可访问 | 指标暴露到公网 | 生产用 `management.server.port` 独立端口或 Nginx 内网白名单（已写进 `SecurityConfig` 注释与本文档） |
| **R4** | 切面切入点被改窄 | 新写接口静默不审计 | **INV-15 用例就是为此存在**：`hasSizeGreaterThan(30)` 自检枚举规模 + 逐接口断言，漏一个即红 |
| **R5** | 与其它泳道合并冲突 | 合并代价 | 共享文件全部纯追加（§2.3）；已 rebase 到 `dd89165` |

### 7.1 回滚

本泳道全部改动可按层独立回退：

1. **代码**：删除 `com.erp.sys` 整个包 + 回退 `ArchitectureTest` 的 2 规则/4 用例。
2. **共享文件**：每次改动都是纯追加，`git revert` 单文件即可，不会带走别人的改动。
3. **迁移**：V13 新增 3 张表 + 权限种子，`DROP TABLE audit_logs, dict_items, dict_types;`
   + `DELETE FROM app_role_permissions WHERE permission IN ('sys:*','sys:read')`。
   **会丢审计历史** —— 生产回滚前应导出。
4. **契约**：删除 `paths` 里 6 个 `/audits*`、`/dicts*` 与 3 个 schema（纯追加，位置固定）。
