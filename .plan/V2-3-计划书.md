## 2. 关键设计

### 2.1 迁移 V11（追加式，不改 V1~V8）

新增表：

1. `sales_quotes` / `sales_quote_lines`（报价单；任务书未列但 FR-SAL-05 必需）
2. `so_shipment_plans` / `so_shipments` / `shipment_lines`（发货计划 + 按仓拆单 + 拣货行）
3. `customer_receivables`（每张出货单一条，余额随出货/退货/回款增量）
4. `customer_receipts` / `receivable_allocations`（收款单 + 核销明细；receipts 为核销守恒的抬头）
5. `product_bundles` / `bundle_items`
6. `customer_credit_snapshots`

加列：

- `customers.credit_limit BIGINT NOT NULL DEFAULT 0`（0 = 不设限，保证存量客户不突变）
- `customers.credit_days INTEGER NOT NULL DEFAULT 0`
- `skus.season_code / band_code / launch_date`
- `warehouses.priority INTEGER NOT NULL DEFAULT 100`
  - **★ 与 V2-1 的 V9 双写**：必须写成
    `ALTER TABLE warehouses ADD COLUMN IF NOT EXISTS priority INTEGER NOT NULL DEFAULT 100;`
    并在迁移注释标明"与 V9 双保险，谁先合谁建"。
- `sales_order_lines.bundle_id / bundle_ratio / bundle_group_no`
  - 套装订单仍落**组件行**（`sku_id` 保持 NOT NULL），组件行带 bundle 分组与配比；
    套装本身不建库存余额行（INV-16）。
- `sales_order_line_reservations.warehouse_id / batch_no`
  - 跨仓自动选仓后，一行订单可有多仓预占；发货计划据此按仓拆单。

索引/约束要点：

- 报价：`uq_quote_no`、`uq_quote_request`、`uq_quote_convert_request`、`uq_quote_converted_order`。
- 发货：`uq_shipment_plan_request`、`uq_shipment_no`、`uq_shipment_line_reservation`（一条预占只能被一个拣货行占用，天然防重复计划）。
- 应收：`uq_receivable_order`（一单一应收）。
- 收款：`uq_receipt_no`、`uq_receipt_request`；核销明细 `CHECK amount > 0`、唯一 `(receipt_id, receivable_id)`。
- 套装：`uq_bundle_code`、`uq_bundle_item`、`CHECK ratio_qty > 0`。
- 权限种子：`sal:quote`、`sal:pick`、`sal:receipt`；读权限复用 `sal:read`；信用配置用 `mdm:write`。

### 2.2 报价单（FR-SAL-05）

- 状态复用 `DocumentStatus` 七态；`COMPLETED` 表示已转化，`converted_order_id` 唯一。
- 转化入口 `POST /sales-quotes/{id}/convert`：
  - 仅 `APPROVED` 可转化；`validUntil < today` 拒绝（`SAL_QUOTE_STATUS_ILLEGAL`）。
  - 请求可带 `warehouseId`（指定仓）或省略（按优先级自动选仓/拆单）。
  - 转化复用 `SalesOrderApplicationService` 的建单/预占/信用校验：
    **信用超限或库存不足时整单回滚，报价单保持 APPROVED，且不产生任何预占。**
  - 幂等：`convert_request_id` 唯一；同键重放返回首次订单；已转化后用新键再转化 → 409。
- 报价单号前缀 `QT`（`DocumentNumberGenerator.DocType.SALES_QUOTE`）。

### 2.3 套装（FR-SAL-10 / INV-16）

- `product_bundles(code,name,price_amount,enabled)` + `bundle_items(bundle_id,component_sku_id,ratio_qty)`。
- 建单时把套装行**展开为组件行**：组件数量 = 套装数量 × 配比；组件行写
  `bundle_id / bundle_ratio / bundle_group_no`，`sku_id` 仍为组件 SKU。
- **套装不持有库存**：不写 `inventory_balances`/`inventory_ledger` 的 bundle 行（bundle 不是 SKU）。
- 套装可用量（单仓）：
  `availableBundles(warehouse) = min over components floor(componentAvailable / ratio)`。
  跨仓汇总口径：`min over components floor(sum(componentAvailable across warehouses) / ratio)`，
  自动选仓时按**每个仓的 min** 逐仓吃量，保证组件同仓成套。
- INV-16：对每个 `(order, bundle_group_no)`：
  `bundleShippedQty × ratio_i == componentLine_i.shippedQty`；库存侧组件扣减总量 =
  `bundleShippedQty × ratio_i`。套装无余额行、无流水。
- 定价：组件行按组件零售价 × 折扣计价（保持与日清/结算同一 `lineAmount` 口径）；
  bundle.price_amount 仅作报价展示，不参与结算，避免"分摊舍入与结算重算不一致"。

### 2.4 自动选仓/拆单（FR-SAL-11）

- 仓库排序：`enabled = true` 且 `priority DESC, id ASC`。
- 普通建单仍按指定仓；新增 `POST /sales-orders/auto-split`（无仓建单）：
  - 非套装行：按仓顺序吃 `available`，**单仓够则不拆，不足才进入下一仓**；
  - 套装行：按仓计算 `min(组件可用/配比)` 后吃量，组件在该仓一起预占；
  - 全部行预占在**一个事务**内完成；任一行总量不足 → 整单回滚，无预占残留；
  - 订单头 `warehouse_id` 记首个（优先级最高）仓，真实分配见预占分段。
- 守恒：`Σ 预占分段数量 == 订单行数量`；`Σ 发货计划行 == 原订单行未出量`；
  单仓足够时预占/发货计划只出现一个仓。

### 2.5 拣货/发货（FR-SAL-06）

- 发货计划：`POST /sales-orders/{id}/shipments`（幂等键 `X-Request-Id`）
  - 读取订单行仍 ACTIVE 的预占分段，按 `warehouse_id` 分组；
  - 每个仓生成一张 `so_shipments`（`DRAFT`），每个预占分段生成一条 `shipment_lines`
    （`planned_qty = reserved_qty`，唯一占用该 `reservation_id`）；
  - 单仓足 → 一张发货单；跨仓 → 多张（拆单）。
- 扫码：`POST /shipments/{id}/scan`，按 `shipmentLineId`（可带 `barcode` 校验）累计
  `picked_qty`，原子守卫 `picked_qty + qty <= planned_qty`；全部扫满 → `PICKED`。
- 确认：`POST /shipments/{id}/confirm`，要求 `PICKED`；
  - 按 SKU 汇总本发货单数量 → `inventory.shipOut`（FEFO，可能拆批次写多条流水）；
  - 逐条 `consumeReservation`；累计订单行 `shipped_qty`；推进订单 `PARTIAL/COMPLETED`；
  - 同步应收：`shippedAmount` 增量写入 `customer_receivables`；
  - 幂等：`confirm_request_id` 唯一，同键重放返回首次结果。
- 兼容旧 `POST /sales-orders/{id}/ship`：改造为按预占的 `warehouse_id` 分组出库，
  单仓订单行为不变；红冲（V8）语义保持不变。

### 2.6 应收/收款/信用（FR-SAL-07/08/09）

- 应收一单一结算对象：`customer_receivables(sales_order_id UNIQUE, customer_id, shipped_amount,
  returned_amount, received_amount, balance, due_date, status)`。
- 不变量（数据库 CHECK + 服务层同口径）：
  `balance = shipped_amount - returned_amount - received_amount`。
- 出货增量：`shipped_amount += 本批发货金额`，`balance +=` 同额；
  退货入库：`returned_amount += 退货金额`，`balance -=` 同额；
  收款核销：`received_amount += 核销额`，`balance -=` 核销额。
- 日期：`due_date = clock.today() + customers.credit_days`（**只用 ClockProvider**）。
- 收款单：`customer_receipts(receipt_no, customer_id, amount, biz_date, request_id UNIQUE)`；
  核销明细 `receivable_allocations(receipt_id, receivable_id, amount)`。
- **核销守恒**：`Σ allocations.amount == receipt.amount`（必须精确相等，否则拒绝）；
  单笔核销不得超过应收余额（条件 UPDATE `balance >= ?`），超额 → `SAL_RECEIPT_OVER_ALLOCATED`；
  收款金额与分配合计不等 → `SAL_RECEIPT_UNBALANCED`。
- 信用控制：
  - `credit_limit = 0` 视为不设限（存量客户/测试零破坏）；
  - 敞口 = `Σ 应收余额 + Σ 未出货订单的未出金额`；新单金额计入后 > 限额 → 拒单
    `SAL_CREDIT_LIMIT_EXCEEDED`；**校验发生在任何预占之前**（硬验收 6）；
  - 通过时写 `customer_credit_snapshots`（`snapshot_date = clock.today()`，记录限额/敞口/订单）；
  - 客户行 `SELECT ... FOR UPDATE` 串行化并发授信。
- 红冲联动：已出货订单红冲前检查应收 `received_amount == 0`，否则拒绝
  （`SAL_STATUS_ILLEGAL`，避免形成"已收款但单据作废"的死账）；无收款时应收置 `VOIDED`、余额归零。

### 2.7 季节/年份/波段（FR-MDM-08）

- `skus.season_code`（如 `2026SS`）、`band_code`（波段）、`launch_date`（上市日期）。
- 查询支持 `seasonCode / bandCode / launchDateFrom / launchDateTo / seasonYear`；
  `seasonYear` 从 `launch_date` 派生（同一年 = 年份维度），不额外加冗余列。
- SKU 创建/更新可写三列；停用逻辑不变。
