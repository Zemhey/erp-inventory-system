## 1. 范围与不变量

| 块 | 数据 | 硬不变量 |
|---|---|---|
| 客户收货地址 | `customer_addresses`（一对多） | 同一客户最多一个默认地址；地址键客户内唯一；停用/不物理删除，历史单据仍指向客户 |
| 仓库库位 | `warehouse_locations` + `warehouses.capacity_qty` | 库位编码仓库内唯一；启用库位容量合计 ≤ 仓库容量；核对端点报告 `==` |
| 商品规格属性 | `product_attribute_values`（商品级键值） | 键商品内唯一；全量替换；不改 SKU 颜色×尺码唯一键与季节/波段 |

**历史单据口径（写死在实现与报告里）**：
- 地址：不提供物理 DELETE；停用只置 `enabled=false`。`sales_orders.customer_id` 仍指向客户，
  地址变更/停用不会改写历史单据；`customer_addresses.customer_id` 外键 `ON DELETE RESTRICT`，
  客户本身也走软停用，因此不存在“删地址导致历史断链”。
- 库位：库存余额维度仍是 `(SKU, 仓库, 批次)`（V1 设计，不引入库位维度）。
  库位停用只改自身 `enabled`，不触碰 `inventory_balances` / `inventory_ledger`；
  用例直接比对停用前后库存行数与流水条数。

## 2. 守恒口径（库位）

`SUM(启用库位的 capacity_qty) == warehouses.capacity_qty`。

- `warehouses.capacity_qty = 0` 表示“仓库未设定容量”，此时不建库位容量上限；
  核对端点照实返回 `0 vs 合计`，一致性由等式本身决定（不会特判成绿）。
- 建/改/启用库位时，若仓库容量 > 0 且 `已用 + 本库位容量 > 仓库容量` → `409 MDM_LOCATION_CAPACITY_EXCEEDED`。
- 允许暂时“分配不足”（合计 < 仓库容量），核对端点报 `consistent=false` 并给出差额；
  这正是运营补齐库位前的真实状态，不隐藏。
- 停用库位不参与合计；这是“库位停用”的自然语义，也让核对能暴露容量缺口。

## 3. 迁移 V18

`V18__mdm_customer_address_location_attribute.sql`（B1 占 V17，本泳道不改号）：

1. `warehouses` 追加 `capacity_qty BIGINT NOT NULL DEFAULT 0 CHECK (capacity_qty >= 0)`（存量行自动 0）。
2. 新表 `customer_addresses`：
   - `tenant_id BIGINT NOT NULL`、`customer_id` FK `ON DELETE RESTRICT`；
   - `UNIQUE (tenant_id, customer_id, address_key)`；
   - `UNIQUE (tenant_id, customer_id) WHERE is_default`（最多一个默认）；
   - `CHECK (NOT is_default OR enabled)`（默认必须启用）；
   - `UNIQUE (tenant_id, create_request_id) WHERE create_request_id IS NOT NULL`（建单幂等）。
3. 新表 `warehouse_locations`：
   - `tenant_id NOT NULL`、`warehouse_id` FK `ON DELETE RESTRICT`；
   - `UNIQUE (tenant_id, warehouse_id, location_code)`；
   - `CHECK (capacity_qty > 0)`；`UNIQUE (tenant_id, create_request_id) WHERE ...`。
4. 新表 `product_attribute_values`：
   - `tenant_id NOT NULL`、`product_id` FK `ON DELETE CASCADE`；
   - `UNIQUE (tenant_id, product_id, attribute_key)`。
5. 三张新表都装 `erp_tenant_fill()` BEFORE INSERT 触发器（复用 V16 函数；会话租户缺失时保持 NOT NULL 响亮失败）。
6. 可回滚：`DROP TABLE product_attribute_values, warehouse_locations, customer_addresses;`
   `ALTER TABLE warehouses DROP COLUMN capacity_qty;`；整个文件可重复执行（`IF NOT EXISTS`）。
7. `TenantTables.ALL` 增加三张表 —— `TenantSchemaIT` 双向比对与 `TenantSql` 改写范围同源。

## 4. 接口（B1 合并后落入 openapi）

### 客户地址（`mdm:read` / `mdm:write`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/customers/{customerId}/addresses?onlyEnabled=` | 列表（数组，非分页） |
| POST | `/customers/{customerId}/addresses` | 建地址，`X-Request-Id`；首条自动默认 |
| PUT | `/customers/{customerId}/addresses/{addressId}` | 改收件信息/默认标志；编码不可改 |
| POST | `/customers/{customerId}/addresses/{addressId}/default` | 切换默认（纯状态，无幂等键） |
| POST | `/customers/{customerId}/addresses/{addressId}/disable` | 停用；默认地址停用后自动提升下一条启用地址 |
| POST | `/customers/{customerId}/addresses/{addressId}/enable` | 重新启用（不自动设默认） |

字段：`addressKey`、`recipientName`、`phone`、`province`、`city`、`district`、
`detailAddress`、`isDefault`、`enabled`。错误码：`MDM_ADDRESS_NOT_FOUND(404)`、
`MDM_ADDRESS_DUPLICATED(409)`、`SYS_VALIDATION_ERROR(400)`。

### 仓库库位（`mdm:read` / `mdm:write`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/warehouses/{warehouseId}/locations?onlyEnabled=` | 列表 |
| POST | `/warehouses/{warehouseId}/locations` | 建库位，`X-Request-Id` |
| PUT | `/warehouses/{warehouseId}/locations/{locationId}` | 改名称/容量；编码不可改 |
| POST | `/warehouses/{warehouseId}/locations/{locationId}/disable` | 停用 |
| POST | `/warehouses/{warehouseId}/locations/{locationId}/enable` | 启用（重跑容量校验） |
| GET | `/warehouses/{warehouseId}/locations/reconcile` | 守恒核对 |
| PUT | `/warehouses/{warehouseId}/capacity` | 设置仓库容量（0=未设定） |

核对响应：`warehouseId / warehouseCapacityQty / locationCapacityQty / difference /
enabledLocationCount / totalLocationCount / consistent`。
错误码：`MDM_LOCATION_NOT_FOUND(404)`、`MDM_LOCATION_DUPLICATED(409)`、
`MDM_LOCATION_CAPACITY_EXCEEDED(409)`。

### 商品规格属性（`mdm:read` / `mdm:write`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/products/{productId}/attributes` | `{ items: [{key,value}] }` |
| PUT | `/products/{productId}/attributes` | 全量替换（空数组=清空）；事务内删旧插新 |

校验：key 1~32、value 1~256、单商品最多 50 条、请求内 key 不得重复。

## 5. 后端结构

- `domain/CustomerAddress`、`WarehouseLocation`、`ProductAttribute`；`Warehouse` 追加 `capacityQty`。
- `repository/*Repository`：全部走 `JdbcTemplate` 文本 SQL（自动被 `TenantSql` 注入租户）。
- 默认地址切换与容量校验统一先锁客户/仓库行（`FOR UPDATE`），唯一索引仍作最终兜底。
- 错误码纯追加到 `ErrorCode` 末尾；不重排既有码。
- `TenantTables` 三张新表；不改 `TenantSql` 规则本身（只依赖其标准 SELECT/INSERT/UPDATE/DELETE 能力）。

## 7. 风险与边界

1. 库存余额不含库位维度（继承 V1，明确不在本泳道扩维）；守恒口径限定为“容量分配”。
2. 地址不提供 DELETE（避免历史链路歧义）；前端只暴露停用/启用。
3. `TenantSql` 不支持复杂连接树：新 SQL 一律单表/标准 JOIN，并补改写用例。
4. B1 合并冲突：若 B1 也改 `TenantTables`/`ErrorCode`，按“双方条目都保留”解决。
5. 契约接棒前 `ApiContractMappingIT` 会因新端点未入契约而红——这是预期状态，
   定向测试排除该门禁；接棒后补契约再跑全量。
