## 1. 范围

### 1.1 做什么

1. **报价单**（FR-SAL-05）：`pages/quotes/quotes`（列表 + 状态筛选）与 `pages/quotes/detail`
   （详情 + 提交 / 审核 / 驳回 / 作废 / **转出货单**）。
2. **发货作业**（FR-SAL-06）：`pages/shipments/shipments`（列表）与 `pages/shipments/detail`
   （**行级扫码累计拣货** + 发货确认）；出货单详情页追加「生成发货计划」入口。
   扫码是本页存在的理由 —— 移动端是唯一天然带摄像头的端。
3. **应收与收款**（FR-SAL-07/08）：`pages/receivables/receivables`（客户应收列表 + 汇总）
   与 `pages/receivables/detail`（余额自洽 + 收款登记，部分核销可用、超额逐字报错）。
4. **待我审批**（FR-APS-02）：`pages/approvals/approvals`（我的待办）与 `pages/approvals/detail`
   （节点时间线 + 同意 / 驳回 / 撤回 / 转办 / 接办）。
5. `pages.json` 追加 8 页（10 → 18），工作台追加四个入口卡片。

### 1.2 不做什么（明确划掉）

- **报价单建单**：多行编辑 + SKU 选择 + 折扣矩阵是桌面表单的活，Web 端已有；
  移动端只做「流转与作业」，与既有 `purApi` / `salApi` 的裁剪口径一致。
- **发货计划拆单参数**：`createPlan` 由后端按仓库 priority 自动拆，移动端不暴露选择器。
- **审批流定义管理**（`/approvals/flows`）、**启停流程**（`aps:flow:write`）：配置类动作留在 Web。
- **红冲 / 退货 / 月结**：不在本批。
- 不改后端、不改契约、不改 Web —— 三条泳道正在并行改后端。

## 2. 接口形状的事实源

★ 全部来自 Controller 的 `toMap` 与 `record`，不来自 `openapi.yaml`。逐条出处见报告 §6。
关键约定：

- 分页响应恒为 `data: { items, total, page, size }`（`shared/web/ApiResponses.java:27`）。
- 金额一律**整数分**，只在展示层除 100（`src/utils/money.ts` 是唯一出口，页面不得散落 `÷100`）。
- 写操作的 `X-Request-Id` 由 `src/api/client.ts:226` 的拦截器统一注入，**页面不手写幂等键**
  （先例：`pages/purchase/detail.vue`）。后端多个接口把该头标了 `@NotBlank`，
  包括 `POST /sales-quotes/{id}/convert`、`POST /sales-orders/{id}/shipments`、
  `POST /shipments/{id}/confirm`、`POST /customer-receipts`、`POST /approvals`。
- `POST /shipments/{id}/scan` 与 `POST /approvals/{id}/approve|reject|withdraw` **不要求**幂等键头，
  但仍走同一条拦截器（带了无害）。

## 3. 两个必须守住的设计边界

### 3.1 两套状态机不共用色板（任务书坑 3）

`DocumentStatus`（单据七态，含 `isExecutable()` / `isOpen()`）与 `ApprovalStatus`
（审批七态：DRAFT / PENDING / TRANSFERRED / APPROVED / REJECTED / WITHDRAWN / CANCELLED）
是同名字、不同义的两套。移动端做法：

- 单据页继续用 `src/utils/documentStatus.ts`（既有镜像）。
- 审批页新建 `src/utils/approvalStatus.ts` 独立镜像，**不 import documentStatus**，
  词表也不同：审批侧的 `APPROVED` 译作「审批通过」而不是单据侧的「已审核」，
  `REJECTED` 是**终态**（单据侧可退回草稿重提，审批侧驳回后重提是**新实例**）。
- 转办后 `TRANSFERRED` 不是终态，`接办` 走 `POST /approvals/{id}/accept-transfer`。

### 3.2 「待我审批」在客户端过滤，因为后端没有这个参数

`GET /approvals` 只接受 `status` / `bizType`（`aps/api/ApprovalController.java:98`），
没有「按当前人」的过滤 —— 逐节点的资格判定在
`ApprovalApplicationService` 里按 `approverPermission` 做（`:175`）。
所以待办口径只能是：**实例在飞（PENDING / TRANSFERRED）且我有当前节点的 `approverPermission`**。
这条推导写在页面里并注明「后端无此参数」，不是移动端自创规则；
按钮显隐照同一口径，**最终能否执行仍由后端 403 兜底**。

## 4. 扫码的降级设计（本批亮点页的可用性前提）

`uni.scanCode` 只在小程序 / App 可用，H5 与微信开发者工具里没有。页面做法：

1. 有摄像头能力 → 「扫码」按钮直接调起，回调把 `{ code, barcode }` 落到当前聚焦行；
2. 调起失败或环境不支持（`#ifdef` + `fail` 回调）→ 退化成**条码输入框 + 提交**，
   界面明确标出「当前环境不支持摄像头，已切为手录」；
3. 两条路径打的是同一个接口 `POST /shipments/{id}/scan`，条码由后端逐字比对
   （`ShipmentApplicationService:197` 不匹配即 `SYS_VALIDATION_ERROR`），
   降级不放松校验。

★ 关键性质：**H5 里页面必须可用**，否则 E2E 无从验证扫码 —— 这是降级不是偷懒。

## 8. 已知的既有缺陷（本批顺手修，都属 miniapp 范围）

1. `e2e/helpers/db.ts`、`e2e/start-db.mjs`、`e2e/stop-db.mjs` 把容器名与端口写死成
   `erp-m4b-pg` / 15441 —— 并行泳道一跑就互删数据。改为环境变量可覆盖，默认值不变。
2. `e2e/seed.setup.ts` 把 storageState 的 `origin` 写死 `http://127.0.0.1:3005`。
   storageState 按 origin **精确装载**，实跑 3020 时所有 `app` project 用例会静默地「没登录」，
   症状是满屏跳登录页、最难归因。改为跟随 `E2E_BASE_URL`。
3. `stop-db.mjs` 默认删 `erp-m4b-pg`，是一条会误伤别泳道的命令；保留默认值但在删除前打印目标。

## 9. 坑（跑通前已知的，全部照做）

1. 中文路径下 Gradle 全部测试 ClassNotFoundException（ADR-0010）→ 走 `D:\erp-build-v2d1`，
   且**不要**从 Git Bash `cd` 进联接再调 `.bat`（MSYS 会解析回中文目录）。
2. `esbuild` 报 `Access is denied` → `TEMP` / `TMP` 指到 `frontend/miniapp/.tmp`
   （`playwright.config.ts` 已对 webServer 这么做，命令行直跑时要自己带）。
3. 本机第三方程序绑 `[::]:8081`，Tomcat 双栈会报端口占用 → 带
   `-Djava.net.preferIPv4Stack=true`。
4. 宿主 PG 在 15432/15441 段（5432 落在 Windows 保留端口段），本泳道用 15460。
5. 含中文的 `.ps1` 必须 UTF-8 with BOM + CRLF，否则 PS 5.1 按 GBK 解码报假语法错。
6. 8080/3000 属用户本人、8081/3001 属 Web E2E 保留 —— 不占、不杀不属于自己的进程。
7. 启用审批流会改变 `approve()` 的行为（`ApprovalGate.requireApproved` 只在**单据审核**处生效，
   不拦 ship）。E2E 里启用流程必须放在自己的 spec 内并在末尾还原，否则别的用例的建单审核会撞
   `APS_APPROVAL_REQUIRED`。

## 10. 回滚方式

- 全部改动都在 `frontend/miniapp/**` 与本目录两个文件里，回滚 = 丢弃这些路径的改动：
  `git stash push -u -m "v2d1-rollback" -- frontend/miniapp .plan/V2-D1-计划书.md .plan/V2-D1-报告.md`
  ★ 不用 `git checkout .` / `reset --hard` / `clean -fd`（纪律 3）。
- 逐提交回滚：本泳道提交都是小步、单主题，`git revert <sha>` 即可，不涉及后端与契约。
- 自建资源回收：`docker rm -f erp-v2d1-pg`（务必带 `E2E_DB_CONTAINER=erp-v2d1-pg` 再跑
  `npm run e2e:db:stop`，否则会删掉 M4B 的库）。产物目录 `.e2e-artifacts/`、`.tmp/` 已 gitignore。
