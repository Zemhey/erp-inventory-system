## 0. 通用约定（沿用既有契约，不新增）

- 路径前缀 `/api/v1`；响应信封 `ApiResponse<T>`（`{code,message,data,traceId}`）、列表为**数组**（非分页）。
- 写操作（POST/PUT）必须携带 `X-Request-Id`（非空）；缺失或空白 → `400 SYS_VALIDATION_ERROR`。
  例外：纯状态切换 `/{id}/default`、`/{id}/disable`、`/{id}/enable` 与 `PUT .../capacity` 不要求幂等键
  （与既有 `submit/approve/void` 等状态端点的既有做法一致，重放天然幂等）。
- 跨租户 / 不存在 / 不属于父资源：**统一 404**，错误码用本模块的 `MDM_*_NOT_FOUND`，不泄露存在性。
- 权限：读 `mdm:read`，写 `mdm:write`。
- 金额不涉及；容量均为整数件数（`long`，单位=件/SKU 存放单元）。

## 1. 新增错误码（`ErrorCode`，纯追加，不重排既有码）

| 错误码 | HTTP | 触发条件 |
|---|---|---|
| `MDM_ADDRESS_NOT_FOUND` | 404 | 地址不存在 / 不属于该客户 / 不属于当前租户 |
| `MDM_ADDRESS_DUPLICATED` | 409 | `addressKey` 在客户内重复；或 `X-Request-Id` 被另一个客户的地址复用 |
| `MDM_LOCATION_NOT_FOUND` | 404 | 库位不存在 / 不属于该仓库 / 不属于当前租户 |
| `MDM_LOCATION_DUPLICATED` | 409 | `locationCode` 在仓库内重复 |
| `MDM_LOCATION_CAPACITY_EXCEEDED` | 409 | 启用库位容量合计将超过仓库容量（仓库容量 > 0 时） |
| `MDM_PRODUCT_ATTRIBUTE_INVALID` | 400 | 请求内 `key` 重复（DB 唯一键会兜底，但先给 400 语义错误） |

> 说明：字段级校验（必填、长度、`capacityQty >= 1`、单商品属性条数上限）由 Bean Validation 直接返回
> `400 SYS_VALIDATION_ERROR`，与既有接口一致；`MDM_PRODUCT_ATTRIBUTE_INVALID` 只用于
> "结构合法但语义非法"（重复 key）的场景。

## 2. 客户收货地址（一对多）

### Schema `CustomerAddress`

| 字段 | 类型 | 必填 | 说明 / 边界 |
|---|---|---|---|
| `id` | integer(int64) | 响应 | 地址 ID |
| `customerId` | integer(int64) | 响应 | 所属客户 |
| `addressKey` | string(maxLength 32) | 是（建） | 客户内唯一的地址键；**创建后不可改** |
| `recipientName` | string(maxLength 64) | 是 | 收件人 |
| `phone` | string(maxLength 32) | 是 | 电话（不强校验格式，允许座机/手机/带分机） |
| `province` | string(maxLength 32) | 是 | 省 |
| `city` | string(maxLength 32) | 是 | 市 |
| `district` | string(maxLength 32) | 否 | 区/县，可空 |
| `detailAddress` | string(maxLength 200) | 是 | 详细地址（街道门牌） |
| `isDefault` | boolean | 否（默认 false） | 默认收货地址；**同一客户最多一个** |
| `enabled` | boolean | 否（默认 true） | 停用即软删；默认地址必须启用 |

**不变量**
1. `UNIQUE (tenant_id, customer_id, address_key)`。
2. `UNIQUE (tenant_id, customer_id) WHERE is_default` —— 同一客户最多一个默认。
3. `CHECK (NOT is_default OR enabled)` —— 默认地址不能处于停用态。
4. 客户的第一条地址自动成为默认（即使请求 `isDefault=false`）。
5. **不提供 DELETE**：历史单据 `sales_orders.customer_id` 仍指向客户，地址只做停用，
   `customer_addresses.customer_id` 外键 `ON DELETE RESTRICT`，客户本身亦走软停用。

### 2.1 `GET /customers/{customerId}/addresses`
- 权限 `mdm:read`；Query `onlyEnabled`（boolean，默认 false）
- 200 `ApiResponse<CustomerAddress[]>`
- 404 `MDM_ADDRESS_NOT_FOUND`：客户不存在或不属于当前租户（**父资源越权同样是 404**）
- 排序：`isDefault DESC, id ASC`（默认地址恒在首位，前端无需二次排序）

### 2.2 `POST /customers/{customerId}/addresses`
- 权限 `mdm:write`；请求头 `X-Request-Id`
- Body：`addressKey`、`recipientName`、`phone`、`province`、`city`、`district?`、`detailAddress`、`isDefault?`、`enabled?`
- 201 `ApiResponse<CustomerAddress>`
- 400 `SYS_VALIDATION_ERROR`（必填缺失/超长）
- 400 `SYS_VALIDATION_ERROR`（`isDefault=true` 且 `enabled=false`）
- 404 `MDM_ADDRESS_NOT_FOUND`（客户不存在/跨租户）
- 409 `MDM_ADDRESS_DUPLICATED`（`addressKey` 重复；或幂等键被另一客户复用）
- 幂等：同 `X-Request-Id` 重放返回 201 与同一条地址（不再新建）

### 2.3 `PUT /customers/{customerId}/addresses/{addressId}`
- Body：`recipientName`、`phone`、`province`、`city`、`district?`、`detailAddress`、`isDefault?`、`enabled?`
  （**不含 `addressKey`**，编码不可改）
- 200 `ApiResponse<CustomerAddress>`
- 400 `SYS_VALIDATION_ERROR`
- 404 `MDM_ADDRESS_NOT_FOUND`
- 409 无（默认唯一由切换端点负责，此处 `isDefault=true` 等价于切换）
- 语义：`isDefault=true` 会把同客户其它地址的默认标志清掉（同事务）

### 2.4 `POST /customers/{customerId}/addresses/{addressId}/default`
- 无 body；切换默认（纯状态，无幂等键，重放幂等）
- 200 `ApiResponse<CustomerAddress>`（返回被设为默认的那条）
- 404 `MDM_ADDRESS_NOT_FOUND`
- 409 `MDM_ADDRESS_DUPLICATED` 不使用；停用地址设默认 → 400 `SYS_VALIDATION_ERROR`
  （实现上先恢复启用再设默认则不需要该分支；**本实现取"必须启用才可设默认"**）

### 2.5 `POST /customers/{customerId}/addresses/{addressId}/disable`
- 200 `ApiResponse<CustomerAddress>`
- 404 `MDM_ADDRESS_NOT_FOUND`
- 语义：置 `enabled=false`；**若停用的是默认地址，自动把 id 最小的启用地址提升为默认**
  （无其它启用地址时该客户暂时无默认，属合法状态）；历史单据不受影响
- 重放：已停用再停用 → 200，状态不变（幂等）

### 2.6 `POST /customers/{customerId}/addresses/{addressId}/enable`
- 200 `ApiResponse<CustomerAddress>`
- 404 `MDM_ADDRESS_NOT_FOUND`
- 语义：置 `enabled=true`；**不自动设为默认**

## 3. 仓库库位

### Schema `WarehouseLocation`
| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | integer(int64) | 响应 | |
| `warehouseId` | integer(int64) | 响应 | 所属仓库 |
| `locationCode` | string(maxLength 32) | 是（建） | **仓库内唯一**；创建后不可改 |
| `name` | string(maxLength 64) | 否 | 展示名 |
| `capacityQty` | integer(int64) | 是 | `>= 1`，件数 |
| `enabled` | boolean | 否（默认 true） | 启用/停用 |

### Schema `WarehouseCapacityReconcile`（守恒核对）
| 字段 | 类型 | 说明 |
|---|---|---|
| `warehouseId` | integer(int64) | |
| `warehouseCapacityQty` | integer(int64) | 仓库设定的容量；**0 = 未设定** |
| `locationCapacityQty` | integer | **启用**库位容量合计 |
| `difference` | integer | `warehouseCapacityQty - locationCapacityQty`（可为负） |
| `enabledLocationCount` | integer | 启用库位数 |
| `totalLocationCount` | integer | 库位总数（含停用） |
| `consistent` | boolean | `warehouseCapacityQty > 0 && difference == 0`；未设定容量时恒 false 并如实报差额 |

**守恒口径（写进契约描述，避免歧义）**
- 等式：`SUM(启用库位 capacityQty) == warehouses.capacityQty`。
- `capacityQty = 0` 表示仓库未设定容量，此时不设上限、核对报 `consistent=false` + 实际差额，**不做特判抹平**。
- 允许"分配不足"（合计 < 仓库容量），核对暴露差额 —— 这是补齐库位前的真实运营状态。
- 库存余额维度仍是 `(SKU, 仓库, 批次)`，**不引入库位维度**；库位停用不触碰 `inventory_balances` / `inventory_ledger`。

### 3.1 `GET /warehouses/{warehouseId}/locations`
- 权限 `mdm:read`；Query `onlyEnabled`（默认 false）
- 200 `ApiResponse<WarehouseLocation[]>`；排序 `locationCode ASC`
- 404 `MDM_LOCATION_NOT_FOUND`（仓库不存在/跨租户）

### 3.2 `POST /warehouses/{warehouseId}/locations`
- 权限 `mdm:write`；`X-Request-Id`
- Body：`locationCode`、`name?`、`capacityQty`、`enabled?`
- 201 `ApiResponse<WarehouseLocation>`
- 400 `SYS_VALIDATION_ERROR`（`capacityQty < 1`）
- 404 `MDM_LOCATION_NOT_FOUND`
- 409 `MDM_LOCATION_DUPLICATED`
- 409 `MDM_LOCATION_CAPACITY_EXCEEDED`（仓库容量 > 0 且 已用 + 本库位 > 仓库容量）

### 3.3 `PUT /warehouses/{warehouseId}/locations/{locationId}`
- Body：`name?`、`capacityQty`（不含 `locationCode`）
- 200 `ApiResponse<WarehouseLocation>`
- 400 / 404 `MDM_LOCATION_NOT_FOUND` / 409 `MDM_LOCATION_CAPACITY_EXCEEDED`
- 停用库位改容量不占用配额（不参与合计），但仍校验 `capacityQty >= 1`

### 3.4 `POST /warehouses/{warehouseId}/locations/{locationId}/disable` / `enable`
- 200 `ApiResponse<WarehouseLocation>`
- 404 `MDM_LOCATION_NOT_FOUND`
- `enable` 会重新跑容量校验 → 可能 409 `MDM_LOCATION_CAPACITY_EXCEEDED`
- 语义：停用不删行、不动库存表；历史库存/流水条数不变（用例 TC-MDM-049 断言）

### 3.5 `GET /warehouses/{warehouseId}/locations/reconcile`
- 权限 `mdm:read`
- 200 `ApiResponse<WarehouseCapacityReconcile>`
- 404 `MDM_LOCATION_NOT_FOUND`

### 3.6 `PUT /warehouses/{warehouseId}/capacity`
- 权限 `mdm:write`；Body `{ "capacityQty": 100 }`（`>= 0`，0=未设定）
- 200 `ApiResponse<Warehouse>`（沿用既有 `Warehouse` schema，含新字段 `capacityQty`）
- 400 `SYS_VALIDATION_ERROR`（负数）
- 404 `SYS_NOT_FOUND`（ warehouses 既有 NotFound 语义：仓库不存在/跨租户）
- **不校验**"下调容量是否低于已分配合计"：允许超额存在，由核对端点暴露 ——
  下调容量是运营决策，若硬阻断会让"缩库"无法执行；一致性与告警走 `consistent=false`。

### 3.7 既有 `Warehouse` schema 变更
`Warehouse` 新增只读字段 `capacityQty`（integer(int64)，默认 0）。
既有 `GET /warehouses`、`POST /warehouses`、`PUT /warehouses/{id}` 响应多一个字段，
**不新增必填**，向后兼容。

## 4. 商品规格属性

### Schema `ProductAttribute`
| 字段 | 类型 | 必填 | 边界 |
|---|---|---|---|
| `key` | string(maxLength 32) | 是 | 属性键，商品内唯一，如 `fabric`/`seasonFit` |
| `value` | string(maxLength 256) | 是 | 属性值 |

### Schema `ProductAttributeList`
```json
{ "items": [ { "key": "fabric", "value": "棉95%/氨纶5%" } ] }
```

### 4.1 `GET /products/{productId}/attributes`
- 权限 `mdm:read`
- 200 `ApiResponse<ProductAttributeList>`（无属性时 `items: []`，不返回 null）
- 404 `SYS_NOT_FOUND`（商品不存在/跨租户 —— 复用既有 product 404 语义，不新增码）
- 排序：`key ASC`（稳定，便于前端 diff 与 E2E 断言）

### 4.2 `PUT /products/{productId}/attributes`
- 权限 `mdm:write`；**无 `X-Request-Id`**（全量替换 = 天然幂等，语义为"设成这组值"）
- Body：`{ "attributes": [ { "key": "...", "value": "..." } ] }`，`attributes` 最多 50 条
- 200 `ApiResponse<ProductAttributeList>`（返回替换后的集合）
- 400 `SYS_VALIDATION_ERROR`（条数 > 50 / key 空或 > 32 / value 空或 > 256）
- 400 `MDM_PRODUCT_ATTRIBUTE_INVALID`（同一请求内 `key` 重复）
- 404 `SYS_NOT_FOUND`
- 语义：事务内"删旧 + 插新"；空数组 `{"attributes": []}` 表示清空
- **不影响**：SKU 颜色×尺码矩阵生成、`skus` 唯一约束、`season/band` 字段（用例 TC-MDM-051 断言）
