## 一、目标与得分点

这一段要把"AI 接进 ERP"讲成**两件不同的事**，而不是一个笼统的"我们支持 AI"：

| # | 评审要看到的 | 证据 |
|---|---|---|
| 1 | 人可以用**一句话**操作业务 | 工作台的指令框：`帮助` 直接问后端要意图清单；`查询库存`、`补货建议`、`账期 2026-10 进销存汇总` 当场出结果 |
| 2 | 它不是只会查询的花架子 | **目标级意图**：`补货建议` 一次组合"可用量 + 在途采购 + 上下限 + 补货公式"；**受限只读 SQL** 意图能回答"哪个客户贡献了最多毛利"这种没预置工具的问题 |
| 3 | **写操作没有被 AI 拿走**（这是这一段最值钱的评分点） | 写意图必须走 `计划 → 复核 → 人确认 → 带凭据执行 → 审计留痕`；待确认队列里那一条**要点一次才生效** |
| 4 | AI 接的是**可配置的**，不是硬编在代码里 | 「系统 → 自然语言 → AI 接入」：解析方式、复核方式、接口地址、模型名当场看得到，`/nl/settings/test` 能测连通，密钥加密存 `sys_config` |
| 5 | Agent 能直接操作（MCP 那一句） | `packages/mcp-server`：在 Agent 客户端里连上，先 `system_status` 自检，再 `query_inventory` / `dashboard_overview` 读数，最后 `nl_plan → nl_command` 走同一条"先看计划再执行"的路 |
| 6 | 我知道边界在哪 | 默认解析器是**离线关键词规则**，稳定可复现但不惊艳；惊艳版要填真实 Key；MCP 侧 Agent **只建草稿，不审核、不入库、不出货、不作废** |

**这段绝对不要讲的东西**：不说"接了大模型所以什么都能问"（意图是固定枚举，`sql_query` 也只在白名单视图上只读）；不说"AI 自动帮我们审单据"（恰恰相反，**审核明确不对 AI 开放**）；不要在镜头前口播 API Key。

## 四、逐字口播文案

**〔00:00 P1〕**
大家好，我是"云裳进销存"的唯一开发者。这是系列第五段，也是最后一段，申报的是可选项 **自然语言操作支持**，加 5%。另外任务.md 最后提的那两点里的"让 AI Agent 可以直接操作（MCP）"，我也在这一段一起交。

**〔00:15 P2〕**
先讲清楚我做了什么。两件事，不是一个。
第一件：**人可以用一句话操作这个系统**，入口就在工作台上。
第二件：**AI Agent 可以直接接进来**，走 MCP 协议。
两件事共同的底线只有一条：**写操作必须人签字。** 这一条我会用整段视频来证明，不是用一句话来讲。

**〔00:45 Web：帮助〕**
〔在指令框输 `帮助`，回车〕我用最笨的一句话开场：我打"帮助"。
〔出清单〕它回给我的是一张意图清单。这一点我想强调一下：**这张清单不是前端硬编码的菜单**，是这句话打到后端、后端把"我现在支持哪些意图"报回来的。
所以我改后端能力，前端不用跟着改。

**〔01:10 Web：查询〕**
〔输 `查询库存`〕查询库存，出来了。〔输 `账期 2026-10 进销存汇总`〕再一句，账期进销存汇总。
这些是**只读意图**，不需要确认，因为它不改任何东西。
我把数字说清楚：意图是一个固定枚举，**一共 12 个，9 个只读、3 个写**。写的那三个我下面单独讲。

**〔01:35 Web：补货建议〕**
〔输 `补货建议`〕
这一条是我最喜欢的一类，它叫**目标级意图**。
我说一下区别在哪：别的意图对应"一次操作"，比如查一次库存；这一句对应的是"**一个目标**"。
我要问"该补什么货"，按传统做法我得自己查可用量、再去查在途采购、再对照上下限、自己算差额。现在一句话，它把这几步组合完，**给我一张带依据的建议清单**。
〔指结论〕注意：**它只读，不建单、不预占**。建议要不要变成采购草稿，是人在这个页面上决定的。这也是我敢把它做成一句话的原因。

**〔02:00 Web：受限 SQL〕**
〔输"哪个客户贡献了最多毛利"〕
这一条走的是 `sql_query`。我要老实讲它的限制，因为它是我做得最小心的一块。
固定的工具只能表达"设计者事先想到的问法"。像"哪个客户贡献了最多毛利""上周退货率多少"，**没有任何一个预置工具装得下这种问法**，加工具等于加一种问法，永远追不上用户。
所以这里允许生成一条查询语句。**但它是只读的，而且限制是硬的**：语句在白名单视图上执行，那个视图已经按租户过滤过；8 秒超时；200 行上限；**写关键字和系统表在入口就被拒**。
它的风险面是"查得慢、查得杂"，不是"改错数据"。这两件事我不能混着说。

**〔02:25 Web：写链（灵魂镜头）〕**
〔输 `创建进货单 供应商=1 仓库=421 SKU=629 数量=10 单价=1200`〕
现在做写操作。我说一下这里的价格口径：**这个系统金额单位是分**，所以我这个单价 12 块。
〔出计划卡片〕**它没有直接建单。**
〔停两秒，指屏幕〕它先给了我三块东西：一个**计划** —— 打算做什么；**影响** —— 会动到哪些数据；一份**复核意见** —— 有没有问题。
后端在这种情况下会标一个 `requiresReview=true`，前端就**必须**把这张计划给人看过，人点头之后才能执行。
〔左侧栏 系统 → 自然语言 → 待确认队列〕我进待确认队列，这条就在里面挂着。
〔选中 → 点确认执行〕现在我才点执行。〔刷新 → 进货单列表〕这张草稿单出来了。
〔系统 → 自然语言 → 操作审计〕然后这里是审计，这一条操作留了痕，**谁发起的、计划长什么样、执行结果是什么，都在**。
〔看一眼镜头〕这一整条链我要说的就一句话：**AI 可以替人跑腿，不该替人签字。**
提交单据是跑腿 —— 把一张草稿送到该去的地方，人随时能撤回重来；**审核是签字** —— 签了责任就落在这个人头上。所以我**只开放提交和建草稿，审核、入库、出货、作废这四件事一律不对 AI 开放**，因为那动的是账和货，必须人看着实物做。
还有一处我在实现里特意卡死的：确认凭据**只有"生成计划"那一步能签发**。那个"复核"接口我刻意让它不签发凭据 —— 不然就等于给"跳过预览直接执行"开了第二条路。

**〔03:10 Web：AI 接入〕**
〔左侧栏 系统 → 自然语言 → AI 接入〕
这一页是"AI 怎么接"这件事的开关，我想说明的是**它是配出来的，不是写死在代码里的**。
〔指解析方式〕第一个字段，解析方式，有两个选项：「关键词规则（离线，不联网）」和「大模型 function calling」。
〔指复核方式〕第二个，复核方式：「仅确定性规则」，或者「规则 + AI 复核」—— 让模型再检查一遍这个计划有没有问题。
〔指接口地址、模型名〕第三、第四，接口地址和模型名，这里我填的是 DeepSeek 的地址和模型名。**换任何一家兼容 OpenAI 协议的模型，改的就是这两格。**
〔指密钥那行〕第五，密钥。**密钥是加密之后存进 `sys_config` 的，不进仓库、不进日志**，这一页也只有配置权限的账号能看到状态。〔点 连通测试〕这个按钮就是拿现在的配置去真打一次，通不通当场告诉你。
〔补一句，按实际口径二选一〕
**〔A 版〕** 现在这套跑的是我填好的大模型配置，你们刚才看到那些换着说法的问法就是它认出来的。
**〔B 版〕** 我今天这一段跑的是**离线关键词规则解析器**。我说明白：它稳定、不联网、可复现，代价是**只认设计好的几种写法**，不惊艳。真正让它听懂各种说法，就是在上面这一格切成大模型，这是我准备了一把 Key 就能开的事，不是架构缺东西。

**〔03:35 手机〕**
〔手机 工作台 → 「自然语言操作」卡片〕〔输一句查询〕
同一个后端入口，移动端也有。这一句我强调的重点是：我**没有为演示另搭一套**，手机上点的是刚才那条链。

**〔03:50 P3〕**
〔回 PPT〕写操作这件事的设计我用一页说清，因为这是整个 AI 功能里我最在意的部分。
三层保险：**一**，能力上就不给 —— 审核、入库、出货、作废四类动作不对自然语言开放；**二**，写意图必须先生成计划给人看，`requiresReview` 是后端标的，前端绕不过去；**三**，执行要带一个由计划签发的凭据，审计里全程留痕。
〔指右下角〕还有一档：复核意见是有结论的，三档 —— 不反对、要人判断、不允许执行。**第三档直接不签发凭据**，那就执行不了。

**〔04:15 MCP：自检〕**
〔切到 Agent 客户端〕第二个方向，让 AI Agent 直接操作这个系统，走 MCP。
〔Agent 调 system_status〕我接进来之后，第一件事不是让它查数据，我让它**先自检**。
〔指返回〕它回给我：后端在不在线、延迟多少毫秒、数据库这些依赖健康不健康、**以及我现在是以什么身份连的**。
这个工具是我特意加的 —— Agent 被问到"系统通不通"的时候，不该靠猜。
〔指工具列表〕这一版我暴露的工具是 **9 个**，以代码里那个 `TOOL_NAMES` 清单为准，我不念一个更大的数。

**〔04:50 MCP：读数〕**
〔Agent 调 query_inventory〕〔指结果〕查库存，按 SKU 和仓库过滤。〔Agent 调 dashboard_overview〕经营概览，八个 KPI 加待办一次拿走。
这里有个我认为最关键的架构点：〔指 PPT〕**MCP 这一层我不做进后端进程里。**
它是一个**独立的适配器**，stdio 和 http 两种传输都能起，做的事就是**通过 HTTP 去打既有的 `/api/v1` 接口**。
所以权限判定、幂等、库存能不能扣 —— 全部还是后端说了算，**MCP 层不复制任何一条业务规则**。
这条设计的价值是：如果 Agent 绕过 MCP 直接调 HTTP 接口，**它撞上的规则一模一样**。我不是给 AI 开了一扇没锁的后门。
〔补一句〕而且这 9 个工具映射的还是那一份 OpenAPI 契约，所以 Agent 看到的字段名和人在 Web 上看到的字段名是同一批 —— 四端共用契约这件事，到这里是第五个消费者。

**〔05:20 MCP：写链〕**
〔让 Agent 调 nl_plan，"创建进货单 …"〕现在让 Agent 做写操作。
〔指 Agent 复述的那段〕注意我用的是 `nl_plan`，**不是** `nl_command`。这个工具是只读的，可以反复调，它给我的是"将要发生什么"。
〔停〕我为什么单独暴露这个工具，理由很直白：如果 Agent 直接调 `nl_command`，**数据就落库了，人根本看不到中间那一步**。
有了 plan，Agent 就得先把计划摘要和复核意见念给我听。
〔人说"可以"〕我说可以。〔Agent 带 confirmation.token 调 nl_command〕〔切到浏览器，刷新 Web 的进货单列表〕你们看，**这张草稿在 Web 界面上也看得到**，同一条链、同一个库。

**〔06:00 P4：MCP 边界〕**
〔回 PPT〕MCP 这一路的边界我念三条。
一，**9 个工具**，全部是既有接口的映射，没有任何一条"MCP 专属的能力"。
二，Agent 侧的写操作**只建草稿** —— 不审核、不入库、不出货、不作废。想让它往前走一步，得有人在界面上点确认。
三，它同样要带 token、同样受权限码约束。**用一个只读账号连进来，Agent 就只能读。** 你们现在拿 `demo / Demo@12345` 连也一样。

**〔06:30 P5：如实的边界〕**
〔这页一定要念〕四条我不藏。
一，自然语言的**默认解析器是离线关键词规则**。它的优点是稳、可复现、不联网；缺点是只认设计好的写法。我今天这一段是〔A：接了真实大模型 / B：跑的离线规则〕。
二，接大模型需要一把 API Key，那是**我的成本**，不是系统缺的能力 —— 配置入口、连通测试、密钥加密存储、换模型的开关都在页面上。
三，意图是固定枚举，**12 个**，不是"什么都能问"。我唯一放开的自由查询是那条只读 SQL，它有白名单视图、超时、行数上限和关键字拦截。
四，MCP 这个包的 README 里"工具清单"那一节数字比代码少，那是我没同步的旧口径 —— 我已经在录之前把它改成和代码一致了，**这件事我主动讲，比你们自己去数出来好**。

这一段对应可选项 **自然语言操作支持**，申报加 5%；同时任务最后提的"让 AI Agent 直接操作（MCP）"也在这一段里交了。

## 六、常见追问与答法

**Q1：你这不就是关键词匹配吗？换个说法就不认了，凭什么算自然语言支持？**
默认解析器确实是关键词规则，这一点我在视频里自己说了，没有冒充大模型。但请把它和"能力天花板"分开看：
① **架构上是解析器可插拔**——`系统 → 自然语言 → AI 接入` 那一页里"解析方式"就是两个选项：关键词规则（离线）/ 大模型 function calling，另有"复核方式"可以选"规则 + AI 复核"；接口地址、模型名、密钥都在页面上配，配完有 `/nl/settings/test` 当场测连通。
② **为什么我默认用规则**：因为规则解析**确定性、离线可复现**，答辩和演示不会因为网络抖一下就翻车，密钥也不需要挂在演示环境里。这是工程取舍，不是能力缺失。
③ 真正的能力是那条**链**：意图枚举、计划、复核、凭据、执行、审计。这一套跟解析器是谁写的没关系——换成大模型，"写操作要人签字"这条硬约束照样成立，因为它是后端标 `requiresReview`，不是前端自觉。

**Q2：AI 会不会哪天把库存扣错了？你哪一层挡着它？**
三层，而且都不在前端：
① **能力层不给**：写意图只有三个——建进货草稿、建出货草稿、提交单据。**审核、入库、出货、作废四类动作压根没对自然语言开放**，因为那动的是账和货，必须人看着实物做。
② **流程层卡**：写意图后端标 `requiresReview=true`，必须先生成计划给人看，执行时带一个**只有"生成计划"这一步能签发的凭据**（`X-Nl-Plan-Token`）。我特意让"复核"那个接口**不签发凭据**，否则就是给"跳过预览"开了第二条路。缺 token 去执行会拿到 409 并附回那份计划。
③ **复核结论层**：复核意见有三档——不反对 / 要人判断 / 不允许执行。**第三档直接不签发凭据，那就执行不了**。
④ 就算以上都被绕开，**数据库层还有约束兜底**：库存表上 `on_hand_qty >= 0`、`reserved_qty >= 0`、`ck_reserved_le_onhand`（预占不大于实存）。
外加全程审计留痕：谁发起、计划长什么样、执行结果是什么，`/nl/audit` 里都有。
补两处实现细节，因为它们是我判断"这功能能不能真负责"的依据：
① **待确认队列里的状态是后端算的**，规则只有一条——参数不全就是 `BLOCKED`、复核否决就是 `VETOED`、其余才是 `PENDING`。这条规则页面和 MCP 两个入口共用一份，不会出现"网页拦住了、Agent 那边没拦住"。
② **只有 `PENDING` 才带截止时间**，过期是**读取时惰性结转**的（读到超时的就顺手标 `EXPIRED`），不依赖定时任务——不会出现"计划躺了三天，第四天定时任务一跑就自动执行"这种事。
③ 从队列里点执行时，**仍然会按意图重新判一次权限**，并且用的是计划那次的 requestId，所以建单幂等也保住了。能看队列不等于能执行队列里的东西。

**Q3：让 AI 直接写 SQL 查库，这不是把库交给模型了吗？**
不是任意 SQL，是一条**受限只读**语句，限制是硬的：
- **只在白名单视图上执行**：那个 `ai` schema 的视图本身**已经按租户过滤**；
- **写关键字与系统表在入口就被拒**；
- **8 秒超时 + 200 行上限**；
- 只读意图不产生任何业务副作用。
**我接受的风险面是"查得慢、查得杂"，不接受"改错数据"。** 这两类风险的处置方式不一样，所以我把它们分开设计而不是笼统"允许查询"。
为什么要放开这一条：固定工具的参数是写死的，只能表达设计者事先想到的问法。"哪个客户贡献了最多毛利""上周退货率是多少"这种问法没有任何一个预置工具装得下——**加一个工具等于加一种问法，永远追不上用户**。

**Q4：MCP 是不是给 AI 开了一个不受管控的后门？**
恰恰相反，我的设计目标是**让 MCP 什么规则都不拥有**。
`packages/mcp-server` **不做进后端进程**，它是一个独立适配器（stdio、http 两种传输都能起），做的事就是通过 HTTP 去打既有的 `/api/v1/*` 接口。所以：**权限码、幂等键、库存能不能扣，全部由后端判定，MCP 层一条业务规则都不复制。**
可验证的结论是：同一个 token、同一个请求，**用 MCP 打和用 HTTP 直打，撞上的规则一模一样**。拿只读账号 `demo / Demo@12345` 连进来，Agent 就只能读。
写操作我也单独收过：`nl_command` 那一路 **只建草稿**，不审核、不入库、不出货、不作废。
另外我在写意图那条路上加了 `nl_plan` 这个**只读**工具，就是为了让"Agent 要改数据"这件事在人和 Agent 之间也要过一次确认——如果只有 `nl_command`，数据落库了人都不知道。

**Q5：你说 9 个工具，可 README 里写着 6 个，到底几个？**
以代码为准，**9 个**，看 `packages/mcp-server/src/tools.ts` 里的 `TOOL_NAMES`：`system_status`、`dashboard_overview`、`query_inventory`、`list_documents`、`get_document`、`inventory_summary`、`query_master_data`、`nl_command`、`nl_plan`。
README 第一节那个"6 个"是旧口径——`system_status`、`dashboard_overview`、`nl_plan` 是后来加的，我没跟着改文档。这是我自己的文档债，我在视频的"边界"页里主动念了这条，也在录之前把那一行改过来了。**文档说的数字和代码里的数字对不上，是我的错，不是"6 和 9 都行"。**

**Q6：这套自然语言功能跟市面上的"ChatBI"比，你的差异化是什么？**
市面上多数做法是"用自然语言生成图表/报表"，那是**读**的增强。我的差异在两点：
① **写路径也给了，但是带签字的**。不是只让你问数，而是允许"给某供应商建一张进货草稿"，代价是把确认这一步做成流程硬要求（计划、凭据、审计）。这个选择很反直觉——多数产品会选择不开放写，因为出事要负责。
② **它长在同一个权限模型和同一份契约上**。意图背后调的还是那 202 个路径里的接口，用的是同一套权限码；租户隔离也一样生效——`demo` 账号在自然语言里问别人的租户，跟它在界面上点到的结果是一样的。
所以我不想把它讲成"AI 功能"，它是**第五个客户端**：Web、H5、小程序、安卓之外，人和 Agent 各占一个入口。
