**〔01:48 备案〕**
域名这件事在国内有一步绕不过去的：备案。〔滚到页脚〕页脚这个号：粤ICP备2026167520号。
〔新标签打开工信部〕这是备案主管机关的查询入口，不是我自己写的字。我搜一下这个域名，出来的主体和号码能对上。

**〔02:10 终端：服务器〕**
〔ssh / Workbench 登录〕现在进服务器。〔nproc && free -h〕
这台机器是 2 核 2G 的入门规格。〔回车〕你们可以看到内存是很紧的，所以我这套东西的编排特意有一个 `docker-compose.2g.yml` 的小内存档。
〔敲 compose ps〕三个容器全在：PostgreSQL、后端、Web，状态栏全是 healthy。

**〔02:45 nginx 分流〕**
〔ls /etc/nginx/conf.d/〕入口层就这几个文件。〔grep server_name〕三个 server 名，对应三个域名。
这里我讲两个坑，都是踩过才知道的。
第一个，〔指文件名〕文件名前面为什么带 `zz-`？因为 `conf.d` 是按字母序加载，而 nginx 会把**第一个 server 块当默认站点**。我的主页配置叫 `zemworld.conf`，如果新站子排在它前面，用 IP 直接访问的时候就会被新站接管，主页反而打不开。所以新站一律加 `zz-`，让它排在后面。
第二个，〔grep limit_req|actuator|404〕`/actuator`、`/swagger-ui`、`/v3/api-docs` 在公网上直接返回 404 —— 这些是运维接口和接口文档，本机看可以，公网不该看。登录接口我单独挂了一个 `limit_req` 限流，专门挡密码暴力尝试。

**〔03:25 m 域名〕**
〔开 https://m.zemworld.cn〕这是移动版，同一台机器同一个 nginx，按域名给的是另一份静态产物。所以两个站不需要两台服务器，也不需要一个站挂两个域名。

**〔03:45 证书续期〕**
〔acme.sh --list〕证书是用 acme.sh 签的，两个域名都在列。〔指 /etc/nginx/cert/〕签完装到这个目录，nginx 配置里指的就是这两个文件。
〔crontab -l〕cron 里挂着自动续期。〔ls 一下 acme-challenge 那条 location〕顺带一句，配置里 `/.well-known/acme-challenge/` 那一段是给续期用的验证目录，删了它证书就续不上，我自己就差点把它当垃圾清掉。

**〔04:05 备份〕**
〔crontab -l 指备份那行〕每天一次数据库备份。〔ls -lh 备份目录〕这里是按天落的 dump 文件，`pg_dump -Fc` 自定义格式。
我要强调一个细节：脚本导完不是把文件留下就报成功，它会再用 `pg_restore -l` 把这个 dump 解析一遍，解析不出表数据就算这次备份失败。因为"备份文件存在"和"备份真的能恢复"是两件事。
另外，恢复到临时库这件事我演练过：还原到一个临时库，比对进货单、出货单、库存流水、用户这几张表的行数，跟源库一致才算数。

**〔04:35 发布与回滚（核心）〕**
下面这段是我要说的 DevOps 的实底。〔./scripts/backup-db.sh〕发布之前先备份，这是脚本自己的建议，我照着做。
〔./scripts/deploy.sh --tag demo-1031a〕
〔指日志〕现在它做三件事：构建镜像、起容器、然后**等 `/readyz` 这个健康检查**。它不是"命令返回了就叫发布成功"，健康检查不过它默认直接回滚到上一版，不会把线上停在一个坏版本上等我去看。
〔等，若超 60 秒切 PPT 讲健康检查〕
〔浏览器刷新，指版本变化〕这一版上线了。
〔cat .deploy-state〕注意这个文件，它记了 `CURRENT_TAG` 和 `PREVIOUS_TAG` 两个版本。回滚为什么能一条命令，靠的就是这个状态文件，不是靠我记得上一个版本叫什么。
〔./scripts/rollback.sh〕〔等〕〔浏览器刷新〕退回上一版了。
〔补一句边界，一定要说〕有一件事必须说清楚：**镜像回滚不等于数据库回滚**。Flyway 迁移只向前，如果某次发布里带了不兼容的迁移，光回滚镜像是不够的，得先从备份把库恢复回来再回滚。这条我写进运维手册了，这次发布我没动迁移，所以回滚是干净的。
整个过程我手点的就是两条命令，没有登录服务器去改文件、也没有拿 SSH 手敲 docker run。

## 六、常见追问与答法

**Q1：你这算 DevOps 吗？没看到流水线，就是几个 Shell 脚本。**
按"有没有 CI 平台"这条标准，我确实不算，这也是我在视频里主动说明的一点（口径 B）。我落的是 DevOps 里更硬的那部分：**发布这件事不靠人的记性**。具体三条证据：①`deploy.sh` 起完必须等 `/readyz`，健康检查不过**默认自动回滚**，不会把线上停在坏版本上等我发现；②每次部署写 `.deploy-state`，`CURRENT_TAG`/`PREVIOUS_TAG` 都在，回滚是 `rollback.sh` 一条命令而不是"我还记得上一版叫什么"；③每日 `pg_dump` 挂着 cron，且脚本会用 `pg_restore -l` 校验 dump 可解析，不是只看文件在不在。
GitHub Actions 那两个 workflow 文件我承认还没在当前代码上真跑过，远端停在 10-20、本地领先三百多提交。**如果录之前它跑绿了，这段我会改成讲门禁 + 一次真实 push；没绿我就不讲。**

**Q2：2C2G 跑 Spring Boot + PostgreSQL + nginx，压得住吗？你是不是没测过载？**
2C2G 是我明确写在运维手册里的目标规格，不是"凑巧能跑"。为此有几处针对性配置：`docker-compose.2g.yml` 是小内存档；JVM 堆参数按这台机器的余量给，不让它去跟 PG 抢；宿主 nginx 直接发静态产物，Web 容器不重复承担渲染。
至于压力，我给不出"扛住多少人"的承诺 —— 这是课程项目，我没有做容量压测。我能给的是**内存吃紧时的可观测性**：工作台上有"运行状态"面板，它调后端 health，后端把数据库连通性和响应延迟原样报出来；出问题当场就能看见，而不是等用户来反馈。这个边界我如实说。

**Q3：备案你只截了一张查询页，怎么证明网站真的备过而不是刚提交？**
两层：①`xuliu.zemworld.cn` 在工信部备案查询里能查到主体和号码（粤ICP备2026167520号），这是主管机关那边的记录，不是我页面页脚写的字；②一个更硬的间接证据：**如果没备案，阿里云会在 80/443 上直接拦掉解析**，我这个站就打不开。现在它正常出页面，说明接入这一关是过了的。
顺带说一个我在运维里踩到的顺序坑：备案拦截是**先放行、后生效**，所以"当时能打开"不能永久当结论用，可达性结论只在当场有效。这也是为什么我这段视频里是**当场打开**而不是放一张旧截图。

**Q4：HTTPS 只放了个 Let's Encrypt，安全性你是不是就靠一个证书？**
证书只是传输层。这次镜头里能看到的其他三件事：①公网**只开 22、80、443**，后端 8080 和 PG 端口不对外发布，扫不到；②`/actuator`、`/swagger-ui`、`/v3/api-docs` 在入口 nginx 上**直接 404**，运维接口和接口文档不在公网上露出；③`/api/v1/auth/login` 单独挂 `limit_req` 限流，挡的是密码暴力尝试；④密钥只在服务器上的 `.env` 里，不进仓库、不进视频。
另外业务层：演示账号是只读角色，只有 5 个权限码，写操作、审计查询、登录日志、用户管理一律 403 —— 你们现在用 `demo / Demo@12345` 登录就能自己验，这也是我全片都用它演示的原因。

**Q5：回滚只回滚镜像，数据库不滚，那万一发布了不兼容迁移怎么办？**
这正是我在视频里主动念的那条边界：**镜像回滚 ≠ 数据库回滚**，Flyway 只向前。所以流程上写死了两件事：①发布**前**先 `backup-db.sh`（我镜头前也真跑了这一步）；②如果这次发布包含不兼容迁移，运维手册要求先从备份恢复库、再回滚镜像。
M6 之后这次发布我没动迁移，所以镜头里的回滚是干净的。真带了破坏性迁移的版本，我不会用"一条命令回滚"糊过去 —— 那条路要走的是"恢复临时库 + 校验关键表计数"，我演练过这个动作。

**Q6：只有你一台服务器，挂了怎么办？**
单点是事实，我不粉饰。现在能给的兜底是**可重建**而不是**可切换**：①入口层三个 nginx 配置是从服务器 `/etc/nginx/conf.d/` 取回仓库存的，运维手册里写了"换一台机器照着落一遍就能复原入口层"，文件名带 `zz-` 前缀这种细节都记了原因；②数据每天 `pg_dump`，14 天保留；③镜像和代码在仓库里，`.env` 是唯一的私有输入，只有密钥和口令。
真正的多实例 + 负载均衡我没做，运维手册里明确写了"单实例重建期间有几秒 502/503，课程/单店场景可接受，需要零中断应改成多实例滚动" —— 我知道边界在哪，也有改的路径。
