# PPT 统一规范（五段共用）

这套 PPT 不是"给人看的幻灯片"，是**录屏的底板**。所以所有决策都服从一个目标：评审在手机上看 1080p 录像时，字还读得清、UI 还没被挡住。

---

## 一、画布与导出

| 项 | 规定 |
|---|---|
| 比例 | **16:9** |
| 尺寸 | **1920 × 1080**（PowerPoint 幻灯片大小设为"宽屏"，或者 WPS 里设自定义 33.87 × 19.05 cm） |
| 导出 | 逐页导出 **PNG**（备用）+ 演示时用 OBS「窗口捕获」抓演示者视图，**不导成视频** |
| 录屏 | 1920 × 1080 @ 30fps，与 PPT 同尺寸 → 画面不缩、不裁、无黑边 |

为什么必须锁死同一个尺寸：PPT 和实机 UI 会在同一段里来回切。尺寸不一致时剪辑要做缩放或加黑边，字就糊了；1080p 下 24 号的中文已经是可读下限，再经一次缩放就不及格。

---

## 二、配色（直接取系统自己的品牌色，别另发明一套）

来源：`frontend/web/src/styles/theme.css` 的 `--ys-*` 令牌。PPT 用同一组色，评审会看到"幻灯片和系统是同一个东西"。

| 用途 | 名称 | 色值 |
|---|---|---|
| **主色**（标题条、强调、图表主系列） | 黛青 | `#2E5D63` |
| 主色深（hover/次级强调、终端底色） | 黛青·深 | `#24494E` |
| 主色浅（大面积底色、色块） | 黛青·淡 | `#E8EFEE` |
| **标题与正文主色** | 墨黑（带褐调） | `#23201C` |
| 次要文字 | 墨黑·次 | `#4A443C` |
| 说明/脚注文字 | 墨黑·三 | `#6A6255` |
| **页面底** | 暖白 | `#F6F2EA` |
| **卡片底**（内容块） | 瓷白 | `#FFFDFA` |
| 辅助色（第二图表系列、链路图节点） | 雾蓝 | `#7C93A6` |
| 状态色 · 预警（库存预警/待补货） | 陶土 | `#A96436` |
| 状态色 · 正常/已完成 | 苔绿 | `#5C7357` |
| 状态色 · 异常/退货/风险 | 胭脂 | `#A25F6B` |
| 分隔线 | 浅暖灰 | `#E8E0D4` |

卡片底用瓷白 `#FFFDFA` 落在暖白 `#F6F2EA` 页底上，两层"白"拉开微弱层次——这是系统自己的做法（`--ys-cibai` / `--ys-nuanbai`），PPT 照搬即可。**不要用纯白 `#FFFFFF` 当卡片**：录屏里纯白会被压缩算法抹平，还和页面底失去层次。

**禁止**：默认 Office 蓝（`#4472C4`）当主色；红黄绿大撞色；深底满屏白字（深色页只在"章节隔页"用，见下）。

字体：中文 **思源黑体 / Noto Sans SC**（系统 `--ys-font-cn` 首选），**数字与英文标识符 Inter**；代码/命令一律 `Consolas`。PPT 里若装不到思源黑体，退 **微软雅黑**，但**别退宋体**（录屏里宋体笔画会抖）。

## 三、字号（1080p 录屏下限，不许再小）

| 元素 | 字号 | 说明 |
|---|---|---|
| 页面主标题 | **40 pt**，思源黑体 Bold | 隔页 56 pt |
| 页内小标题/卡片标题 | **28 pt** Bold | |
| 要点正文 | **24 pt**，行距 1.4 | **绝对下限 24 pt**。PPT 默认 18 pt 在 1080p 录像里等于看不清 |
| 脚注 / 资料来源 | **18 pt** | 全页最多一行脚注 |
| 代码行 / 命令 | **22 pt** Consolas，每页 ≤ 6 行 | 长命令换行用 `\`，不许横着拖出画面 |
| 表格 | **20 pt**，单元格 ≤ 2 行 | 表格超过 5 行 4 列就拆页或改成图 |

---

## 四、每页信息密度上限（超了就拆页，不要缩字号）

- **一页只有一个论点**，标题写成论点而不是名词（"单机版和云版共用同一套镜像"，而不是"单机版说明"）。
- 每页 **要点 ≤ 3 条**，每条 **≤ 20 字**。
- 每页 **数字 ≤ 4 个**。超过 4 个数字时评审的眼睛会开始漏读——把多余的数字放进口播，不放进页面。
- 每页最多 **1 个视觉主体**（一张截图 / 一张架构图 / 一个图表），不给三宫格拼图。
- **代码页只贴"能证明论点的最小片段"**：≤ 6 行。想展示完整逻辑就画示意图 + 口播讲。
- 一页 **停留 25–60 秒**。低于 20 秒说明这页可以合并，高于 90 秒说明该拆两页。

页面骨架（每页固定，五段共用）：

```
┌────────────────────────────────────────────────────────┐
│ 〔黛青条 · 高 90px〕页标题 40pt 白字          段号/页码 │  ← 顶部条右上：`01 / 09`
│                                                        │
│   正文区（y=90 → y=880）                               │
│   · 要点 ≤3 条                                         │
│   · 1 个视觉主体                                       │
│                                                        │
│ 〔底部安全区 y=940 → 1080：只放页码/来源，不放内容〕     │
└────────────────────────────────────────────────────────┘
```

章节隔页：黛青 `#2E5D63` 满屏底 + 白字 56pt 一句 + 分值角标（`单机版 · 10%`）。**全片只有 5 张隔页**，用来给剪辑留明显接缝。

## 五、头像画中画（PiP）安全区约定 —— 本节是全片统一的硬规则

### 5.1 位置与尺寸

| 项 | 规定 |
|---|---|
| 默认位置 | **左下角**：左边距 24px、下边距 24px |
| 尺寸 | 直径 **200px 圆形**（1080p 下 ≈ 画面宽度 10.4%，再大就喧宾夺主） |
| 描边 | 2px 黛青 `#2E5D63`，外圈 0 阴影（阴影在录像压缩后会脏） |
| 透明度 | **100%，不许半透明**（半透明人头像叠在表格上会变成"脏斑"） |
| 覆盖层 | 头像上沿加一条 4px 高黛青细线，视觉上"压住"内容，避免看起来像画面缺陷 |

PPT 每页的 **左下角 240 × 240px 是"预留空区"**：不放标题、不放要点、不放箭头终点。要点从 x=240 起排版。这条约定必须在做 PPT 之前就定下来，不然九页做完再挪一次成本翻倍。

### 5.2 为什么不能压在右上角（硬性）

**这套系统的右上角是有功能入口的，不是装饰**：`frontend/web/src/layouts/MainLayout.vue` 的 `.header-right` 里，从左到右排着

1. **当前租户切换器**（`tenant-chip`，只有多租户成员才渲染）
2. **深色 / 浅色主题切换**图标按钮
3. **用户菜单 → 退出登录**

头像压在右上角会直接产生三个后果：

- 讲到"多租户"这一段时，画面里看不见租户切换器 —— 评审会以为**没做**，而它恰恰是本系统最能讲的功能之一；
- 切主题、切换租户这些动作是**要用鼠标点的**，点了头像挡住的那块会露出"鼠标消失在头像里"的割裂感；
- 演示中途切错了租户需要退回切换器，被挡住就只能靠键盘盲操作，是一条废镜头。

同理另外三个禁区：
- **左上角**：系统 logo 与面包屑起始位置；
- **正中 1/3 区域**：表格数值、图表主系列都在这；
- **正下方居中 60px**：字幕条的位置，头像压在字幕上等于同时废掉两样。

### 5.3 唯一例外：涉及侧边栏最后一组菜单时，头像临时挪到右下角

Web 端左侧栏从上到下 10 个分组：工作台 / 主数据 / 库存 / 采购 / 销售 / 财务中心 / 报表 / 系统 / 系统工具 / **自然语言**。**最后一组"自然语言"就贴在侧栏底部，正好被左下角的默认头像位压住**。

规则：

- 凡是要点"系统 → 自然语言 → AI 接入 / 待确认队列 / 操作审计"这类菜单时（**主要出现在 05 段，03 段末尾也会点一次**），把头像改到 **右下角**（右边距 24、下边距 24，同样 200px）。
- 改到右下前，先把该页列表的分页器翻到第一页或选一个**数据量小、没有分页条**的页面 —— 右下角第二个冲突点就是表格分页器。
- 同一段里头像**只挪一次**，挪完就别再动，观众对"人在哪"的稳定预期比位置美学重要。
- 在 `ppt/05-…大纲.md` 的对应页已经标了"此页起头像挪右下"。

### 5.4 实机演示（非 PPT）时的头像位

录屏演示 Web UI 时，同样用左下 200px。Web 页面左下角是侧边栏底部，除了"自然语言"分组那一次例外，压到的是侧栏留白与滚动条，代价可接受；比压在右上角（真功能入口）划算得多。

## 六、PPT 与实机演示的切换节奏

每段视频的骨架固定是 **PPT 起 → 实机演示 → PPT 收**，具体：

```
封面页(1) → 本段讲什么(1) → 架构/原理页(2~4) → 【切实机演示】 → 小结页(1) → 结尾页(1)
```

- 切到实机前，用一张"演示路线图"页（列出待会点的 3 步），评审知道自己在看什么，不会在长页面里跟丢鼠标。
- 实机演示期间**不插 PPT**；要解释原理就回 PPT 一页，讲完再切回实机 —— 剪辑时靠黛青隔页做接缝。
- 浏览器操作**每步停顿 1.5 秒**再点下一处，让鼠标轨迹可见；页面滚动用**缓慢拖动滚动条**而不是 Ctrl+Home 一闪而过。
- 演示数据：一律先确认是 `demo / Demo@12345` 登录（右下角/右上角租户 chip 里能看到当前身份），**不出现 admin 口令、不出现真实手机号**。

## 七、封面（每段 1 张，1280 × 720 PNG）

版式固定，只改三处文字：

- 底：暖白 `#F6F2EA`
- 左上：系统名「云裳进销存」+ 一句话定位（墨黑 `#23201C`，28pt）
- 中部：**这一段的主标题**（黛青 `#2E5D63`，44pt Bold）
- 右下：**分值角标**（白字，黛青底圆角块，`单机版 · 10%` / `可选项 · 加分 5%`）
- 左下：`第 1 段 / 共 5 段 · 2026-10-30`

五张封面只有"主标题 + 角标 + 日期"不同，放在文件列表里像一套，评分人一眼扫完五段。

## 八、命名与存放

```
.plan/视频制作/ppt/01-单机版-大纲.md      ← 逐页大纲（页码｜标题｜要点≤3｜视觉素材｜口播提示）
design/ppt/01-单机版.pptx                 ← 实际 PPT 文件（放这里，别堆根目录）
design/ppt/cover/01-单机版系统-10%.jpg    ← 封面导出
```

做 PPT 时**先把五份大纲都过一遍再动手**，因为隔页与小结页有跨段复用（"系统一句话定位"这页五段共用），一次做好五段就省四次工。
