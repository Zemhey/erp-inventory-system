## 二、录制顺序与理由

按 **01 → 04 → 02 → 03 → 05** 录，不按编号顺序剪。理由：

1. **01 单机版最先录。** 它只依赖本机 Docker，不依赖线上、不依赖账号、不依赖任何人的操作，录砸了重录成本最低（一条命令就能回到干净状态：`stop-standalone.ps1 -RemoveData -Yes` 再 `start`）。先用它把手感找回来，顺便把头像位、字幕样式、封面模板一次性定型。
2. **04 PC 端第二个录。** 和 01 一样是本机就能完成的段落，但窗口相关能力（托盘、打印、关闭隐藏）只能在**有交互式桌面的真机会话**里验，无 GPU 的远程会话起不来窗口。趁状态好连着录。
3. **02 云托管第三个录。** 需要 SSH 进服务器、需要等 CI 那一件事有结论（见第五节）。它是全片最容易"说错一句就被追问"的段落，留一个完整白天录。
4. **03 B/S 最后压轴，但要拆两次录。** 它是四端合集，链路最长，其中安卓真机部分依赖"手机上装好 APK"这个前置动作；把它排在 01/02/04 之后，可以复用前面已经调好的开场与字幕模板，只补中段。
5. **05 自然语言排在最后，因为它有一个可选的加分动作**：填一把真实的 DeepSeek Key。填与不填，讲的是同一个分镜，只是效果差别很大。等前面四段录完，如果 Key 到位就录"惊艳版"，没到位就录"stub 版 + 一句诚实说明"，不会卡住整条流水线。

## 四、工具清单

| 用途 | 选什么 | 为什么是它 |
|---|---|---|
| 录屏 | **OBS Studio**（免费） | 唯一原因：它能把"摄像头画中画"作为**独立源**和屏幕一起录，事后还能挪位置；剪映做不到干净的画中画+绿幕。场景固定 3 个：`PPT` / `屏幕+头像` / `手机投屏+头像` |
| PPT 录制 | OBS 里用"窗口捕获"抓演示者视图，不用录整个桌面 | 避免桌面弹出微信/IDE 通知；也不会把第二个显示器的东西带进画面 |
| 剪辑 | **剪映专业版（桌面）** | 中文字幕自动识别准确率够用，导出不加水印，比 Premiere 快得多。本项目不需要调色，需要的是"当天录当天出" |
| 字幕 | 剪映"识别字幕"→ **人工逐条校对** | 系统里全是专有名词（FEFO、tenant_id、ArchUnit、acme.sh、SmartScreen），自动识别一定会错，见第六节 |
| 封面 | PPT 直接导出 PNG（1280×720，用 `ppt/README.md` 的封面页版式） | 不用装 PS，五张封面模板一致，评审在文件列表里一眼扫得完 |
| 头像摄像头 | 优先**手机当摄像头**（Camo / DroidCam，走 USB 不走 Wi-Fi）；没有就用笔记本内置头 | 手机传感器比大多数笔记本摄像头清晰；USB 不会卡顿掉帧 |
| 麦克风 | **有线耳麦**，不用笔记本内置麦 | 内置麦会把键盘声和风扇声一起收进来，剪辑时降噪压不干净会糊掉人声。键盘声靠"少敲键盘、多念已备好的文案"规避 |
| 手机投屏 | **scrcpy**（USB 调试） | 免费、延迟低、能在电脑上直接操作手机，录屏只录一个窗口就够了。不要用国内厂商自带的"多屏协同"，会带进它自己的水印 |
| 终端录制 | Windows Terminal，字号 **16–18**，黛青底（`#24494e`）+ 瓷白字 | 1080p 里终端 12 号字评审在手机上根本看不清，这是最常见的失分点 |
| 浏览器 | Chrome/Edge 隐身窗口 + 缩放 **110%**，隐藏书签栏 | 隐身窗口保证没有你的其他标签页头像/书签入镜；110% 是 1080p 下表格文字的可读下限 |

**本机资源红线**：这台机器 16G 内存，Docker Desktop + Electron + Chrome + IDE 同时开会卡到录出掉帧。录屏前**关掉 IDE 与多余的 Chrome 标签**，录屏时只用一个 OBS + 一个浏览器窗口。

## 五、命名规范

统一格式：

```
序号-主题-系统名-分值-录制日期.mp4
```

五段的确切文件名（直接用，别临场改名）：

```
01-单机版系统-云裳进销存-10%-2026-10-30.mp4
02-云托管上线与运维-云裳进销存-15%-2026-10-31.mp4
03-BS系统四端-云裳进销存-25%-2026-11-01.mp4
04-PC端桌面版-云裳进销存-加分5%-2026-10-30.mp4
05-自然语言与MCP-云裳进销存-加分5%-2026-11-02.mp4
```

为什么这样命名（对应任务.md "要注意命名，让人一看就知道"）：

- **序号在前**：文件名排序就是观看顺序，评审不用猜哪段是第一部。
- **主题写"系统形态"而不是"模块名"**：写"单机版系统"而不是"standalone 演示"，非技术评审也看得懂；写"BS系统四端"，一看就知道这段是必选项 25% 的答卷。
- **分值直接写进文件名**：`-10%-`、`-加分5%-`。评分表是一列一列打分的，文件名带分值等于替评审做了归档，减少"这段到底算哪一项"的争议。可选项两段特意写 **"加分5%"** 而不是 "5%"，避免和必选段的百分比混淆。
- **系统名统一"云裳进销存"**：五段之间、以及和下载页 `https://xuliu.zemworld.cn/dl/` 上的 APK/便携包命名口径一致。
- **日期是录制日期不是提交日期**：万一某段要重录，新文件名只改日期，旧文件留档；对得上"这段是哪天实测的"。

配套文件也统一：

```
01-单机版系统-云裳进销存-10%-2026-10-30.mp4          成品（H.264，1920×1080，30fps）
01-单机版系统-云裳进销存-10%-2026-10-30.jpg          封面，1280×720
01-单机版系统-云裳进销存-10%-2026-10-30-字幕.srt     字幕单独留档，改文案不用重录
```
