## 一、目标与得分点

这段只有一个任务：让评审相信 **PC 端不是把网页存成快捷方式**，也不是"再写一套桌面程序"。

| # | 评审要看到的 | 证据 |
|---|---|---|
| 1 | 它是**一个真的可执行包**，双击就能跑 | 从公网 `/dl/` 下载 `YunshangERP-0.2.2-portable.exe`（80,722,176 字节，Windows 免安装），当场双击起来 |
| 2 | 它的**架构有决策**，不是随手套壳 | 为什么不用 `loadFile()`：SPA 的 history 路由和 `/api` 相对地址在 `file://` 下全废 → 改成**主进程内起本地静态服务 + `/api` 反代**，窗口加载 `http://127.0.0.1:8788/` |
| 3 | 它对**业务代码零侵入** | `app/desktop` 对 `frontend/web` 的改动量是 **0 行**；渲染进程复用 Web 端全部页面，不复制源码、不加业务组件 |
| 4 | 它有**只有桌面能做的事** | 托盘常驻、点 X 不退出、Ctrl+P 打印/ Ctrl+Shift+S 另存 PDF、菜单里的 AI 页面入口 |
| 5 | 它有**工程自证**，不是"我看着能用" | `npm run smoke` 12 项 HTTP 层自测；固定端口 8788 被占用时**响亮失败而不偷偷换端口**（因为 localStorage 按 origin 隔离，端口一换等于换站） |

**这段绝对不要讲的东西**：不要说"离线可用"。断网时**页面壳能打开**是实测过的，但"数据缓存/断网可查"这件事没做，别把它讲成单机版那种离线能力（那是第 01 段的主题）。

## 二、录制前置条件

- [ ] **必须在有交互式桌面的本机录**。远程桌面/云主机/无头会话里 Electron 起不来窗口（`GPU process isn't usable`）。如果只能用那种会话，先试 `DESKTOP_DISABLE_GPU=1`；起不来就别录本段，改录 `npm run serve` + 浏览器（但那就丢了"桌面"这个卖点，不推荐）。
- [ ] **磁盘先看一眼**：这台机器 C、D 盘都紧张。便携包 80 MB，解压后临时目录还要更多。**选一个剩余空间 > 1 GB 的盘做实验目录**，别在桌面解（桌面在 C 盘）。
- [ ] **端口 8788 必须是空的**：残留的桌面实例会占住它，而这个壳遇到 `EADDRINUSE` 是**故意直接失败退出**的（这是设计，不是 bug）。录之前确认：
  ```powershell
  netstat -ano | findstr :8788
  ```
  有输出就先把那个进程关掉。**顺手把这个"失败退出"当成一个镜头素材**：如果你先起一个、再起第二个，第二个窗口报的是可归因的错误而不是悄悄换端口 —— 这是很好的第三论点证据。
- [ ] **录之前把"只有桌面能做"的三件事真的点一遍**（它们此前只在无人值守环境验过对象创建，**交互行为没被人点过**，录这段就是第一次真点）：
  - 点窗口右上角 **X** → 应该**隐藏到托盘**而不是退出；
  - **托盘图标双击/右键 → 恢复窗口**；
  - **Ctrl+P** 打印预览、**Ctrl+Shift+S** 另存为 PDF（会弹保存对话框，需要人点）。
  任何一条点不通，**就把那个镜头从分镜里删掉**，改成口播讲"实现了但交互待补验"——不要在直播式操作里当场翻车，也不要点不通还硬说它好。
- [ ] **打印机不用管**：本机 `getPrintersAsync()` 返回空（没打印机），所以**只录"另存为 PDF"这条路径**，不要承诺真机套打。PDF 这条路是实测过的（`printToPDF` 产出过合法的 `%PDF-1.4` 文件）。
- [ ] **Deep link 不录**：`erp-desktop://` 协议注册需要写 HKCU、需要安装包环境，**从未验过**。这段视频不提它（只在第六节问答里作为边界承认）。
- [ ] **下载与 SmartScreen 预演**：先在浏览器里把 exe 下到一个"干净的 Edge/Chrome 隐身窗口"下（**下载来源标记会影响 SmartScreen 是否弹**），双击看它到底弹不弹。弹了就按分镜里那段话术处理；没弹就**改口播**为"这次没弹是因为我已经在本机跑过这个文件"，别硬演一个不存在的弹窗。
- [ ] **确认包指向的后端**：`config/desktop.config.json` 或构建参数决定后端地址（优先级 **环境变量 > 配置文件 > 内置默认 `http://127.0.0.1:8080`**；线上分发的那版是用 `--api https://xuliu.zemworld.cn` 打的）。录之前确认窗口里登录打得通线上后端，**并且全程只用 `demo / Demo@12345` 只读账号**，别在公网写数据。
- [ ] **准备一张能打印的单据**：打印/存 PDF 要有内容可打。用 `demo` 登录后进 **销售 → 出货单** 打开一张已有单（只读就够）。
- [ ] **smoke 那一条命令能跑**：`cd app/desktop; npm run smoke`，**第 I 项在后端没跑时是 SKIP，不是通过**——录的时候要么把本地后端起起来让它真过，要么就在口播里如实说这一项这次是 SKIP。别把 12/12 说成 12 项全通过。
- [ ] **头像位**：默认左下 200px。Electron 窗口里左下角是侧边栏底部（同样有"自然语言"分组），03:20 那段要点菜单里的 AI 页面入口时，**按 `ppt/README.md` §5.3 把头像临时挪到右下角**，本段只挪这一次。

**〔00:00 P1〕**
大家好，我是"云裳进销存"的唯一开发者。这是系列第四段，申报的是任务里可选项的 **PC 端**，加 5%。

**〔00:15 P2〕**
我先立一个规矩：这一端如果只是"把网页存个快捷方式"，那它不配单独算一端。所以我这段给你们看三件事：**它是一个真的可执行包**；**它的架构是做过决策的**；还有最重要的一条 —— **它对 Web 端业务代码的改动是零行**。

**〔00:42 下载〕**
〔开 https://xuliu.zemworld.cn/dl/〕东西在公网下载区，`YunshangERP-0.2.2-portable.exe`。
〔下载完 右键属性〕**80,722,176 字节**。便携包，免安装 —— 解压就能跑，不写注册表。

**〔01:05 SmartScreen〕**
〔双击 exe → 蓝色弹窗〕这里会弹一个 Windows 的提示："已保护你的电脑"。
**我不回避这个画面，我讲讲它为什么会出现。**
因为这个包**我没有做代码签名**。签名证书是要付费、要走验证流程的，我这是一个课程项目，我没有买。
没签名的后果就是 Windows 不认识这个文件的作者，第一次运行会拦你一下。
〔点 更多信息 → 仍要运行〕处理方式是"更多信息"、然后"仍要运行"。
我要说的是：**这件事我提前告诉你，而不是让你自己撞上以为我发的是毒包。** 正式交付里这一步是买证书，是一个花钱的待办，不是一个技术问题。

**〔01:28 窗口起来〕**
〔窗口打开 → 登录页〕起来了。
〔输 demo / Demo@12345 登录〕这是工作台。
这个窗口里的界面跟你们在浏览器里看到的一模一样 —— **这不是像，这就是同一份东西**：桌面端不复制前端源码、不加任何业务组件、不改一个像素，它加载的就是 Web 端的构建产物。

**〔01:52 本地服务〕**
〔netstat -ano findstr :8788〕〔指 LISTENING〕这里有个在监听 8788 的进程，那是这个壳自己在主进程里起的一个**本地静态服务**。
〔浏览器另开 http://127.0.0.1:8788/〕我用浏览器再开一次这个端口。〔页面出〕行为完全一致，所以壳里没有魔法。

**〔02:10 P3 架构决策〕**
〔回 PPT〕为什么非要自己起一个服务，我讲讲这个决策。
桌面套壳最直觉的做法是 `loadFile('index.html')`，把产物直接读进来。**这条路在这个项目上是死的**，两个原因：
第一，Web 端用的是 history 模式路由，`file://` 下面你去刷新一层子路径，它会去文件系统里找那个目录，结果就是**白屏**。
第二，页面里的接口写的是相对地址 `/api/...`，在 `file://` 下面它会变成 `file:///api/...`，**接口全挂**；而如果我为了它改成绝对地址，那就跨域了 —— **后端是刻意不配 CORS 的**，我不想为了一个壳去动后端。
〔指右边〕我的做法是：主进程里起一个本地静态服务，加一段 `/api` 反向代理，窗口加载 `http://127.0.0.1:8788/`。
这样同源成立、不需要 CORS，history 路由能回落，**结果就是 Web 端和后端一行都不用改**。
〔指右下那行〕这个代理其实就是把我们开发时 vite 那个 proxy，在打包产物上重做了一遍。实现只用了 Node 内置模块。

**〔02:35 端口占用〕**
〔再起一个壳 → 屏幕出现 EADDRINUSE 那段中文提示〕
现在你们看到它报错了。这个端口是**故意固定**的，端口被占的时候它宁可失败退出，也不肯悄悄换一个。

**〔02:52 P4 为什么固定〕**
〔回 PPT〕原因不显然但后果很实际：登录 token、权限快照、当前租户都存在 **localStorage** 里，而 localStorage 是按 **origin** 隔离的，origin 里面包含端口。
端口一随机，每次启动浏览器就认为是"另一个站点"，症状就是**每次都要重新登录、租户选择也丢**。这是个极难归因的 bug，所以我从设计上不给它发生的机会。

**〔03:05 托盘〕**
〔点窗口 X → 窗口消失 → 双击托盘图标 → 窗口回来〕
桌面增量第一件事：我点右上角的 X，**程序没退，它收进托盘了**。〔指托盘图标〕我双击它，窗口回来了。
我说明一下这个镜头的价值：仓库里的说明写的是"托盘对象创建成功"，但**"点了 X 会不会隐藏、双击会不会恢复"这是交互行为，之前在没有人的环境里点不了。今天我现场点给你们看。**

**〔03:28 打印与 PDF〕**
〔销售 → 出货单 → 打开一张〕第二件事，本地打印。〔按 Ctrl+Shift+S〕
〔保存对话框 → 存到桌面 → 打开 PDF〕这是一张出货单的 PDF，是**桌面直接生成的**，不经过任何在线服务。
我加个边界，免得你们自己发现：我这台机器上**没有打印机**，所以真机套打我没验过，我只演"另存为 PDF"这条我实测过的路。

**〔03:52 菜单入口〕**
〔打开应用菜单 / 托盘菜单 → 点 AI 页面入口〕〔跳到 待确认队列〕
第三件事，桌面端的菜单里我放了几个只有桌面才需要的入口 —— 这几个跳转地址是**对齐 Web 端路由表**写的，不是另配一套 URL，不然菜单会跳到一个不存在的页面。
〔顺带〕这块面板在 PC 端以前是会误报故障的，因为壳里只转发了 `/api`，没转发 `/actuator`，"运行状态"就读不到后端。这个我后来补上了。

**〔04:05 smoke〕**
〔cd app/desktop; npm run smoke〕最后给一个自证。
这是桌面壳的 12 项自测，测的是 HTTP 层：静态托管、history 路由回落、`/api` 反代、端口占用要失败、还有那个 preload 暴露面。
〔指第 I 项〕这一项如果你们看到是 SKIP，那是因为本地后端当时没起 —— 它**不算是通过**，我不含糊这个。

**〔04:22 P5 边界〕**
〔回 PPT〕三条边界我念完，别等我讲完你们再问。
一，**没有代码签名**，所以刚才那个蓝屏你们以后每次拿到新版本都可能看到一次。
二，深链协议 `erp-desktop://` **我还没验过** —— 它要写注册表、要安装包环境，所以我今天这段里没有演它。
三，断网的时候壳和页面能打开，**但我没有做离线数据缓存**。离线可查数据那是单机版那条路的事，不在这个包里，我不混着说。

**〔04:40 P6 结尾〕**
这一段收一句：**业务只有一份，桌面只补只有桌面能做的事。**

## 六、常见追问与答法

**Q1：这不就是个 Electron 套壳吗？价值在哪？**
是套壳，但"壳该怎么套"是这次的技术决策，价值在**代价控制**上。
直觉做法 `loadFile()` 在这个项目上会坏在两处：history 路由在 `file://` 下刷新一层子路径会白屏；相对地址 `/api` 会变成 `file:///api` 而接口全挂。修它有两条路：给后端加 CORS、或者构建时往 Web 端注入绝对地址 —— **两条都要动业务侧代码**，而后端是刻意不配 CORS 的。
我选的是第三条：主进程里起本地静态服务 + `/api` 反代，窗口加载 `http://127.0.0.1:8788/`，同源自然成立。结果是**对 `frontend/web` 的改动是 0 行**，`git diff` 是空的。业务代码零污染不是巧合，是那个架构决策换来的。

**Q2：你说"离线能打开壳"，那它算不算单机版？**
不算，我把这条线画得很清楚。桌面壳里**有界面、没有数据库**：断网时窗口能起、页面能出（因为产物在磁盘上），后端不在时它给的是一个**可归因的 502 `DESKTOP_UPSTREAM_UNREACHABLE`**，不是白屏。
"数据也能离线用"是另一条产品路线，那个东西是**单机版**（`infra/standalone`，PostgreSQL + 后端 + Web 三个容器都在本机，数据落在本机 Docker 卷，README 里明确写了运行期不联网）。
而且我在桌面端的说明里写了下一步：离线要做得和单机版**同一个口径**，不要在这端再造一套缓存 —— 两套缓存必然不一致。

**Q3：80 MB 是不是太大了？里面装了什么？**
大头是 Electron 运行时，不是业务代码。整个移动端界面的产物才约 600 KB，前端产物也不大。
所以这 80 MB 花在哪很清楚：Chromium + Node + 图标资源，`electron-builder` 打 portable 格式的固有成本。
**这个体积我认为可以讲清楚，但不该拿去跟浏览器端比。** 真正的对比应该是它和"用户自己装 Java、装 Node、装数据库"比 —— 那条路的体积和麻烦都远大于 80 MB（第 01 段单机版走的就是容器路线，靠 Docker 换环境一致性）。

**Q4：没签名你就不做安装包了吗？用户怎么信任这个 exe？**
两条待办我都承认：①**代码签名**（要花钱、要走证书验证流程，是课程预算外的，所以我选择把它放进"边界"页而不是藏起来）；②**安装包形态**——深链协议 `erp-desktop://` 必须靠安装阶段注册协议才生效，这也是我**今天没演深链**的原因：`setAsDefaultProtocolClient` 要写 HKCU，我目前只保留了 `handleDeepLink` 的映射逻辑，**没跑过**。
现在的分发形态是便携包 + sha256 校验文件（下载区旁边有 `.sha256`），至少能让用户确认"下载没被改过"。信任这一环我靠的是可核查性，不是靠我嘴上说安全。

**Q5：桌面端既然能连线上后端，为什么 Web 和桌面要分开申报两个分？**
因为**它们解决的问题不同**。Web 端解决"任何有浏览器的机器都能用"，桌面端解决四件只有桌面能做的事：托盘常驻、本地打印/存 PDF、深链（待补）、以及一个可交付的可执行文件形态。
申报上我没有拿"页面长得一样"去要两次分：任务.md 里 25% 那一项的必选项是服务端、web 端、小程序、安卓 APP，PC 端在**可选项**那一栏。我按这个表来——B/S 四个必选我在第 3 段交，PC 端单独在第 4 段交。

**Q6：`window.desktop` 暴露了什么？会不会被页面里的代码拿去为所欲为？**
暴露面是我刻意收过的。preload 只挂 **8 个点名方法**，而且我在自测里正面断言了这三件事必须是 false：`window.require`、`window.process`、`window.ipcRenderer`。也就是说渲染进程里没有 Node 能力，只能调那 8 个方法，每个方法背后是一次 IPC 往返。
这条约束还有一层业务侧的：Web 端如果将来想用桌面能力，得按 `window.desktop?.isDesktop` **渐进增强**——那是业务侧改动，我这条泳道刻意没动它，所以同一份前端产物在浏览器里也照样跑。
