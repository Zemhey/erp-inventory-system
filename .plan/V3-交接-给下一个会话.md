## 五、踩过的坑（照抄结论，别重新试）

### 1. 权限码：新模块必须给 ADMIN 补通配符
后端和前端都按权限码过滤。ADMIN 角色现在持有的是**模块通配符**（`pur:*`、`sal:*`、`inv:*`…），**没有 `fin:*`**。
所以 W2 加了 `fin:*` 体系后，必须在 V20 里给 ADMIN 补上，否则 **admin 登录后看不到菜单、接口 403**。
写法参考现有迁移 seed `app_role_permissions(role_id, permission)`，用 `INSERT ... SELECT ... WHERE NOT EXISTS` 幂等。
**更省事的替代**：路由 meta 不写 permission，接口用已有的 `sys:*`。

### 2. 登录链路的新表，`tenant_id` 必须允许为空
W1 把 `sys_login_log.tenant_id` 建成 NOT NULL，但登录时租户还没解析出来 → 整个 `/auth/login` 打成 500。
已补 `V19.1__login_log_tenant_nullable.sql`。

### 3. 有数据库默认值的表，不要用 `SimpleJdbcInsert`
它会按表结构把**所有列**都写进 INSERT 的列清单，没赋值的列一律绑 `null`，
**把列上的 `DEFAULT now()` 顶掉** → not-null 冲突。改成显式列清单。

### 4. 跨表通用 SQL 必须先核对真实列名
W1 的"最近单据"用一套通用列名套所有单据表，但 `inventory_transfers` 的单号叫 `transfer_no`，
而且**没有** `total_qty` / `total_amount` / `warehouse_id` → 工作台 500。
已改成 `DashboardRepository.DocSource` record，按单据类型声明真实列名。

### 5. 迁移补丁用小数版本号
已应用的迁移**改内容会被 Flyway 校验拒绝**（checksum 不符）。
补丁用 `V19.1`（19 < 19.1 < 20），这样后面 V20/V21/V22 到达时不会触发 out-of-order 报错。

### 6. 本机环境怪癖
- **带斜杠的 git 分支名会被静默丢弃**：`git branch feat/xxx` 退出码 0、无报错，但 ref 根本没建，
  `git worktree add -b feat/xxx` 因此报 `fatal: invalid reference`。→ 只能用无斜杠名（`v3-2-finance`）
- `wmic` 已从系统移除，查内存用 `Get-CimInstance Win32_OperatingSystem`
- `frontend/web/node_modules` 的 esbuild 曾因目录被打上 `Low Mandatory Level` 完整性标签而无法执行
  （报 `The service was stopped`，没有任何错误输出）。已用管理员 `icacls /setintegritylevel "(OI)(CI)M" /t` 修好。
  **如果又出现 esbuild 起不来，先查完整性标签，不要怀疑 Node 版本或中文路径。**
