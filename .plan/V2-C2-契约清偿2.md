### 2.1 X-Request-Id 判据（不猜，以扫描结果为凭）

`scripts/contract-check.py` 会把「契约声明」与「实现是否 `@RequestHeader("X-Request-Id")`」双向核对。
本批 15 个写操作（13 POST + 2 PUT）里，6 个消费（#2 #8 #9 #18 #20 #24）→ 声明 `#/components/parameters/RequestId`；
其余 9 个（#4~#7 #11 #13 #14 #19 #28）**不消费** → 不声明，并在 `description` 写明幂等由谁保证：

- #4~#7：幂等由**状态机 + version 条件 UPDATE** 保证（重复提交同一转移第二次 → `SAL_QUOTE_STATUS_ILLEGAL`）
- #11 #14：`code` 唯一约束 / `enabled` 标志本身幂等
- #19：扫码是**累加**语义（`picked_qty += qty`），无幂等键；越界由 `SAL_SHIPMENT_OVER_PICK` 拦住

## 3. 需要写清的语义（不写空壳 schema）

- **#8 报价转化**：仅 APPROVED 且未过期可转；同键重放返回首次订单，新键再转 → 409；
  信用超额/库存不足整单回滚，报价单保持 APPROVED；订单业务日期用**转化当天**（避开已锁账的报价月）；
  内部订单幂等键是 `<requestId>:Q<quoteId>`。
- **#9 auto-split**：按 `warehouses.priority DESC` 逐仓吃量，单仓足够只产生一个分配；
  响应 `lines[].allocations = [{warehouseId, qty}]`（**无** reservations 字段，预占 id 在 `reservationIds`）；
  套装行按「每仓可用套装 = min(组件可用 ÷ 配比)」成套分配。
- **#15 套装可用量**：`availableQty = min(floor(component.availableQty ÷ component.ratioQty))`；
  `warehouseId` 省略 = 全仓汇总口径；套装无自身库存行（INV-16）；空组件返回 0。
- **#18/#20 发货**：计划按 ACTIVE 预占所在仓拆多张发货单；`confirm` 要求整张 PICKED；
  出库 + 消费预占 + 累计已出量 + 登记应收同事务；同键重放返回首次结果。
- **#21~#26 应收/收款守恒**：`balance = shipped − returned − received`；
  `Σ allocations` 必须**精确等于** `amount` → 否则 `SAL_RECEIPT_UNBALANCED`(409)；
  单行核销超余额 → `SAL_RECEIPT_OVER_ALLOCATED`(409)（含并发条件 UPDATE 失败）；
  应收不存在/跨客户 → `SAL_RECEIVABLE_NOT_FOUND`(**404**，申请稿误记 409)；
  部分核销合法（`amount < balance` 时状态保持 OPEN）。
- **#27/#28 信用**：`exposureAmount = 应收未收余额 + 未出货订单金额`；
  `creditLimit = 0` → 不设限 → `availableCredit = -1`（哨兵值，不是负额度）；
  超限额的错误码是 `SAL_CREDIT_LIMIT_EXCEEDED`(409)，发生在**建单/转化**时而非本端点，
  两端点都写交叉引用。账期 = `creditDays`（0 表示现结）。
