## 0. 一句话目标

**这个系统的后端已经有 36 个控制器、175 个接口，但前端只有 23 个业务页和 31 条平铺菜单，打开像个小工具。**
你这一批负责把"门面"做出来：**菜单分 8 组、工作台有图表、待办中心、单据详情抽屉、全局搜索，再补组织架构/系统参数/单号规则/登录日志。**

做完之后，用户打开系统第一眼就应该像"大型商业 ERP"，而不是"进销存工具"。

## 3. 任务清单

### FR-V3-01 菜单 8 组重构（**先做这条，别人等你**）

**为什么先做**：W2/W3/W4 三条泳道同时在开工，他们都要加路由。你先把路由拆成"按模块一个文件 + 自动装载"，再把 8 个分组全部注册好，**后面三条泳道就零冲突**。

要求：
1. 新建 `src/router/modules/` 目录，把现有 31 条路由按模块拆成 `mdm.ts` / `inv.ts` / `pur.ts` / `sal.ts` / `rma.ts` / `set.ts` / `cst.ts` / `aps.ts` / `sys.ts` / `iam.ts` / `rpt.ts` / `fin.ts`（`fin.ts` 先建空数组）。
2. `index.ts` 用 **`import.meta.glob('./modules/*.ts', { eager: true })`** 自动收集，**不要再手动 import 每个模块** —— 这是让别人的新文件自动生效的关键。
3. 每条路由 `meta` 增加 `group` 字段，取值：`workbench | masterdata | purchase | sales | inventory | finance | report | system`。
4. 新建 `src/layouts/menuGroups.ts`，**预先注册全部 8 个组**（含 `finance`，即使现在是空的），组顺序与计划书 §9 一致。
5. `MainLayout.vue` 改为读 `menuGroups`，按 `group` 归组；保留 `flat` 能力（单页组不显示二级）。

**验收**：登录后左侧是 8 个分组，展开顺序为 工作台→主数据→采购→销售→库存→财务→报表→系统；财务组暂时为空不报错。

### FR-V3-02 工作台重做

现在是 `src/views/DashboardView.vue`，内容单薄。重做成：

- **8 个 KPI 卡**：今日销售额 / 今日订单数 / 库存总值 / 库存 SKU 数 / 应收未收 / 应付未付 / 待审单据 / 库存预警数
- **4 张图表**（引入 `echarts` + `vue-echarts`，**按需引入**，别全量 import）：
  1. 近 30 天出入库趋势（双折线）
  2. 库存按仓库分布（饼图）
  3. 应收账龄（柱状：0-30/31-60/61-90/90+）
  4. 本月热销 TOP10（横向条形）
- **待办列表**：待我审批（取 APS 模块）+ 库存预警
- **最近单据**：最近 10 条进货单/出货单，点击打开详情抽屉

**后端**：新增 `GET /api/v1/dashboard/summary`，一次返回上述所有数据（不要前端打 8 个接口）。
放在新包 `com.erp.rpt.api.DashboardController` 或复用 `rpt`，自己定，但**不要新建模块目录**避免架构测试失败。

**验收**：工作台首屏 2 秒内有数；4 张图有数据；点最近单据能开抽屉。

### FR-V3-03 待办中心

新页 `src/views/workbench/TodoCenterView.vue`，四个 Tab：
1. **待我审批** —— 复用 APS 现有查询
2. **库存预警** —— 安全库存以下的 SKU（W3 会建预警表，你先用"库存 < 安全库存"临时查询，字段若不存在就用固定阈值 10）
3. **逾期应收** —— 应收单 `due_date < today` 且未结清
4. **异常单据** —— 长时间停在中间状态（如草稿超 3 天）

**后端**：新增 `GET /api/v1/todos?type=approval|stock|receivable|abnormal`，统一返回 `{type, count, items[]}`。

**验收**：4 个 Tab 都能出数；点条目能跳到对应单据。

### FR-V3-04 单据详情统一抽屉

抽 `src/components/DocumentDrawer.vue`，props：`{ type, id, visible }`。
结构：头部（单号/状态/日期/往来单位）→ 行明细表 → 状态时间轴 → 关联单据（原单/红冲单/收付款）。

先接入 4 种单据：进货单、出货单、退货单、调拨单。其余单据后续接入。

**验收**：4 种单据从列表点行都能开抽屉，内容与数据库一致。

### FR-V3-05 全局搜索

顶栏一个输入框，输入后弹层显示分组结果：单据号 / 商品 / 客户 / 供应商。
**后端**：`GET /api/v1/search?q=xxx&limit=20`，每组最多 5 条，返回 `{group, items:[{id, code, name, type, url}]}`。
**验收**：输单号能直接跳到单据详情；输商品名能跳到商品页。

### FR-V3-23 组织架构

新表：
```sql
sys_department(id, tenant_id, parent_id, code, name, sort_no, leader_user_id, enabled, ...)
sys_position(id, tenant_id, code, name, level, enabled, ...)
```
`app_users` 加列 `department_id` / `position_id`（**加列不加表**）。
页面：左侧部门树 + 右侧详情/岗位列表，支持拖拽排序可省。
**验收**：能建三级部门树；用户能挂到部门。

### FR-V3-24 系统参数

新表 `sys_config(id, tenant_id, config_group, config_key, config_value, value_type, remark, ...)`。
按组展示：`document`（单据）/ `inventory`（库存）/ `finance`（财务）/ `notice`（通知）。
页面：左侧组、右侧键值表格，可编辑。
**验收**：改一个参数能保存；刷新后仍在。

### FR-V3-25 单号规则

新表 `sys_number_rule(id, tenant_id, doc_type, prefix, date_pattern, seq_length, current_seq, reset_cycle, ...)`。
页面：规则列表 + 实时预览（如 `PO20261025-0001`）。
**改造**：现有单号生成逻辑改为读规则；**必须保留 fallback**（规则不存在时用旧逻辑，避免历史单据生成失败）。
**验收**：改前缀后新建单据单号跟着变；并发下序号不重复（用数据库序列或 `SELECT FOR UPDATE`）。

### FR-V3-29 登录日志 / 在线用户

新表 `sys_login_log(id, tenant_id, user_id, username, ip, user_agent, login_at, success, fail_reason, ...)`。
在 `AuthController` 登录成功/失败处写入。
页面：登录日志列表（可按人/时间/结果筛）+ 在线用户（用 token 有效期粗算即可，不做实时会话存储）。
**验收**：登录一次能看到记录；密码错误也记录并标红。

## 4. 技术约束

- **包结构**：`com.erp.<module>/{api,application,repository,domain}`，沿用现有，不要新架构。
- **迁移**：`V19__v3_skeleton.sql`，一个文件；新表**全部带 `tenant_id`**，并加入 `shared/tenant/TenantTables.java` 的 `ALL` 集合（不然租户隔离测试会漏）。
- **契约**：新端点同步写 `packages/api-contract/openapi.yaml`。**只追加你自己的 path，不要改动别人已有的节点，不要重排**（4 条泳道并行，重排必冲突）。
- **错误码**：追加到 `ErrorCode.java` 末尾，注意**最后一条带分号，前面的逗号**。
- **权限码**：新增 `org:read` / `org:write` / `sys:config` / `sys:numberrule`，写进角色初始化数据。
