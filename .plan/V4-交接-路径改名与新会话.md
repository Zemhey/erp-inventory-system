## 一、发生了什么

主仓库路径从 `D:\MajorCacheFolder\Company system\自选` 改成 **`D:\MajorCacheFolder\CompanySystem\erp`**
（去掉空格和中文，根因：中文路径让 Gradle/PowerShell 反复出事，Docker Desktop 重启后 Windows 还把
`2904-3003` 整段动态保留、3000 端口绑不上）。

改名本身要在资源管理器里做，**必须在停掉后端/前端之后**，否则目录被句柄占着改不动。

## 二、新会话的第一件事：跑修复脚本

```
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\erp-rename-repair.ps1"
```

它做四件事（写它是为了让动作可重放、可核对，而不是靠手敲）：

1. `git worktree repair D:\erp-v3-1..4 D:\erp-v4-1..4` —— 这 8 个泳道工作树的 `.git` 里硬写了旧绝对路径，不修就全成"不是 git 仓库"。
2. 重建 `D:\erp-build` 联接（指向新主路径）+ 8 个泳道的 `frontend/web/node_modules` 联接。
   **联接只能用 `[System.IO.Directory]::Delete($path,$false)` 删**，递归删会把目标里的真实文件一起带走。
3. 自检 `git log` / `git status`。
4. 打印起服务命令。

脚本对"目标是真实目录 / 不是 Junction"的情况会跳过而不是覆盖，所以重复跑安全。

## 六、这个项目反复踩的坑（新会话请当硬约束）

- **改任何 SQL 前先实测列名**。已四次中招且编译期全都无感：`purchase_order_lines` 的 FK 是 `order_id`
  不是 `purchase_order_id`；`inventory_transfers` 没有 `total_qty`/`total_amount`；`transfer_lines` 只有
  `unit_cost_amount`；`skus.max_level = 0` 是"未设上限"的哨兵值（`ck_sku_level_order`）。
- **门禁必须注入漂移证明它会红**。字段级门禁自带 `--selftest`（四类漂移注入）；它曾经"红 98 条"里
  有 42 条是检查器按方法名索引 builder 造成的误匹配（记录访问器 `l.summary()` 撞
  `DashboardService.summary()`），也有 24 条是 main 上早就存在的悬空 `$ref` —— **分不清来源就会去改错东西**。
- **并行泳道必须从 main HEAD 切并且验基线**。上一批三条道全都切在 W1 合并点之前，缺 V19 和 4 个页面，
  判据不要读文档，用 `git merge-base --is-ancestor <基线> main` + 查一个只有新版才有的文件在不在。
- **口径**：销售/采购/报表金额单位是**分**，`com.erp.fin` 是**元**；折扣是万分比（9000 = 9 折）。
- 跑 `gradlew test` 前先 `clean`，否则陈旧 test worker 会报 `ClassNotFoundException` 让你以为测试挂了。
- PowerShell 5.1 会把无 BOM 的 UTF-8 脚本按 GBK 读 —— **别在 .ps1 里写含中文的路径**；Windows 原生
  python 看不见 MSYS 的 `/tmp`，临时文件用 `C:/Users/Administrator/AppData/Local/Temp`。
