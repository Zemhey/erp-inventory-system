## 1. 交付一：`scripts/preflight.mjs` —— 出包前置检查

### 1.1 查什么（按平台）

| 平台 | 检查项 | 判级 |
|---|---|---|
| 全端 | `VITE_API_BASE_URL` 是否设置 / 是否相对路径 / 是否合法 URL / 是否仍是占位符 | ✖（非 H5）；H5 相对路径是 ℹ（有代理） |
| 全端 | 协议：`http` 明文 | ✖，加 `--allow-http` 且是内网 IP 段时降为 ⚠（真机联调场景） |
| mp-weixin | `appid` 空 / `touristappid` / 格式不像 `wx+16hex` | ✖ 三种分开报，措辞不同 |
| mp-weixin | `setting.urlCheck = false` | ⚠（说清"开发者工具能跑 ≠ 真机能跑"） |
| mp-weixin | 隐私指引申报扫码 | ℹ（本地查不了，指向后台） |
| app | 顶层 DCloud `appid` 格式 ✖ / 账号归属 ⚠ | 见输出 |
| app | `packagename` 空 ✖ / 格式 ✖ / 看着像占位值 ⚖ / 合法 ℹ | 四态分开 |
| app | `versionCode` 是否正整数 ✖、`versionName` 是否 x.y.z ⚠ | |
| app | `icons` 未配置 ⚠（**明确写"能出包，但是 HBuilderX 的默认图标"**）；已配置但文件不存在 ✖ | |
| app | **CAMERA 权限** —— 自己去 grep `src/pages/**` 里的 `uni.scanCode` / `<camera>` / `createCameraContext`，用量与权限对账 | 缺则 ✖ |
| app | `ios: {}`、`sdkConfigs: {}` | ℹ（本次不出 iOS，空是符合现状的） |
| h5 | 路由模式等 | 全 ℹ，**当前 exit 0** |

输出每条固定四行：**缺什么 → 后果 → 在哪（文件:行 → 字段路径）→ 怎么改 + 示例命令**。
行号是解析 JSONC 时记录的字节偏移反查出来的，改了 manifest 不会错位。

### 1.2 关键取舍：默认 fail，但留逃生口

`prebuild:mp-weixin` / `prebuild:app` / `prebuild:h5` 会先跑 preflight，**有 ✖ 就 exit 1，构建直接被拦**。
逃生口三档（都实测过）：

```bash
npm run build:mp-weixin:force        # = preflight --warn-only --allow-http && uni build（跨平台，Windows cmd 也能跑）
PREFLIGHT_MODE=warn npm run build:app    # POSIX shell 等价
ERP_SKIP_PREFLIGHT=1 npm run build:app   # 完全跳过（不建议）
node scripts/preflight.mjs app --allow-http --warn-only   # 内网真机联调强行出包
```

取舍说明：`--warn-only` **不减少任何检查、不删任何输出**，只把 ✖ 降级为 ⚠ 并以 0 退出——
所以它不是"永远绿的检查"，红字照样糊一脸；而 `build:*` 默认变红是有意的（配置没齐就别怪构建放行），
README §4.6 与 preflight 自己的结尾都直接给出强行出包的那条命令。

### 1.3 只用 Node 内置模块

`node_modules` 是指向主构建区的 junction，不能 `npm install`。所以 preflight / set-appid / make-icons
只用 `node:fs`、`node:path`、`node:zlib`、`node:url`、`process`；JSONC 解析、`.env` 解析、PNG
解码/编码/CRC32 全自己写（`scripts/jsonc.mjs` 是三者共用的定点读写库）。

## 2. 交付二：`scripts/set-appid.mjs` —— 一条命令写正式 appid

**要求：保留注释与键顺序。** 所以不做 `JSON.parse` + `JSON.stringify` 回写（那会把注释、空行、
键序全抹掉，diff 变成整文件重写）。实现：解析 JSONC 时记录每个 value token 的 `[start,end)` 偏移，
写回时只 splice 那一小段字节，其余逐字节不动。工具链侧确认安全：`@dcloudio/uni-cli-shared/dist/json/json.js`
用 `jsonc-parser` 解析 manifest，注释是被容忍的（实测带注释的 manifest 三端构建全通过）。

三个目标：`mp-weixin`（默认）/ `--target dcloud`（顶层 DCloud appid）/ `--target packagename`，
带格式校验（`wx+16hex`、`__UNI__+`、Android 反域名）、`--show`、`--dry-run`、`--force`。

### 2.1 实测（假 appid —— **这只是验脚本，不是验发布**）

```
$ node scripts/set-appid.mjs wxBAD
✖ 格式不符："wxBAD"
  要求：微信小程序 AppID（/^wx[0-9a-f]{16}$/）
  从哪拿：小程序后台 → 开发管理 → 开发设置 → AppID（wx + 16 位小写十六进制，整段复制别手敲）
  确实要写非规范值（演练/占位）就加 --force
exit=1

$ node scripts/set-appid.mjs wx0a1b2c3d4e5f6071
▍微信小程序 AppID 写入
  文件：src/manifest.json（第 46 行，字段 mp-weixin.appid）
  "touristappid" → "wx0a1b2c3d4e5f6071"
  除这一处 value 外，注释/键顺序/缩进逐字节不变
exit=0

$ git --no-pager diff -- src/manifest.json | grep -E "^[-+].*appid"
-    "appid": "touristappid",
+    "appid": "wx0a1b2c3d4e5f6071",          ← 整个文件只有这一行 value 变了
```

然后 `node scripts/set-appid.mjs touristappid --force` **还原**成游客号。
仓库最终状态仍是 `touristappid` —— 故意的：留一个格式合法的假号会让 preflight 变绿、
让人以为 appid 已配好，比"明显的游客号 + 一条红的检查"更坏。

### 3.2 CAMERA 权限的判定依据（读代码，不猜页面名）

`grep uni.scanCode src/pages/**` 命中 3 处，全部是**主路径**，手输是降级：

| 页面 | 用法 |
|---|---|
| `src/pages/shipments/detail.vue:140` | `uni.scanCode({ scanType: ['barCode','qrCode'] })`，成功后 `autoFocusByBarcode` 自动切焦点行 |
| `src/pages/purchase/scan-receive.vue:167` | 同上，扫码结果 `resolveLine(code)` 定位单据行 |
| `src/pages/stocktakes/scan.vue:258` | 同上，扫条码建盘点单 |

三处结构一致：`#ifdef H5` 直接 `enterManual(...)` 降级；`#ifndef H5` 调 `uni.scanCode`，
`fail` 回调里 `enterManual('未能调起摄像头（…），已切为条码手录。')`。
页面里那个条码输入框（`placeholder="扫码枪可直接打入，也可手输"`）是**降级 UI，不是主交互**。
→ 结论：安卓真机要 `android.permission.CAMERA`，否则扫码键点了只会掉进手录，PDA 场景等于废掉。
（`<camera>` 组件与 `createCameraContext` 全仓库 0 命中，所以不需要别的相机相关配置。）
