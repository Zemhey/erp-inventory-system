## 3. 各泳道范围与硬验收

### B1 租户 UI（`feat/tnt-ui`）

**目标**：让"多租户"在界面上可见、可管理、可验证，同时不削弱 V2-7 的隔离不变量。

- 顶栏显示当前租户（编码/名称）；租户切换只在**该用户确实是多个租户成员**时出现。
- 租户管理页：列表 / 启用 / 停用（平台级元数据），只有平台租户管理员可见；普通租户管理员看不到、也调不通。
- 登录链路：登录响应与 `/auth/me` 带 `tenantId/tenantCode/tenantName`（或等价字段），刷新后仍能恢复；切换租户必须重新签发 JWT（`tid` 随新 token 变化），禁止前端只改显示。
- 后端：如现有 `tenants` 表不足，V17 增加 `app_user_tenants`（用户×租户成员）与平台租户管理员角色/权限；`app_users.tenant_id` 仍是"主租户"，不得删除。租户成员关系必须由数据库约束保证唯一。
- **隔离红线**：V2-7 的 135 格跨租户矩阵必须保持全绿；平台租户管理员只能管理 `tenants` 元数据，**不能读取任何租户的业务数据**。新增"跨租户切换后业务数据仍 404"的用例，正对照为同租户 200。
- 前端：`MainLayout` 顶栏、登录页租户选择（如采用登录时选租户）、`/tenants` 页面、路由与菜单权限；`npm run check` 项数只增不减。
- 契约：作为第一阶段 owner，修改 `openapi.yaml` **仅限** `/tenants`、`/auth/login`、`/auth/me`、`/auth/switch-tenant` 相关路径与 schema；不改 MDM/报表。
- 验收：全量 `check` 绿；`contract-check.py` / `schema-field-check.py` 0；前端 build/check；Web E2E 新增"租户可见 + 切换 + 无权限不可见 + 跨租户 404"至少 3 条，连续两遍。

### B2 主数据字段（`feat/mdm-fields`）

**目标**：补齐"客户收货地址、仓库库位、商品规格属性"三块真实字段与界面，不建孤岛表。

- 客户收货地址：一对多；默认地址唯一；停用/删除不破坏历史单据（历史单据保留快照或外键限制需写明）。
- 仓库库位：库位属于仓库；库位容量/状态；**库位合计 == 仓库合计**的守恒断言（按 SKU/批次维度或明确定义的口径），并提供对账端点/测试。
- 商品规格属性：颜色/尺码之外的扩展属性（键值或结构化列），不破坏 SKU 矩阵生成与唯一约束。
- 迁移：`V18__*.sql`；必须可回滚、存量库可平滑升级；唯一约束（如 `(tenant_id, customer_id, address_key)`、`(tenant_id, warehouse_id, location_code)`）在库层成立。
- 前端：客户地址维护、仓库库位维护、商品规格属性编辑；列表/表单/空态/错误态齐全。
- 契约：**B1 合并前禁止改 `openapi.yaml`**。先把精确的路径/字段/边界写进 `.plan/B2-契约申请.md`；B1 合并后由指挥侧发"接棒"消息，B2 再 merge main、落契约、跑双门禁并提交。
- 验收：全量 `check` 绿（接棒后）；契约双门禁 0；前端 build/check；E2E 至少覆盖地址默认唯一、库位合计守恒、规格属性影响 SKU 查询三条。

## 5. 合并顺序与门禁

**顺序：B1 → B2 → B3 → B4（B4 随最终合并）。禁止连合两条再验。**

每合一条，指挥侧必须：

1. 在**全新/干净**的 ASCII 联接工作树跑 `clean check --no-daemon --offline`，记录 tests / failures / errors / skipped、JaCoCo 原值（行/分支分子分母）、耗时；

3. 受影响前端 `npm run build` + `npm run check`（`TEMP/TMP=frontend/web/.tmp`）；
4. 受影响 E2E（Web 或 H5）连续两遍，teardown 前缀残留 0、业务表回基线；
5. `git status --short` 空；`index/` 重新生成并 `--check` 通过（主工作区唯一写者）；
6. 合并提交写清 merge 来源、用例增量、迁移号、契约增量、未解风险。

**红灯处理**：不回滚成"跳过用例/删断言/降门限"；先定位是代码、测试、环境还是契约，再修。跨租户 404、守恒、幂等三类不变量不允许后补或豁免。
