## 2. 页面范围：对照 Web 十页给优先级与裁剪

> **裁剪原则**（来自 ADR-0004 的后果）：复杂录入、大表格、批量操作留在 Web；
> 移动端只做"站在仓库/门店里一只手能完成"的事 —— 查库存、看流水、收货、发货、看板。
> 每个页面先做**只读/单动作**版本，不在移动端复刻 Web 的多行编辑器。

| # | Web 页面 | 移动端页面 | 优先级 | 本批 | 裁剪说明 |
|---|---|---|---|---|---|
| — | 登录 | 登录 | P0 | ✅ | 复用同一套 `/auth/login`；无图形验证码/记住我 |
| — | 工作台 | 工作台（简版） | P0 | ✅ | 只保留：库存总量、库存行数、账实一致性、最近 5 条流水、快捷入口；不做进货/出货单量（需 `pur:read`/`sal:read`，且下一批才有列表页） |
| 1 | 库存查询 | 库存查询 | P0 | ✅ | 余额 + 流水分页完整保留；提供仓库筛选、仅看可用、批次筛选、单据号反查；不做导出 |
| 2 | 出货单 | 出货单（列表 / 详情 / 出货） | P1 | ⬜ | 建单留在 Web（多行 + 折扣）；移动端只做已存在单据的查看与"确认出货" |
| 3 | 进货单 | 进货单（列表 / 详情 / 入库） | P1 | ⬜ | 建单留在 Web；移动端做收货场景（分批入库、批次/效期录入） |
| 4 | 退货单 | 退货单（列表 / 详情 / 入库） | P2 | ⬜ | 建单需要选原出货行，屏幕小易错，建议仍在 Web；移动端可做审核与入库 |

| 6 | 供应商 | — | P3 | ⬜ | 桌面维护型 CRUD，移动端不复刻 |

| 8 | 仓库 | — | P3 | ⬜ | 同上；移动端只在筛选器里用到仓库列表 |

**为什么 P0 是这三页**：
1. 登录是唯一入口，必须先打通 token/存储/401 三件事；
2. 工作台证明"移动端真的在读后端数据"，而不是静态欢迎页；
3. 库存查询是移动端最高频场景（仓库现场扫码/查货的前置），余额三量与流水分页能覆盖
   `FR-INV-01/02` 的移动端展示，也为下一批出货/进货的单据明细提供语义基础。

**本批明确不做的移动端能力**：扫码（需相机权限与条码格式约定）、离线缓存、消息推送、
生物识别登录、多语言、主题切换。

### 3.3 API 客户端（对齐 Web `client.ts`）

用 `uni.request` 包一层 Promise，**不引 axios**（小程序端没有 XHR，axios 适配器会额外引入风险）。

| 约定 | 实现 |
|---|---|
| baseURL | 默认 `/api/v1`（H5 走 Vite 代理）；小程序/Android 用 `VITE_API_BASE_URL` 覆盖成绝对地址 |
| token | 每次请求从 storage 读 `erp.token`，注入 `Authorization: Bearer <token>` |
| 幂等键 | 仅 `POST/PUT/PATCH/DELETE` 注入 `X-Request-Id`；GET 不加（与 Web 一致） |
| 拆包 | 2xx 且 `code === 'OK'` 时返回 `data`；分页返回 `{items,total,page,size}` |
| 401 | 清 token；**登录页不跳转**（401 是"账号或密码错误"的业务结果）；其它页 `reLaunch` 登录页并提示过期 |
| 403/423/5xx | 优先展示后端 `message`；5xx 附 traceId；页面同时保留内联错误态 |
| 网络失败 | 明确提示"检查后端 8082 是否启动"，不要伪造成业务错误 |
| 配置未就绪 | 小程序端 base 仍是相对路径时，直接抛出可读错误（避免所有请求静默 404） |

**金额**：接口中的 `*Amount` 一律整数分；`fenToYuan()` 只用于展示，`yuanToFen()` 只用于未来表单提交。
库存页唯一用到金额的是流水的 `unitCostAmount`（可能为 null，显示 `-`）。

### 3.4 登录态与路由守卫

uni-app **没有 vue-router 的全局 `beforeEach`**。采用双保险：

1. `uni.addInterceptor('navigateTo' / 'redirectTo' / 'switchTab')`：无 token 且目标不是登录页时，
   `reLaunch` 到登录页并取消本次导航；
2. 每个受保护页面 `onShow()` 调 `ensureLoggedIn()`：覆盖"tab 切换、H5 直接改 hash、小程序冷启动"
   等拦截器可能漏掉的入口。

登录态存 `uni.setStorageSync`（H5 映射 localStorage，小程序映射本地缓存），持久化三项：
`erp.token`、`erp.permissions`、`erp.user`。权限只用于按钮/页面显隐，**不是安全边界**（后端仍会 403）。

### 3.5 路由与 tabBar

- `pages/login/login` 独立；`pages/dashboard/dashboard`、`pages/inventory/inventory` 是 tabBar 两页；
- 登录成功用 `uni.switchTab` 进工作台；登出用 `uni.reLaunch` 回登录页（`reLaunch` 可跳非 tab 页）；
- tabBar 只用文字、不放图标（首版避免二进制资源；下一批可补 81×81 图标）；
- 工作台/库存页开启 `enablePullDownRefresh`，`onPullDownRefresh` 里刷新后 `stopPullDownRefresh`。

### 3.6 三端配置矩阵

| 端 | API base | 前置 |
|---|---|---|
| H5 dev（3002） | `/api/v1`（Vite 代理到 8082） | 无需 CORS |
| H5 build | `/api/v1`（由部署方反代） | M6 决定 Nginx 路径 |
| 微信小程序 | `VITE_API_BASE_URL=https://<域名>/api/v1` | HTTPS + 域名白名单 + ICP 备案；开发工具可关闭"合法域名校验"用本机 HTTP |
| Android | 同上（绝对地址） | 开发期允许明文 HTTP；正式包必须 HTTPS |

### 3.7 UI 约定

- 单位用 `rpx`，设计基准 750；页面左右留 32rpx；底部留 `env(safe-area-inset-bottom)`；
- 语义色固定：实存=墨色、预占=橙色、可用=绿色；入库流水=绿色 `+`、出库=红色 `-`；
- 三态齐全：加载（骨架/文案）、空（说明为什么空 + 下一步）、错误（可读消息 + 重试）；
- **不显示英文错误码**给终端用户；错误码留在控制台便于排障；
- 不得把 `availableQty` 在前端重算成 `onHand − reserved`（后端返回什么就显示什么，
  这是 Web 库存页同一条纪律）。

- **库存**：余额/流水双标签；余额支持仓库、批次、仅可用；流水支持仓库、单据号、
  加载更多（`page/size`）并**按 id 去重**；`hasMore` 用 `页码 × size < total` 判断，
  即使去重导致条数变少也不会无限加载；筛选在请求飞行中再次修改会"补跑一次"，
  避免开关/仓库已变但列表还是旧结果；金额仅对 `unitCostAmount` 用 `fenToYuan()` 展示；
- **守卫**：`uni.addInterceptor`（navigateTo/redirectTo/switchTab）+ 每个受保护页面 `onShow`
  的 `ensureLoggedIn()` 双保险；H5 直接改 hash、小程序冷启动到 tab 页都能覆盖；
- **API 客户端**：`uni.request` 封装；写操作自动 `X-Request-Id`；401 清 token/权限/用户三项
  缓存；登录页 401 不跳转。

## 6. 已知坑（移动端特有的，提前写死）

| # | 坑 | 规避 |
|---|---|---|
| 1 | **GitHub / npmjs 不可达**：`degit` 拉预设模板必失败、`npm install` 默认源超时 | 手工脚手架 + `--registry=https://registry.npmmirror.com`；锁文件入库 |
| 2 | **vite 版本冲突**：Web 端用 vite 6，uni-app 该版本 peer 要求 5.2.8 | 独立 `package.json`，精确 `"vite": "5.2.8"`，不共享 node_modules |
| 3 | **中文路径 / 联接**：后端构建必须走 `D:\erp-build-m4`；本泳道 worktree 本身是 ASCII+空格 | miniapp 命令统一从 `D:\erp-build-m4\frontend\miniapp` 进入；不要从联接里跑 `git` 的破坏性命令 |
| 4 | **H5 有代理，小程序没有**：`/api/v1` 在小程序里是非法地址 | `VITE_API_BASE_URL` 配绝对地址；`config.ts` 在非 H5 平台对相对地址直接报可读错误 |
| 5 | **uni.request 没有拦截器** | 全部逻辑集中在 `api/client.ts`；页面不直接调 `uni.request` |
| 6 | **401 在登录页也会跳转** → 用户点登录毫无反馈（M3-S8 E2E-02 同类缺陷） | 401 分支判断当前页是否登录页；登录页只展示消息，不跳转 |
| 7 | **`reLaunch` 跳 tab 页 / `switchTab` 跳非 tab 页都会失败** | 登录成功用 `switchTab`；登出/过期用 `reLaunch` 到 login |
| 8 | **小程序 appid**：`touristappid` 只能本地预览，不能上传/真机完整能力 | README 写明替换 `manifest.json → mp-weixin.appid`；上传前完成注册与类目 |
| 9 | **小程序域名**：必须 HTTPS + 已备案域名 + 白名单；开发工具可临时关闭校验 | 本地联调用"不校验合法域名"；演示/上线走 M6 域名与证书 |
| 10 | **Android 明文 HTTP**：uni-app 默认可能禁止 cleartext | 本地调试用 HBuilderX 配置/`usesCleartextTraffic`；正式包必须 HTTPS |
| 11 | **签名证书不入库**：`.gitignore` 已排除 `*.keystore` / `*.jks` | 证书放在仓库外；README 只写路径约定，不写口令 |
| 12 | **字典截断**：`/skus`、`/products` 的 `size` 上限 200 | 与 Web 相同：超出时显示 ID，不假装完整；下一批考虑按需查询 |
| 13 | **E2E/测试数据隔离**：共享库 15432 有既有数据与 `e2e-reserve-001` | 本泳道一律用自有 PG 15434；共享库只允许唯一前缀造数并清理 |
| 14 | **不要杀 8080/3000 进程** | 联调端口固定 8082/3002；E2E 端口 8081/3001 保留 |
| 15 | **`<switch @change>` 类型冲突**（本批实测）：Vue 的 intrinsic 类型把 `switch` 当 SVG 元素，事件是 `Event` 而非 `{detail:{value}}` | 处理函数签名收 `unknown` 再收窄（见 `inventory.vue`）；`picker` 同理 |
| 16 | **按钮 hover 残留灰色**（本批实测）：uni-app 默认 `hover-class` 在桌面/模拟鼠标点击后保持灰底，截图与真机都像"禁用" | 自定义按钮统一 `hover-class="none"`；需要按压反馈时自定义 hover 类 |
| 17 | **uniStatistics 默认开启**（本批实测）：模板会注入统计代码并写 `__DC_STAT_UUID` | `manifest.json` 根加 `"uniStatistics": {"enable": false}`；构建日志出现「已开启 uni统计」即未生效 |
| 18 | **H5 构建产物无代理**：`/api/v1` 只在 dev server 有代理 | 生产由 Nginx 反代 `/api`；小程序/Android 必须绝对地址（见 §3.6） |
