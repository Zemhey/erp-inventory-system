## 4. ★ 写接口总数与审计覆盖率

```
写接口总数：42
审计覆盖：  42 / 42 = 100%
```

**口径**：从 Spring 的 `RequestMappingHandlerMapping`（运行时注册表）枚举
`com.erp.*` 下所有带 `@PostMapping` / `@PutMapping` / `@PatchMapping` / `@DeleteMapping`
的处理方法，**排除 test-profile 后门 `/__test__/*`**。

实测分布（无 PATCH/DELETE 映射，全部为 POST/PUT）：

| 模块 | 写接口数 |
|---|---|
| mdm（商品/SKU/供应商/客户/仓库） | 15 |
| pur（进货单） | 6 |
| sal（出货单） | 6 |
| rma（退货单） | 6 |
| inv（库存） | 4 |
| set（结算） | 2 |
| iam（登录） | 1 |
| nl（自然语言） | 1 |
| sys（审计/字典，全只读） | **0** |

**门禁怎么守住的**（`AuditCompletenessIT`）：

1. `TC-SYS-028`：逐接口发真实请求，断言"每个接口让 `audit_logs` 至少多一行"。**漏一个即红**。
2. `TC-SYS-029`：审计行数 ≥ 枚举出的写接口数（下界兜底）。
3. `TC-SYS-030`：枚举器自检 —— 不得含 GET、不得含 `/__test__`、必须含 8 个已知写接口。
   防止"枚举器悄悄变窄导致门禁变成纸糊"。
4. `TC-SYS-031`：`/__test__/*` 后门的写请求**不产生**审计（排除规则真的生效）。

> 这条测试的价值：将来有人加了写接口却忘了让切面覆盖，CI 会红并**点名那个接口**。
