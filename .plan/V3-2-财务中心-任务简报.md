## 0. 一句话目标

**当前系统有应收应付，但没有"财务中心"——这是最不像大型 ERP 的地方。**
所有商业 ERP 的第一大模块都是财务（金蝶财务云、SAP 的 FI/CO）。你这一批负责把**简化版复式记账**做出来：
科目表、凭证（借贷平衡）、进货出货自动生成凭证、银行账户与日记账、费用报销、发票台账、资产负债表 + 利润表。

**做完之后**：用户能说"我的系统有总账，业务单据能自动生成会计凭证" —— 这是答辩时最硬的一句话。

## 2. 范围口径（先看清楚，别做成财务软件）

**做**：借贷平衡的凭证、科目余额、业务单据自动生成凭证、费用报销、发票登记、两张财务报表。

**不做**（用户已明确划掉，别自己加）：
- ❌ 凭证模板引擎 / 自定义分录规则
- ❌ 多币种、汇率
- ❌ 合并报表、合并抵消
- ❌ 税务申报、增值税专用发票开具
- ❌ 固定资产折旧（属 P2，本批不做）
- ❌ 预算控制
- ❌ 与外部财务软件对接

**口径一句话**：够"看起来专业"，不做成能过审计的真财务系统。

## 3. 数据模型（V20 一个迁移文件）

```sql
-- 会计科目（树形，三级够用）
fin_account(
  id, tenant_id, code, name, parent_id,
  category,        -- ASSET/LIABILITY/EQUITY/COST/REVENUE/EXPENSE
  direction,       -- DEBIT 借 / CREDIT 贷
  is_leaf, init_balance numeric(18,2) default 0,
  enabled, remark, created_at, updated_at
)
-- 唯一约束 (tenant_id, code)

-- 凭证头
fin_voucher(
  id, tenant_id, voucher_no, voucher_date, period,   -- period 形如 2026-10
  source_type,     -- MANUAL/PUR_IN/SAL_OUT/PUR_PAY/SAL_RCV/EXPENSE/INVOICE
  source_id, source_no,
  status,          -- DRAFT/AUDITED/POSTED
  total_debit numeric(18,2), total_credit numeric(18,2),
  created_by, audited_by, posted_at, remark, ...
)
-- 唯一约束 (tenant_id, voucher_no)；索引 (tenant_id, period)

-- 分录
fin_voucher_line(
  id, tenant_id, voucher_id, line_no,
  account_id, account_code,          -- account_code 冗余，方便报表与审计
  summary, debit numeric(18,2), credit numeric(18,2), ...
)

-- 银行账户 + 现金日记账
fin_bank_account(id, tenant_id, code, name, bank_name, account_no, currency, balance numeric(18,2), enabled, ...)
fin_cash_journal(id, tenant_id, account_id, biz_date, direction, amount, balance, source_type, source_id, summary, ...)

-- 费用报销
fin_expense(id, tenant_id, expense_no, applicant_id, department_id, expense_type,
            amount, status, /* DRAFT/SUBMITTED/APPROVED/PAID/REJECTED */ apply_date, remark, ...)
fin_expense_line(id, tenant_id, expense_id, line_no, expense_item, amount, invoice_no, remark, ...)

-- 发票台账
fin_invoice(id, tenant_id, invoice_no, invoice_type, /* OUTPUT 销项 / INPUT 进项 */
            direction, partner_id, partner_name, amount, tax_amount, total_amount,
            invoice_date, source_type, source_id, status, remark, ...)
```

**硬约束**：每张表都必须有 `tenant_id`，并加进 `shared/tenant/TenantTables.java` 的 `ALL` 集合。

## 4. 任务清单

### FR-V3-06 会计科目表

- 端点：`GET/POST/PUT/DELETE /api/v1/fin/accounts`、`GET /api/v1/fin/accounts/tree`
- 页面 `src/views/fin/AccountView.vue`：左侧科目树（按 category 分 6 大类）+ 右侧编辑表单
- 初始化数据（写进 V20 迁移的 `INSERT`）：至少 25 个标准科目，例如
  ```
  1001 库存现金(资产/借)  1002 银行存款(资产/借)
  1122 应收账款(资产/借)  1123 预付账款(资产/借)
  1405 库存商品(资产/借)  1401 原材料(资产/借)
  2202 应付账款(负债/贷)  2203 预收账款(负债/贷)
  2221 应交税费(负债/贷)
  4001 实收资本(权益/贷)  4104 利润分配(权益/贷)
  6001 主营业务收入(收入/贷)  6051 其他业务收入(收入/贷)
  6401 主营业务成本(成本/借)  6402 其他业务成本(成本/借)
  6601 销售费用(费用/借)  6602 管理费用(费用/借)  6603 财务费用(费用/借)
  ```
- **验收**：树能展开；新增科目后能出现在树里；被凭证引用的科目不许删（返回 409）

### FR-V3-07 凭证管理

- 端点：`GET/POST/PUT /api/v1/fin/vouchers`、`POST /api/v1/fin/vouchers/{id}/audit`、`POST .../post`
- 页面 `src/views/fin/VoucherView.vue`：
  - 列表：凭证号/日期/摘要/来源/金额/状态
  - 录入抽屉：表格式分录（摘要、科目选择、借方、贷方），**实时显示借贷合计与差额**
  - 保存校验：**借贷必须相等**，不等直接 400 并返回差额
- 状态机：`DRAFT → AUDITED → POSTED`，POSTED 后不可改（只能红冲）
- **验收**：录入 2 借 2 贷平衡凭证能保存；不平衡被拒绝且提示差额；审核后过账。

### FR-V3-08 业务单据自动生成凭证（**这条最有价值**）

在现有业务服务的"完成"节点后触发，生成 `source_type=业务类型` 的凭证。规则：

| 业务动作 | 借方 | 贷方 |
|---|---|---|
| 采购入库确认 | 1405 库存商品（不含税金额） | 2202 应付账款（含税总额） |
| | 2221 应交税费-进项（税额） | |
| 销售出库确认 | 1122 应收账款（含税） | 6001 主营业务收入（不含税） |
| | | 2221 应交税费-销项（税额） |
| 销售出库（同时） | 6401 主营业务成本 | 1405 库存商品 |
| 收款核销 | 1002 银行存款 | 1122 应收账款 |
| 付款核销 | 2202 应付账款 | 1002 银行存款 |

**实现方式**：新建 `FinVoucherService.generateForSource(sourceType, sourceId)`，在业务服务里**通过事件或直接调用**触发。
**幂等**：同一 `(source_type, source_id)` 只生成一次，重复调用返回已有凭证。
**免税/税额为 0 时**：不生成税费行，不要写 0 金额分录。

- **验收**：做一笔进货入库 → 财务凭证列表出现一张凭证，借贷平衡；重复确认不会生成第二张。

### FR-V3-09 银行账户 + 现金日记账

- 端点：`/api/v1/fin/bank-accounts`（CRUD）、`/api/v1/fin/cash-journal?accountId=&from=&to=`
- 页面 `src/views/fin/BankAccountView.vue`：账户列表 + 选中后右侧日记账（日期、摘要、借方、贷方、余额）
- 余额计算：`当日余额 = 上日余额 + 借方 - 贷方`（银行是资产，借增贷减）
- **验收**：建 2 个账户；收付款后余额跟着变；日记账余额连续。

### FR-V3-10 费用报销

- 端点：`/api/v1/fin/expenses`（CRUD + `submit` / `approve` / `reject` / `pay`）
- 页面 `src/views/fin/ExpenseView.vue`：报销单列表 + 明细行 + 审批按钮
- 状态机：`DRAFT → SUBMITTED → APPROVED → PAID`，驳回回 `DRAFT` 并留原因
- 付款时：生成凭证（借 6602 管理费用 / 贷 1002 银行存款），并写一条现金日记账
- **审批若要接 APS**：可选，做不了就自己实现简单两级（部门主管 → 财务），**不要因此卡住**
- **验收**：提交→审批→付款全流程通；付款后凭证和日记账都有记录。

### FR-V3-11 发票管理

- 端点：`/api/v1/fin/invoices`（CRUD + 状态变更）
- 页面 `src/views/fin/InvoiceView.vue`：销项/进项两个 Tab
- 关联：可挂到进货单/出货单（`source_type` / `source_id`）
- 校验：同一单据的可开票金额不得超过单据金额（超额 409）
- **验收**：登记一张销项发票能关联到出货单；超额开票被拒。

### FR-V3-12 财务报表（资产负债表 + 利润表）

- 端点：`GET /api/v1/fin/reports/balance-sheet?period=2026-10`、`GET .../income-statement?period=2026-10`
- 口径：
  - 科目余额 = `init_balance + Σ(借方) - Σ(贷方)`（按 direction 决定正负）
  - 资产负债表：资产合计 = 负债合计 + 权益合计（**必须配平，不平要报差异**）
  - 利润表：营业收入 − 营业成本 − 费用 = 利润
- 页面 `src/views/fin/FinancialReportView.vue`：两张表切换 + 期间选择 + 打印按钮
- **验收**：造 5 笔业务后，资产负债表配平（差额 0），利润表数字与毛利分析对得上。

### FR-V3-13 财务中心首页

- 端点：`GET /api/v1/fin/overview`
- 页面 `src/views/fin/FinanceHomeView.vue`：
  - 4 个卡片：资金余额（所有银行账户合计）/ 应收总额 / 应付总额 / 本月收支
  - 1 张现金流图（近 6 个月收入 vs 支出）
  - 快捷入口：录凭证 / 报销 / 开发票 / 看报表
- **验收**：数字与各明细页一致。

## 5. 技术约束

- **包结构**：新模块 `com.erp.fin/{api,application,repository,domain}`，与现有 12 个模块同级。
  ⚠️ 项目有架构测试（`ArchitectureTest`），新模块的依赖方向要遵守现有约定（不要反向依赖 api 层）。
- **迁移**：`V20__v3_finance.sql`，**一个文件**，含建表 + 科目初始化数据。已应用的迁移不改内容。
- **契约**：新端点写进 `packages/api-contract/openapi.yaml`，**只追加自己 tag（`fin`）下的节点，不重排、不改别人的**。
- **错误码**：追加到 `ErrorCode.java` 末尾（如 `FIN_VOUCHER_UNBALANCED(400)`、`FIN_ACCOUNT_IN_USE(409)`、`FIN_PERIOD_CLOSED(409)`），注意最后一条带分号。
- **金额**：`numeric(18,2)`，Java 用 `BigDecimal`，**禁用 double**。舍入用 `HALF_UP`。
- **幂等**：自动生成凭证必须幂等（`(source_type, source_id)` 唯一）。
