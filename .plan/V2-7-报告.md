## 2. 这轮实际修掉的根因（按影响面排序）

> 上一轮 23:22 的 433 PASSED / 131 FAILED **不是"DB_URL 连错 15432"**：集成测试走
> Testcontainers（`PostgresTestBase` 覆写 `spring.datasource.url`），`DB_URL` 对它们无效。
> 本轮逐条从 JUnit XML 的错误 SQL 反推，根因全部在代码/迁移改写层：

### 2.1 `TenantSql` 对 `UNION [ALL]` 的作用域错误（5 条审批用例）

`data_scopes` 的 UNION ALL 查询把第二分支的 `ds` / `ur` 谓词拼进了第一分支的 WHERE，
PostgreSQL 报 `missing FROM-clause entry`。修复：顶层集合运算符先切段，再逐段改写
（`TenantSql.rewriteScope` 的 ⓪ 分支），并新增 `TC-TNT-030`。

### 2.2 `INSERT … SELECT` 两个缺陷（角色分配 / 角色种子）

① 字面量被拼到整条 SELECT 末尾，落在 WHERE 之后（`... = 7, 7`，语法错误）；
② SELECT 片段与 `ON CONFLICT` 之间丢空格（`1ON CONFLICT`）。
修复：字面量插到 SELECT **列表**末尾（顶层 FROM 之前）、尾段显式补空格；
新增 `TC-TNT-019/052`。

### 2.3 `LEFT JOIN` 谓词写进 WHERE（成本模块整片归零）

`CostSourceRepository` 的两处 LEFT JOIN 被追加右表谓词后，NULL 行被 WHERE 过滤，
外连接退化成内连接 —— 成本引擎读到 0 条流水，CostEngine/CostMonthly/Margin/CostApi
合计 30+ 条用例失败。修复：LEFT JOIN 右表谓词注入 **ON**，左表仍在 WHERE；
新增 `TC-TNT-005/049`。类注释里"本项目 0 处 LEFT JOIN"的错误说法已更正。

### 2.4 `ON CONFLICT` 白名单与"显式 tenant_id 提前返回"（发货计划 / 角色 / 单号）

- V16 把 `so_shipment_plans.uq_shipment_plan_request` 改成 `(tenant_id, request_id)`，
  但改写白名单漏了该表 → 发货计划创建报"no unique or exclusion constraint"。
- 造数/种子 SQL 已显式带 `tenant_id` 时，`rewriteInsert` 提前返回，**没有**修
  `ON CONFLICT (code)` 目标（`app_roles` 的复合唯一匹配不上）。
修复：白名单补 `so_shipment_plans` / `app_roles`，引入"列清单已含 tenant_id 仍修
ON CONFLICT 目标"的分支；`skus` 刻意移出白名单（其现有目标 `product_id,color,size`
仍依赖全局唯一索引，按表一刀切会改坏）。新增 `TC-TNT-050/051`。

### 2.5 仓储注入了具体类 + `@Primary` 双主（18 条报表/指标用例上下文失败）

- 20 个仓储把构造参数写成 `TenantAwareJdbcTemplate`，而容器 Bean 的声明返回类型是
  `JdbcTemplate` → `NoSuchBeanDefinitionException`。
- `TenantJdbcConfig` 的 `@Primary` 与 `ReportIT.CountingConfig` 的 `@Primary`
  撞成"两个 primary" → Web 上下文起不来。
修复：仓储统一按接口 `JdbcTemplate` 注入；Bean 返回类型改为 `TenantAwareJdbcTemplate`
并**去掉** `@Primary`（Boot 的 `JdbcTemplateAutoConfiguration` 带
`@ConditionalOnMissingBean`，正常上下文仍只有本 Bean）；`TenantJdbc` 的参数类型同步
改为 `JdbcTemplate`。`ReportIT` 的计数模板改为继承 `TenantAwareJdbcTemplate`，
保证"计数"与"租户过滤"同时生效。

### 2.6 匿名请求的审计写入丢失（登录失败 / actuator）

审计由 HTTP 切面在 Controller 外写；登录/actuator 请求没有 token，过滤器不会绑定租户，
`AuditLogRepository.insert` 被 TenantSql 拒绝，`AuditRecorder` 捕获后静默丢审计
——表现为 `erp_audit_written_total` 不涨、审计 gauge 为 0。
修复：`AuditRecorder` 在**无绑定**时显式以默认租户写入（有绑定则按真实租户）；
`AuditMetricsBinder` 的 gauge 用 `TenantContext.callAsSystem` 统计**全局**审计行数。
业务写入仍按真实租户落库（§5 的审计归属用例钉住）。

### 2.7 并发测试的工作线程没有租户上下文（8 个既有并发用例）

`ThreadLocal` 不跨线程；这些用例在 `@BeforeEach` 绑定默认租户后新建线程池，
worker 线程拿不到绑定 → `SYS_TENANT_CONTEXT_MISSING`。
修复：只在**测试侧**对提交给线程池的服务调用包 `TenantContext.runIn/callIn(DEFAULT, …)`
（CostEngine、InventoryReserve、CreditControl、Settlement、DocumentNumberGenerator、
MasterData、PurchaseOrderReversal、SalesOrderReversal），不改断言、不删用例。
`ReportQueryPlanIT` 的 `@BeforeAll` 造数同理显式绑定租户。

### 2.8 日志断言与 MDC

`TenantAwareJdbcTemplate` 继承 `JdbcTemplate` 后，Spring 的 SQL DEBUG 日志落到
`com.erp.*` 下被测试捕获；`TraceLogCapture` 返回的 message 不含 pattern 里的 traceId。
修复：`TraceLogCapture` 在行首还原 `[traceId]`（与真实日志一致），断言语义不变。

## 4. 跨租户矩阵口径

- **资源（9）**：商品 / SKU / 库存 / 进货单 / 出货单 / 退货单 / 结算 / 报表 / 审计。
- **读法（5）**：按 id 直查 / 列表 / 导出（`export=csv`）/ 关联查询 / 聚合。
- **身份（3）**：租户 2 管理员（拿租户 1 的 id）/ 租户 1 管理员（同租户正对照）/ 匿名。
- **404 口径**：按 id 直查的单条资源（商品、SKU、三张单据、审计详情）一律 404，
  响应体不含 `IAM_FORBIDDEN`；列表/聚合类返回 200 + 空/仅本租户行。
- **真实 id**：两个租户各造一套**编码/单号相同**的数据（`TNT-WH`、`PO-TNT-0001`），
  id 不同 —— 用不存在的 id 测 404 只能证明"接口会 404"，与隔离无关。
- **正对照**：每一格都由租户 1 管理员用同一接口/同一批 id 再打一次，必须 200 且响应里
  真有该行；另有 `TC-API-132` 证明租户 2 看自己的数据也 200 有内容。

> 注入点都在 `TenantSql`（租户过滤的唯一出口）；每次跑完立即 `git checkout` 不行（禁令），

### 漂移 ① 去掉 SELECT/UPDATE/DELETE 的租户谓词

- 注入：`rewriteScope` 跳过 WHERE 谓词拼装。

- 恢复：重新加回谓词，矩阵 + 守恒用例全绿。

### 漂移 ② 去掉 INSERT 的 `tenant_id` 列与值

- 注入：`rewriteInsert` 不追加 `tenant_id` 列/值（依赖 DB 默认值 1）。

## 9. 偏离计划书的地方（逐条理由）

1. **矩阵身份命名**：计划书写"3 身份"，本实现取"租户 2 管理员 / 租户 1 管理员 / 匿名"。
   与 V2-6 的"他仓仓管 / 本仓只读 / 匿名"同构；两个管理员都授 ADMIN（功能权限满），
   矩阵只考租户维，不把 RBAC 的 403 混进来。
2. **`INSERT … SELECT` 不靠触发器填租户**：V16 的 `erp_tenant_fill()` 依赖会话变量
   `erp.tenant_id`，而应用从未设置该变量（TenantContext 只活在 JVM 里）。若只靠触发器，
   `tenant_id` 取到 NULL → NOT NULL 报错。因此显式补列/补值，触发器仅作为裸 SQL 的兜底。
3. **`audit_logs` 列定义未动**：V13 已是 `NOT NULL DEFAULT 1`，且有 append-only 触发器；
   V16 按计划书只追加索引。应用路径显式补 `tenant_id`；匿名登录审计显式归默认租户
   （见 §2.6，属已知限制）。
4. **`skus` 不在 `ON CONFLICT` 白名单**：V16 只把 `create_request_id` 改成复合唯一，
   现有 `ON CONFLICT (product_id,color,size)` 仍依赖全局唯一；按表一刀切会改坏造数。
5. **废弃 `TenantDataSource` 第二层**：Spring Bean 自引用会在启动期
   `BeanCurrentlyInCreationException`（WIP 已实测 53 个测试类全红）；改为"19 处
   PreparedStatementCreator 提取 SQL 文本"（`TenantJdbc`），从"运行时拦截"变成"可断言"。
6. **演示租户登录用户未写入迁移**：迁移已由指挥侧在存量库跑过，追加账号会改 V16 校验和；
   `tnt_admin_1` / `tnt_admin_2` 由测试集中创建（`TestDataFactory.inTenant`），
   演示账号留待 B1/B4 用新的 V17/或种子脚本补（见 §10 风险）。
7. **6 个并发用例与 2 个测试基础设施文件有改动**：仅"把提交给线程池的服务调用包进
   `TenantContext`"，断言与业务语义未改；`TraceLogCapture` 只补 traceId 前缀；
   `ReportIT` 的计数模板改为租户感知（否则计数与隔离二选一）。
