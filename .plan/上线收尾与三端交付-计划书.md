## 2. 硬约束与红线

1. **不改 `zemworld.conf`、不动 `/var/www/portfolio`**；新站点一律新增独立 `conf.d/*.conf`。
2. **不把 8080 / 15435 / 18080 暴露公网**；新站点全部走宿主 nginx 反代到 `127.0.0.1:18080`。
3. **不在服务器上编译**（2C2G）；镜像在本机做，`docker save → upload → docker load`。
4. **compose 的 `IMAGE_TAG` 是 backend 与 web 共用的** —— 只重建其中一个时，必须给另一个也打同 tag，否则 `up` 会**静默中止**而 `/readyz` 仍然 UP（已踩过）。
5. **密码/口令/密钥不进仓库、不进文档、不进对话**；需要用户输入时让他从私有文件复制。
6. **每完成一个阶段就跑对应门禁**，最后统一提交；提交按功能分组，不写"update"式提交信息。
7. 新子域名解析**由用户加**（控制台动作一次只给一个、给精确入口）；未解析前不要开始签证书。

  ```powershell

  $env:VITE_API_BASE_URL = "/api/v1"
  npm run build:h5
  Remove-Item Env:\VITE_API_BASE_URL
  ```
  验收：`dist/build/h5/index.html` 存在；产物里**不应**出现 `https://xuliu.zemworld.cn`（否则就是没覆盖成功，跨域会全挂）：
  ```bash

  ```
- [ ] **A-4 打包上传**
  ```bash

  (cd dist/build/h5 && tar czf /d/MajorCacheFolder/erp-h5.tar.gz .)
  MSYS_NO_PATHCONV=1 "D:/Major_Software/workbench/workbench.exe" upload \
    /d/MajorCacheFolder/erp-h5.tar.gz /tmp/ \
    -i i-7xv6l0ysutak53sfdjxr -r cn-guangzhou -f
  ```

- [ ] **A-5 服务器落位 + HTTP 站点**
  ```bash
  # workbench exec
  mkdir -p /var/www/erp-h5 && tar xzf /tmp/erp-h5.tar.gz -C /var/www/erp-h5 && rm -f /tmp/erp-h5.tar.gz
  chown -R root:root /var/www/erp-h5 && find /var/www/erp-h5 -type d -exec chmod 755 {} + && find /var/www/erp-h5 -type f -exec chmod 644 {} +
  ```
  新建 `/etc/nginx/conf.d/zz-erp-h5.conf`：`listen 80; server_name m.zemworld.cn;`
  - `location ^~ /.well-known/acme-challenge/ { root /var/www/letsencrypt; }`（签证书用）
  - `root /var/www/erp-h5; index index.html;`
  - `location /api/ { proxy_pass http://127.0.0.1:18080; }`（带 `Host`/`X-Real-IP`/`X-Forwarded-For`/`X-Forwarded-Proto`）
  - `location = /readyz { proxy_pass http://127.0.0.1:18080/readyz; }`
  - `location ~ ^/(actuator|swagger-ui|v3/api-docs) { return 404; }`
  - `add_header X-Robots-Tag "noindex, nofollow" always;`
  - `nginx -t && systemctl reload nginx`
  ⚠️ 文件名用 `zz-` 前缀，保证在 `zemworld.conf` 之后加载，**不抢默认站点**（否则 IP 访问会被接管）。
- [ ] **A-6 签证书**（与 xuliu 同法）
  ```bash
  /root/.acme.sh/acme.sh --issue -d m.zemworld.cn -w /var/www/letsencrypt --keylength 2048 --server letsencrypt
  /root/.acme.sh/acme.sh --install-cert -d m.zemworld.cn \
    --key-file /etc/nginx/cert/m.zemworld.cn.key \
    --fullchain-file /etc/nginx/cert/m.zemworld.cn.pem --reloadcmd "systemctl reload nginx"
  ```
  然后把 80 的 `location /` 改成 `return 301 https://$host$request_uri;`，加 443 server 块（`listen 443 ssl; http2 on;`）。
  LE 偶发 POST 超时 → 重试；连续 3 次失败再考虑 ZeroSSL（需向用户要邮箱）。
- [ ] **A-7 验收**（全部用 `--resolve` 防本机 DNS 抖动）
  ```bash
  curl -s -o /dev/null -w '%{http_code}\n' https://m.zemworld.cn/
  ```

## 4. 环境与坑（新会话必读，都是实测来的）

1. **Git Bash 路径改写**：给 workbench 传远程命令时，命令串以 `/` 开头会被改写成本地路径 → 一律 `MSYS_NO_PATHCONV=1`。
2. **workbench exec 单次 180 秒超时**：长任务（签证书、`docker load`）用 `nohup ... &` 落日志再轮询；`| tail` 会把失败掩盖成 exit 0，务必 `; echo "exit=$?"`。
3. **compose 共用 `IMAGE_TAG`**：换任一镜像必须给另一个也打同 tag（见 §2 第 4 条）。
4. **vite build 会清空 `dist/`**：任何放在 `dist/` 里的构建辅助文件（如覆盖层 Dockerfile）都会被删 —— 放仓库外。
5. **Docker Hub 不可达**：镜像用"基于上一版本换产物"的覆盖层做（`erp-web-overlay.Dockerfile`、`backend-overlay/`）；网络恢复后要回头走完整多阶段重建。
6. **本机 curl 走 Schannel 会做证书吊销检查**，国内网络下访问 LE 证书站点可能失败（`code=000`），而 Node TLS 正常 —— 验证脚本优先用 Node，别误判成站点挂了。
7. **WXSS 不支持 `:root`**，且选择器列表里有一个无效就会**丢弃整条规则** → 小程序端样式变量必须单独写 `page`（本轮已修，别再合回去）。
8. **electron-builder 收尾 EBUSY**：目标 exe 被正在运行的实例占用会失败；改版本号或先关闭程序。
9. **登录失败会锁号**（5 次 / 15 分钟）：做接口探测时用不存在的用户名，别拿 `admin`/`demo` 试错；必要时用 SQL 复位 `failed_attempts`。
10. **H5 构建必须覆盖 `VITE_API_BASE_URL` 为相对地址**（A-3），否则从 `m.zemworld.cn` 调 `xuliu` 会被 CORS 拦死。
