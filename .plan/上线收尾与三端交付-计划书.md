1. **不改 `zemworld.conf`、不动 `/var/www/portfolio`**；新站点一律新增独立 `conf.d/*.conf`。
2. **不把 8080 / 15435 / 18080 暴露公网**；新站点全部走宿主 nginx 反代到 `127.0.0.1:18080`。
3. **不在服务器上编译**（2C2G）；镜像在本机做，`docker save → upload → docker load`。
4. **compose 的 `IMAGE_TAG` 是 backend 与 web 共用的** —— 只重建其中一个时，必须给另一个也打同 tag，否则 `up` 会**静默中止**而 `/readyz` 仍然 UP（已踩过）。

6. **每完成一个阶段就跑对应门禁**，最后统一提交；提交按功能分组，不写"update"式提交信息。
7. 新子域名解析**由用户加**（控制台动作一次只给一个、给精确入口）；未解析前不要开始签证书。

## 4. 环境与坑（新会话必读，都是实测来的）

1. **Git Bash 路径改写**：给 workbench 传远程命令时，命令串以 `/` 开头会被改写成本地路径 → 一律 `MSYS_NO_PATHCONV=1`。
2. **workbench exec 单次 180 秒超时**：长任务（签证书、`docker load`）用 `nohup ... &` 落日志再轮询；`| tail` 会把失败掩盖成 exit 0，务必 `; echo "exit=$?"`。
3. **compose 共用 `IMAGE_TAG`**：换任一镜像必须给另一个也打同 tag（见 §2 第 4 条）。
4. **vite build 会清空 `dist/`**：任何放在 `dist/` 里的构建辅助文件（如覆盖层 Dockerfile）都会被删 —— 放仓库外。
5. **Docker Hub 不可达**：镜像用"基于上一版本换产物"的覆盖层做（`erp-web-overlay.Dockerfile`、`backend-overlay/`）；网络恢复后要回头走完整多阶段重建。
6. **本机 curl 走 Schannel 会做证书吊销检查**，国内网络下访问 LE 证书站点可能失败（`code=000`），而 Node TLS 正常 —— 验证脚本优先用 Node，别误判成站点挂了。
7. **WXSS 不支持 `:root`**，且选择器列表里有一个无效就会**丢弃整条规则** → 小程序端样式变量必须单独写 `page`（本轮已修，别再合回去）。
8. **electron-builder 收尾 EBUSY**：目标 exe 被正在运行的实例占用会失败；改版本号或先关闭程序。
9. **登录失败会锁号**（5 次 / 15 分钟）：做接口探测时用不存在的用户名，别拿 `admin`/`demo` 试错；必要时用 SQL 复位 `failed_attempts`。
10. **H5 构建必须覆盖 `VITE_API_BASE_URL` 为相对地址**（A-3），否则从 `m.zemworld.cn` 调 `xuliu` 会被 CORS 拦死。
11. **视觉交付不能用 `innerText` 验收**：底栏/悬浮层这类元素"在 DOM 里"和"看得见"是两件事 —— 被 z-index 盖住、被裁掉、被顶出视口，文本照样取得到（§8.5 就是这么被我误判过一次）。要 `document.elementFromPoint()` 命中测试 + 截图真的看一眼。
12. **`uni.hideTabBar()` 只在小程序/App 端生效，H5 端不生效**：H5 要藏 uni-app 自画的那条 `uni-tabbar` DOM，只能靠 CSS（且 `pages.json` 的 `tabBar` 声明不能删，`switchTab` 与 `--window-bottom` 依赖它）。
13. **`node … && gradlew …` 里前一步崩了，日志文件还是上一次的 `BUILD SUCCESSFUL`**：出包链每步都要看退出码，别只看日志尾部（§8.5 里差点发出旧包）。

### 8.5 「底栏没有我的」· H5 端原生标签栏盖住自绘底栏（2026-10-29 深夜，用户报）

用户："浏览器打开的和 app 都没有「我的」，我记得之前改过是有的。" **他记得没错，两端也都没错。**

- 实测链：先在 `m` 站上取 `innerText` → 里面**有**「我的」，一度判成"你看的是缓存"；
  截图一看，底栏只有 5 项。再用 `document.elementFromPoint()` 打命中测试，才拿到真相：
  压在上面的元素链是 `div.uni-tabbar__label < … < uni-tabbar`，也就是 **uni-app 为 H5 自己画的那条原生 DOM**
  （z-index 998），自绘的 `app-tab-bar`（含「我的」，z-index 900）被整条盖在下面。
- 根因：组件靠 `uni.hideTabBar()` 藏原生栏，**这个 API 在小程序/App 端有效，H5 端不生效** ——
  所以小程序里「我的」是好的，浏览器和安卓 App（都是 H5 渲染）一起看不见。
  而 `pages.json` 的 `tabBar` 声明必须留着（`switchTab` 保活与 `--window-bottom` 让位都依赖它），
  微信原生栏又最多 5 项放不下第 6 个，所以只能自绘 + 在 H5 用 CSS 收掉那条 DOM。
- 修法：`App.vue` 里加 `#ifdef H5` 的 `uni-tabbar{display:none!important}`，
  并删掉原来那段"给 H5 原生栏配深色"的样式 —— 栏都不显示了，那段成了死代码。
  小程序端不命中该选择器（那边没有这些节点），已实测重建后的 `dist/build/mp-weixin` 里**不含**这条规则。
- 复验（真站 + isMobile 模拟 + 命中测试 + 截图）：6 项全在 `工作台 库存 出货 进货 商品 我的`，
  点「我的」进 `#/pages/me/me`，账号/偏好/改密/退出都在。
- ★ **坑（下次别再踩）**：底栏、悬浮按钮这类"看得见的东西"不能用 `innerText` 判定交付 ——
  元素在 DOM 里但被盖住、被裁掉、被顶出视口，文本照样能取到。要 `elementFromPoint()` 命中测试 + 截图真的看一眼。
- ★ 顺带修了出包链上的一个隐患：`sync-h5.mjs` 原本"先 `rmSync` 整个 `assets/www` 再复制"，
  Windows 上目录句柄会被索引器/杀软顶住（实测 EPERM），**目录删不掉但子文件已经删了一半**，
  而 `&&` 一断，后面 `gradlew` 根本没跑，日志里留的是上一次的 `BUILD SUCCESSFUL` —— 差点把旧包当新包发出去。
  改成"先复制、再按差集清残留"（本次清掉 32 个旧 hash 文件），并显式比对 `assets` 与 `dist` 的内容哈希。
  新成品：`app/yunshang-erp-0.3.0.apk`，sha256 `b6a14c7758669463…`（**之前那份要重装**）。
